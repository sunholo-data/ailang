# AILANG Dev Tools Reference v0.8.0

> This document teaches AI agents how to use the AILANG **toolchain** (not language syntax).
> For syntax: `ailang prompt` | For tools: `ailang devtools-prompt`

## 1. Running & Testing Programs

```bash
# Run a module (flags BEFORE filename)
ailang run --caps IO,FS --entry main module.ail

# Run with AI effect (multi-provider)
ailang run --caps IO,AI --ai gemini-2-5-flash module.ail

# Type-check without running
ailang check module.ail
ailang check --timeout 30s module.ail          # Timeout + stack dump on hang
ailang check --debug-compile module.ail        # Phase timing breakdown
ailang check src/                              # Recursive directory check

# Run tests
ailang test tests/
ailang test --format json tests/               # JSON output

# Interactive REPL
ailang repl

# Watch for changes (auto-reload)
ailang watch module.ail

# Module interface (normalized JSON)
ailang iface <module>
```

**Capabilities** (comma-separated with `--caps`):
| Cap | Grants | Example |
|-----|--------|---------|
| `IO` | print, readLine | Console I/O |
| `FS` | readFile, writeFile | File system |
| `Net` | httpGet, httpRequest | Network |
| `AI` | call, callJson | AI providers |
| `Env` | getEnv | Environment vars |
| `Clock` | now | Time access |
| `Process` | exec | External commands |

**All `run` flags** (must come BEFORE filename):
| Flag | Purpose |
|------|---------|
| `--caps <list>` | Enable capabilities (IO,FS,Net,AI,Env,Clock,Process) |
| `--entry <name>` | Entrypoint function (default: main) |
| `--args-json <json>` | JSON arguments to entrypoint (use `-` to read from stdin) |
| `--args-file <path>` | Read JSON arguments from a file (Windows/PowerShell-friendly) |
| `--ai <model>` | AI model (e.g., gemini-2-5-flash, claude-haiku-4-5) |
| `--ai-stub` | AI effect with stub handler (for testing) |
| `--emit-trace <fmt>` | Export trace (jsonl, otel, jsonl,otel, auto) |
| `--verify-contracts` | Enable runtime contract validation |
| `--no-budgets` | Bypass effect budget enforcement |
| `--budget-report <mode>` | Print budget usage after execution (flat, json) |
| `--debug-types` | Show type inference debug output |
| `--node <id>` | Filter --debug-types to specific node ID |
| `--debug-compile` | Show compilation phase statistics |
| `--relax-modules` | Allow module path mismatch (prototyping) |
| `--seed <n>` | Random seed for deterministic execution |
| `--virtual-time` | Use virtual time for deterministic execution |
| `--json` | Output errors in structured JSON |
| `--compact` | Compact JSON output |
| `--quiet` | Suppress progress messages |
| `--no-print` | Suppress output (exit code only) |
| `--allow-env <list>` | Allowed environment variables (comma-separated) |
| `--env <list>` | Override env vars (KEY=value,FOO=bar) |
| `--env-snapshot <file>` | Load environment snapshot from JSON |
| `--write-env-snapshot <file>` | Write environment snapshot and exit |
| `--stdlib-path <path>` | Override stdlib directory |
| `--max-recursion-depth <n>` | Max recursion depth (default: 10000) |
| `--process-timeout <dur>` | Process exec timeout (default: 30s) |
| `--process-allowlist <list>` | Allowed commands (comma-separated, path-pinned) |
| `--process-max-output <n>` | Max stdout+stderr bytes (default: 10MB) |

## 2. Debugging with Traces

```bash
# Export execution trace as JSONL (stdout)
ailang run --emit-trace jsonl --caps IO --entry main module.ail > trace.jsonl

# Export to Cloud Trace / OTEL collector
ailang run --emit-trace otel --caps IO --entry main module.ail

# Auto-emit when telemetry configured (zero extra flags)
# Set GOOGLE_CLOUD_PROJECT or OTEL_EXPORTER_OTLP_ENDPOINT first
ailang run --caps IO --entry main module.ail

# Both formats simultaneously
ailang run --emit-trace jsonl,otel --caps IO --entry main module.ail

# Type inference debugging (M-DX11)
ailang run --debug-types module.ail
ailang run --debug-types --node 42 module.ail   # Filter to specific node

# Contract verification
ailang run --verify-contracts --caps IO --entry main module.ail
```

**Trace event types**: `module_start`, `function_enter`, `function_exit`, `effect`, `contract_check`, `budget_delta`, `error`

**Debug environment variables**:
| Variable | Purpose |
|----------|---------|
| `DEBUG_STRICT=1` | Fail loudly on unhandled cases |
| `DEBUG_PARSER=1` | Token position tracing |
| `DEBUG_MONO_VERBOSE=1` | Monomorphization tracing |
| `DEBUG_CODEGEN=1` | Warn on record type fallback |
| `DEBUG_APPROVAL_WATCHER=1` | Verbose GitHub label detection |
| `AILANG_RELAX_MODULES=1` | Allow module path mismatch |
| `AILANG_FS_SANDBOX=<dir>` | Restrict all FS/zip operations to directory |

### FS Sandbox

Set `AILANG_FS_SANDBOX` to confine all file system operations to a directory:

```bash
AILANG_FS_SANDBOX=/tmp/work ailang run --caps IO,FS --entry main file.ail
# readFile("data.txt") → reads /tmp/work/data.txt
# writeFile("out.txt", s) → writes /tmp/work/out.txt
```

Applies to all FS builtins, all `std/zip` operations, and `std/process` working directory.

### In-Program Debugging (Debug Effect)

The `Debug` effect is a **ghost effect** — use it instead of `IO` (println) for logging in packages. Unlike IO, Debug doesn't cascade to every caller and is erased in release builds:

```bash
ailang run --debug --caps IO,Debug --entry main file.ail
```

```ailang
import std/debug (log, check)

func process(data: string) -> string ! {Net, Debug} {
  log("processing: ${data}");
  check(length(data) > 0, "data must not be empty");
  httpGet("https://example.com/${data}")
}
```

- **Use Debug, not IO** for logging in library/package code
- **Write-only**: `log`/`check` write to host context; AILANG code cannot read it
- **Release mode erases**: `--release` removes all Debug calls (zero cost)

## 2a. Static Contract Verification (Z3)

Prove contracts correct at compile time — no tests needed, no runtime overhead.

```bash
# Verify all contracts in a file (requires Z3 installed)
ailang verify file.ail

# Show generated SMT-LIB for each function
ailang verify --verbose file.ail

# Machine-readable JSON output
ailang verify --json file.ail

# Strict mode: exit 1 if any function can't be verified
ailang verify --strict file.ail

# Custom per-function timeout (default: 5s)
ailang verify --timeout 10s file.ail
```

**How it works**: Translates pure functions with `requires`/`ensures` to SMT-LIB, invokes Z3 to prove postconditions hold for ALL inputs satisfying preconditions.

**Output states**:
| Status | Meaning |
|--------|---------|
| `VERIFIED` | Z3 proved the contract holds for all valid inputs |
| `VIOLATION` | Z3 found a counterexample (concrete inputs that break ensures) |
| `SKIPPED` | Function outside decidable fragment (with reason + hint) |
| `ERROR` | Encoding or solver error |

**Decidable fragment** (what can be verified):
- int/bool/enum parameters and returns
- Arithmetic (`+`, `-`, `*`, `/`), comparison, logical operators
- `if`/`else`, `let`, `match` on enums/ADTs
- Must be pure (`! {}`), non-recursive, non-higher-order

**Example with counterexample**:
```bash
$ ailang verify examples/runnable/contracts/finance.ail
→ Verifying contracts in finance.ail
  Solver: Z3 version 4.15.4

  ✓ VERIFIED calculateTax    6ms
  ✓ VERIFIED netIncome        6ms
  ✗ VIOLATION brokenDiscount
    Counterexample:
      price: Int = 0
      discount: Int = 1

  3 functions: 2 verified, 1 violations
```

**Install Z3**: `brew install z3` (macOS) or `apt install z3` (Linux), or set `AILANG_Z3_PATH`.

### IFC labels (v0.16.0+)

`ailang verify` also reports sink-refinement violations against the IFC label system:

- `T<label>` annotates a value as carrying a source-level taint (e.g. `string<email>`)
- `T{not LABEL}` annotates a parameter position as a sink that refuses values labelled with LABEL
- Functions that change a value's label must declare `! {Declassify}` in their effect row

```ailang
pure func sanitize(raw: string<email>) -> string<sanitized> ! {Declassify}
ensures { result == "[sanitized]" }
{ "[sanitized]" }
```

Try the demos:
```bash
ailang verify examples/runnable/contracts/inbox_injection_v2.ail   # 5 functions: 3 verified, 2 violations
ailang verify examples/runnable/contracts/inbox_v2_app.ail          # cross-module variant
```

See the [IFC Labels guide](https://ailang.sunholo.com/docs/guides/ifc-labels) for the full grammar and worked examples. Use `ailang prompt --version v0.16.0` to get the AI-teaching prompt that covers IFC labels.

## 3. Verifying Determinism (Replay)

```bash
# Record a trace
ailang run --emit-trace jsonl --caps IO --entry main module.ail > baseline.jsonl

# Replay and compare against baseline
ailang replay baseline.jsonl

# JSON output for programmatic comparison
ailang replay --json baseline.jsonl

# Override source file during replay
ailang replay --file modified.ail baseline.jsonl
```

**Exit codes**: 0 = match, 1 = mismatch, 2 = error

**Auto-resolution**: Replay extracts module name and capabilities from the baseline trace's `module_start` event, so you typically don't need `--file` or `--caps` overrides.

## 4. Training Data Export

Score traces for quality and export as AI fine-tuning data.

```bash
# Score a trace (human-readable)
ailang export-training --score trace.jsonl

# Score as JSON (machine-readable)
ailang export-training --score --json traces/

# Export all traces as training data (JSONL)
ailang export-training traces/

# Filter by quality score (0.0-1.0)
ailang export-training --min-score 0.7 traces/

# Export to file with source code resolution
ailang export-training --output training.jsonl --source-dir src/ traces/
```

**Quality scoring** (weighted 0.0-1.0):
| Component | Weight | Logic |
|-----------|--------|-------|
| Completion | 30% | 1.0 if clean exit, 0.0 if errors |
| Complexity | 25% | Functions, depth, call count (log scale) |
| Contracts | 20% | Pass rate (0.5 neutral if none) |
| Budget efficiency | 15% | 20-80% usage optimal |
| Effect diversity | 10% | Multiple effect types = higher |

**Output format**: Each line is `{"source": "...", "trace": "...", "score": 0.85, "metadata": {...}}`

**Full trace pipeline**:
```bash
# 1. Capture trace
ailang run --emit-trace jsonl --caps IO --entry main module.ail > trace.jsonl
# 2. Verify determinism
ailang replay trace.jsonl
# 3. Score quality
ailang export-training --score trace.jsonl
# 4. Export for training
ailang export-training --min-score 0.5 traces/ > training.jsonl
```

## 4a. Improving Your Code with Traces

After writing AILANG code, use traces to **self-evaluate** and iterate.

**Workflow: Write → Trace → Score → Improve → Verify**

```bash
# 1. Write your module, then capture its trace
ailang run --emit-trace jsonl --caps IO --entry main solution.ail > trace.jsonl 2>output.txt

# 2. Score: how good is this code?
ailang export-training --score --json trace.jsonl
# Returns: {"score": 0.42, "completion": 1.0, "complexity": 0.3, "contracts": 0.0, ...}

# 3. Identify weaknesses from the score:
#    - contracts=0.0 → Add requires/ensures to critical functions
#    - complexity=0.3 → Code is too simple (flat call graph)
#    - budget_efficiency=0.0 → No budget annotations

# 4. Improve the code (add contracts, deepen call graph, add budgets)

# 5. Verify the improvement didn't break anything
ailang run --emit-trace jsonl --caps IO --entry main solution.ail > trace2.jsonl 2>/dev/null
ailang export-training --score --json trace2.jsonl
# Score should be higher now
```

**What each score component tells you**:

| Component | Low Score Means | How to Improve |
|-----------|----------------|----------------|
| Completion (30%) | Program crashed or errored | Fix runtime errors |
| Complexity (25%) | Flat call graph, few functions | Extract helper functions, use recursion |
| Contracts (20%) | No requires/ensures | Add pre/postconditions to key functions |
| Budget efficiency (15%) | No budget annotations or exhausted | Add `@limit=N` to effect types |
| Effect diversity (10%) | Only uses one effect type | Use IO+FS, or IO+Net, etc. |

**Reading trace events to debug**:

```bash
# See exactly what your code did
ailang run --emit-trace jsonl --caps IO --entry main module.ail 2>/dev/null | jq '.event'
# Shows: "module_start", "function_enter", "effect", "function_exit", "module_end"

# Check effect invocations (IO, FS, Net all traced)
ailang run --emit-trace jsonl --caps IO --entry main module.ail 2>/dev/null | jq 'select(.event == "effect")'

# Non-deterministic effects are auto-flagged (deterministic=false)
# Flagged: Net.httpGet, Net.httpPost, Net.httpRequest, Clock.now, Clock.sleep, IO.readLine
ailang run --emit-trace jsonl --caps IO,Net --entry main module.ail 2>/dev/null | \
  jq 'select(.effect.deterministic == false)'

# Check module execution duration (nanoseconds)
ailang run --emit-trace jsonl --caps IO --entry main module.ail 2>/dev/null | \
  jq 'select(.event == "module_end") | .module.duration_ns'
```

**Regression guard after refactoring**:

```bash
# Before refactoring: capture baseline
ailang run --emit-trace jsonl --caps IO --entry main module.ail > baseline.jsonl

# After refactoring: replay to verify identical behavior
ailang replay baseline.jsonl    # Exit 0 = deterministic, 1 = behavior changed
```

## 6. Delegating Tasks (Coordinator)

The coordinator daemon executes tasks autonomously using AI agents.

```bash
# Service management
ailang coordinator start                     # Start daemon
ailang coordinator stop                      # Stop daemon
ailang coordinator status                    # Check if running
ailang coordinator watcher-status            # Check GitHub label watcher

# Send tasks
ailang messages send coordinator "Fix the parser bug" --title "Bug" --from "user" --type bug
ailang messages send design-doc-creator "Design semantic caching" --title "Feature" --from "user"

# Review completed work
ailang coordinator pending                   # Interactive approval queue
ailang coordinator diff <task-id>            # View git diff
ailang coordinator logs <task-id>            # Streaming execution logs
ailang coordinator list                      # List all tasks

# Approve/reject (interactive)
# Use ailang coordinator pending with keys:
#   a = approve, r = reject (with feedback), d = diff, c = chat history

# Approve/reject (CLI)
ailang coordinator approve <task-id>
ailang coordinator reject <task-id> --feedback "Add error handling"

# Task lifecycle
ailang coordinator reopen <task-id>          # Reopen rejected task
ailang coordinator retry <task-id>           # Reset failed task to pending
ailang coordinator cleanup                   # Cancel stale tasks
ailang coordinator worktree <task-id>        # Show worktree directory
```

**Agent pipeline**: `GitHub Issue -> design-doc-creator -> [Approval] -> sprint-planner -> [Approval] -> sprint-executor -> [Approval] -> Merged`

| `--api-key-header H` | HTTP header for API key auth |
| `--api-key-env VAR` | Env var with expected API key |

**Auto-generated endpoints**:
| Endpoint | Purpose |
|----------|---------|
| `POST /api/{module}/{func}` | Call AILANG function |
| `GET /api/_meta/modules` | List modules + exports |
| `GET /api/_meta/openapi.json` | OpenAPI 3.1 spec |
| `GET /api/_meta/docs` | Swagger UI (interactive explorer) |
| `GET /api/_meta/redoc` | ReDoc (API reference) |
| `GET /api/_health` | Health check |
| `GET /.well-known/agent.json` | A2A Agent Card |
| `POST /a2a/` | A2A JSON-RPC task endpoint |
| `POST /mcp/` | MCP streamable HTTP (with `--mcp-http`) |

**Route annotations** (on exported functions):
| Annotation | Purpose |
|------------|---------|
| `@route("METHOD", "/path")` | Custom URL path and HTTP method |
| `@raw` | Receive full HttpRequest record (body, headers, method, query) |
| `@nowrap` | Return raw JSON without response envelope |
| `@noexpose` | Hide from HTTP/MCP (still importable by other modules) |
| `@mcp_name("name")` | Override the MCP tool name (must match `^[a-zA-Z0-9_-]{1,64}$`) |

**Request headers in `@route`**: Declare a `_headers: Json` parameter to receive HTTP request headers without switching to `@raw` (preserves multipart parsing).

**MCP tool quality**: Doc comments (`--` above func) become tool descriptions. `inputSchema` uses named parameters with JSON Schema types. `--routes-only` and `@noexpose` filter MCP `tools/list`. MCP tool names match `^[a-zA-Z0-9_-]{1,64}$` (Claude Desktop compatible) — auto-generated as bare function names when unique, or `<lastSegment>_<funcName>` on collision. Override with `@mcp_name("name")`.

## 13. Unified AI Execution

Programmatic AI execution for automation, CI/CD, and agent workflows.

```bash
# Execute a task with AI
ailang exec --workspace /path/to/repo "Fix the type error in parser.go"

# With specific model

# Streaming JSON output (for dashboards)
ailang exec --stream-json --task-id task-123 "Add unit tests"

# API-only mode (text generation, no file editing)
ailang exec --api-only --model gemini-2-5-flash "Explain this error"

# Dry run (validate without executing)
ailang exec --dry-run "Review this code"

# Register task in Observatory for tracking
ailang exec --register-task --parent-task-id parent-123 "Fix bug"
```

**`exec` flags**:
| Flag | Purpose |
|------|---------|
| `--workspace` | Working directory |
| `--model` | Model to use |
| `--timeout` | Execution timeout |
| `--task-id` | Task ID for tracing |
| `--parent-task-id` | Parent task for hierarchy |
| `--system-prompt` | System prompt to prepend |
| `--api-only` | Text generation only (no file editing) |
| `--register-task` | Register in Observatory |
| `--stream-json` | NDJSON streaming output |

### WASM Type-Checker Budget (v0.22.x+)

The WASM-compiled type-checker runs on the host JavaScript engine's call
stack (~10–15K frames) — much tighter than native Go's dynamically-growable
goroutine stacks. Certain code shapes that type-check in milliseconds on
the CLI can take 80+ seconds in WASM. v0.22.x added a 2-second wall-clock
budget guard that surfaces a structured `WasmTypeCheckerBudgetExceededError`
instead of letting the browser freeze.

**If you see this error**: rewrite using the five WASM-friendly patterns
below. See [docs/docs/reference/limitations.md](../../../docs/docs/reference/limitations.md)
for the diagnostic background and the postmortem of the first instance
(cognitive_commons/services/citizen.ail, May 2026).

### WASM-Friendly Patterns

Five compounding code shapes to avoid when targeting browser/WASM. The
workarounds also produce more idiomatic AILANG for CLI-only code — the
WASM cliff is the forcing function but the style improvements stand on
their own.

**Headless smoke harness** (catches violations before merge):
```bash
node demos/scripts/wasm-loadmodule-harness.js   # in sister demos repo
# exit 0 = all modules load cleanly
# exit 3 = stack overflow (likely citizen-shape)
# exit 4 = budget exceeded (clear structured error)
```

#### Pattern 1 — Triple-nested `match`

BAD (catches the cliff):
```ailang
match decode(raw) {
  Err(e) => Err(e),
  Ok(j)  => match getString(j, "error") {
    Some(err) => Err(err),
    None      => match getString(j, "text") {
      None     => Err("missing text"),
      Some(tv) => Ok({text: tv, ...})
    }
  }
}
```

GOOD (flatten with helpers + sequential let-bindings):
```ailang
pure func optional_string(j: Json, key: string) -> string = match getString(j, key) {
  Some(s) => s, None => ""
}

match decode(raw) {
  Err(e) => Err(e),
  Ok(j)  => {
    let err = optional_string(j, "error");
    if length(err) > 0
      then Err(err)
      else match getString(j, "text") {
        None     => Err("missing text"),
        Some(tv) => Ok({text: tv, glyph: optional_string(j, "glyph"), ...})
      }
  }
}
```

#### Pattern 2 — Repeated matches on same tagged-union with `.field` access

BAD (each `s.x` / `s.y` triggers fresh tagged-union receiver analysis):
```ailang
let has_score = match score_result { Ok(_) => true,  Err(_) => false };
let sx        = match score_result { Ok(s) => s.x,   Err(_) => 0.0 };
let sy        = match score_result { Ok(s) => s.y,   Err(_) => 0.0 };
```

GOOD (one match → record → plain field reads downstream):
```ailang
pure func unpack(r: Result[JudgeScore, string]) -> {has: bool, x: float, y: float} =
  match r {
    Ok(s)  => {has: true,  x: s.x, y: s.y},
    Err(_) => {has: false, x: 0.0, y: 0.0}
  }
let score = unpack(score_result);
```

#### Pattern 3 — Heavy intra-package imports with constructor destructuring

BAD (8 destructured names including 3 sum constructors):
```ailang
import cognitive_commons/services/consensus
  ( CommonsState, applyUtterance, applyManifestoEdit,
    currentLeader, leaderGap, EditOutcome,
    Accepted, RejectedNotLeader, RejectedTooShort )
```

GOOD (import only what you actually use; qualify others if needed):
```ailang
import cognitive_commons/services/consensus
  ( CommonsState, applyUtterance, applyManifestoEdit, RejectedTooShort )
```

#### Pattern 4 — Multi-effect annotations on hot-path functions

BAD (every effect adds row constraints to the solver):
```ailang
export func speak(...) -> Result[CommonsState, string] ! {AI, DOM, Msg, IO} = {
  -- 60 lines mixing AI calls, DOM patches, Msg sends, println
}
```

GOOD (split orchestration; multi-effect function only orchestrates):
```ailang
func compose_only(...) -> Result[AuthorReply, string] ! {AI} = { ... }
func render_only(reply: AuthorReply, region: string) -> () ! {DOM} = { ... }
func broadcast_only(reply: AuthorReply) -> () ! {Msg} = { ... }

export func speak(...) -> Result[CommonsState, string] ! {AI, DOM, Msg} = {
  match compose_only(...) {
    Err(e)    => Err(e),
    Ok(reply) => { render_only(reply, region); broadcast_only(reply); Ok(st) }
  }
}
```

#### Pattern 5 — Deep record-field access in tight expressions

BAD (`.sentiment.x` four times inside string interpolation):
```ailang
let sx = show(st.sentiment.x);
let sy = show(st.sentiment.y);
let tx = show(proposer_target.x);
let ty = show(proposer_target.y);
"x=${sx}, y=${sy}, tx=${tx}, ty=${ty}"
```

GOOD (let-bind intermediate record once):
```ailang
let s = st.sentiment;
let t = proposer_target;
"x=${show(s.x)}, y=${show(s.y)}, tx=${show(t.x)}, ty=${show(t.y)}"
```

**Runnable worked example**: `examples/wasm_friendly_patterns.ail` has
`bad_*` and `good_*` versions of each pattern side-by-side. Passes
`ailang check`; demonstrates that the refactored shapes are also shorter
and easier to maintain.

## Troubleshooting: No Output / Silent Failures

When your program type-checks and runs but produces **no output**, check these in order:

**1. Missing `--caps` flag (most common)**
```bash
# WRONG: no capabilities — IO effects silently fail or error
ailang run module.ail

# CORRECT: flags BEFORE filename
ailang run --caps IO module.ail
```
Flags MUST come before the filename. `ailang run module.ail --caps IO` does NOT work.

**2. Wrong effect signature**
```ailang
-- WRONG: IO[Unit] is not valid effect syntax
export func main() -> IO[Unit] { println("hello") }

-- CORRECT: Unit with IO effect annotation
export func main() -> Unit ! {IO} { println("hello") }
-- or shorthand:
export func main() -> () ! {IO} { println("hello") }
```

**3. Multi-expression bodies need semicolons (inside `{ }`)**
```ailang
-- WRONG: second expression not reachable (parsed as two statements without separator)
export func main() -> () ! {IO} {
    let xs = dedup(myList)
    println(show(length(xs)))
}

-- CORRECT: use semicolons inside { } blocks
export func main() -> () ! {IO} {
    let xs = dedup(myList);
    println(show(length(xs)))
}

-- ALSO CORRECT: single-expression form with let...in (no braces)
export func main() -> () ! {IO} =
    let xs = dedup(myList) in println(show(length(xs)))
```

**4. `println` needs a string argument**
```ailang
-- WRONG: println(42) — type error
-- CORRECT: println(show(42)) — show converts any type to string
```

**5. `--debug-compile` showing "0 specializations" is NORMAL**
This just means no polymorphic functions needed monomorphization. It does NOT indicate a problem.

**Diagnostic checklist:**
```bash
ailang check file.ail                    # 1. Type errors?
ailang run --caps IO file.ail 2>&1       # 2. Check stderr for errors
ailang run --caps IO --debug-compile file.ail  # 3. Compilation phases OK?
```

## Quick Reference: Common Workflows

**"My program produces no output"**:
1. Verify `--caps IO` is BEFORE the filename: `ailang run --caps IO file.ail`
2. Check effect signature is `-> () ! {IO}` (not `-> IO[Unit]`)
3. Check multi-line bodies use semicolons: `let x = e; println(x)`
4. Check stderr: `ailang run --caps IO file.ail 2>&1`

**"My program crashes"**:
1. `ailang check --timeout 30s file.ail` (type errors?)
2. `ailang run --emit-trace jsonl --caps IO --entry main file.ail > trace.jsonl` (trace execution)
3. `ailang replay trace.jsonl` (is it deterministic?)

**"Is my change correct?"**:
1. Record baseline: `ailang run --emit-trace jsonl ... > baseline.jsonl`
2. Make changes
3. Replay: `ailang replay baseline.jsonl` (exit 0 = match)

**"What tools do I have?"**:
1. `ailang docs --list` (stdlib modules)
2. `ailang builtins list --by-module` (builtin functions)
3. `ailang prompt` (language syntax reference)

**"Train on my own traces"**:
1. `ailang run --emit-trace jsonl --caps IO --entry main module.ail > trace.jsonl`
2. `ailang replay trace.jsonl` (verify determinism)
3. `ailang export-training --score trace.jsonl` (check quality)
4. `ailang export-training --min-score 0.5 traces/` (export high-quality examples)

**"How do I improve my code quality?"**:
1. `ailang run --emit-trace jsonl --caps IO --entry main file.ail > trace.jsonl`
2. `ailang export-training --score --json trace.jsonl` (check score breakdown)
3. Add contracts, extract functions, add budget annotations based on low scores
4. Re-trace and re-score (iterate until score > 0.5)

**"Monitor agent work"**:
1. `ailang chains list --since 24h` (recent executions)
2. `ailang chains view <id> --spans` (detailed view)
3. `ailang chains stats --by-agent` (cost summary)

**"Serve my AILANG code as an API"**:
1. `ailang serve-api --watch --cors --caps IO,AI ./api/` (start dev server)
2. `curl http://localhost:8080/api/<module>/<function>` (call endpoints)

**"Prove my contracts correct"**:
1. `ailang verify file.ail` (prove all contracts)
2. `ailang verify --verbose file.ail` (see generated SMT-LIB)
3. `ailang verify --json file.ail` (machine-readable for CI)

**"Set up a new project"**:
1. `ailang init web-app my-app` (scaffold)
2. `cd my-app && ailang serve-api --watch --frontend ./ui api/` (develop)

### Package Coordination (M-PKG-MSG)

When packages are published or upgraded, the system emits structured coordination messages automatically.

```bash

# Find which workspaces depend on a package
ailang pkg affected-by sunholo/auth

ailang messages list --inbox pkg:sunholo/auth

# Send a structured compatibility report
ailang messages send pkg:sunholo/auth "Compatibility verified" \
  --title "[compatibility-report] sunholo/auth" --from "workspace:docparse"
```

**Inbox addressing**: Package messages use typed prefixes:
- `pkg:vendor/name` — package inbox (e.g., `pkg:sunholo/auth`)
- `workspace:name` — workspace inbox (e.g., `workspace:docparse`)
- `team:name` — team inbox (e.g., `team:registry-admin`)

**Auto-emitted on publish**: `upgrade-available`, `interface-change-notice`, `effect-widening-warning`

**Message lifecycle**: `open` → `acknowledged` → `in_progress` → `completed` (or `blocked`, `rejected`, `superseded`)

**11 message kinds**: `upgrade-available`, `interface-change-notice`, `effect-widening-warning`, `compatibility-request`, `compatibility-report`, `contract-regression`, `migration-request`, `deprecation-notice`, `upgrade-complete`, `blocked`, `superseded`
