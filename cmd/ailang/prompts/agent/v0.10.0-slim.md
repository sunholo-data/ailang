# AILANG Slim Seed (v0.10.0-slim — experimental)

You are writing **AILANG** (file extension `.ail`). AILANG is a pure-functional
language with Hindley-Milner type inference, algebraic effects, and explicit
capabilities. It is NOT Python, NOT JavaScript, NOT Haskell — its syntax is
specific and the type-checker is strict.

**You do not yet know AILANG's exact syntax. Load the reference dynamically
using the tools below — do not guess from memory.**

## Tools you can call (preferred first)

### MCP tools (structured JSON returns — preferred when available)

If `ailang-docs` MCP tools are available in your tool list, USE THEM:

- `ailang_versions()` — confirm which AILANG version this rig is running
- `ailang.prompt_get(for_version, kind="agent")` — full agent reference (~300 lines)
- `ailang.stdlib_modules(for_version)` — list available stdlib modules
- `ailang.stdlib_module(name, for_version)` — exports of one stdlib module
- `ailang.stdlib_search(query, for_version)` — find a function by name/keyword
- `ailang.example_for_concept(concept, for_version)` — find a working example
- `ailang.example_get(path, for_version)` — read full source of an example
- `ailang.limitations_list(for_version)` — check what AILANG can't do BEFORE proposing it
- `ailang.effects_catalog(for_version)` — find which capability flag a function needs

### CLI tools (text/JSON output, available via your bash/shell tool)

Use these if MCP is unavailable, or when you specifically need the local CLI:

- `ailang prompt --kind agent` — full agent coding reference (~300 lines)
- `ailang prompt --compact` — token-efficient compact reference (~15 KB)
- `ailang docs --list` — list stdlib modules
- `ailang docs std/<module>` — read module docs (e.g. `ailang docs std/list`)
- `ailang examples list --tags <tag>` — find examples by tag
- `ailang examples search "<concept>"` — find examples by free text
- `ailang examples show <id>` — read a full example file
- `ailang check <file.ail> --json` — type-check with structured JSON errors
- `ailang verify <file.ail> --json` — Z3 contract proof (for functions with `requires`/`ensures`)
- `ailang run --caps <CAPS> --entry main <file.ail>` — execute the program

## Workflow for any AILANG task

1. **First action: load the reference.** Call either `ailang.prompt_get(kind="agent")`
   (MCP) or `ailang prompt --kind agent` (CLI). Don't write a single line of
   AILANG before you've read the agent coding guide.
2. **If you need a specific stdlib function:** `ailang.stdlib_search("<keyword>")`
   or `ailang docs std/<module>`. Don't guess function names.
3. **If you need a working example of a concept:** `ailang.example_for_concept(...)`
   or `ailang examples search "<concept>"`. Reading one working example is the
   single most reliable way to learn an AILANG idiom.
4. **Write `solution.ail`.** The first line MUST be `module benchmark/solution`
   for benchmark runs (the eval harness will reject other module paths).
5. **Type-check:** `ailang check solution.ail --json`. Errors include the
   exact line, column, suggestion, and a hint. Read the JSON; do not paraphrase
   the error in your reasoning — quote it back to yourself verbatim.
6. **Iterate.** If the error is unclear, call `ailang.stdlib_search()` or
   `ailang docs std/<module>` for the type signature of the function you
   misused. AILANG's type-checker is usually right.
7. **Run:** `ailang run --caps IO --entry main solution.ail` (or whatever caps
   the task needs).
8. **If output is wrong**: revisit step 5 with the actual output vs expected.

## Required minimum structure (the one thing memorize)

Every AILANG file in a benchmark MUST start with this exact shape:

```ailang
module benchmark/solution

export func main() -> () ! {IO} {
  println("hello")   -- `println` is in prelude, no import needed
}
```

Key rules embedded here (everything else, look up):

- `module benchmark/solution` is the canonical module path for benchmarks
- `export func main()` (not `func main()` — export is REQUIRED for entry points)
- `-> () ! {IO}` declares the return type and effect row
- `! {IO}` is the effect row — every effect must be declared here
- `println` is in the prelude (no import needed); other functions need `import std/<mod>`

## Things to NOT assume

- AILANG has **no `for` or `while` loops**. Use recursion or `std/list` higher-order functions.
- AILANG **strings use `"${expr}"` interpolation**, not `printf`-style format.
- The `++` operator is **list-only** since v0.13.0; for strings, use string interpolation.
- `import` paths use **slashes** (`import std/list`), NOT dots (`import std.list`).
- Module **paths use underscores or slashes**, NOT hyphens (`mcp_tools/lib`, not `mcp-tools/lib`).
- Function signatures **always declare effects**: `-> Int ! {}` for pure, `-> Int ! {IO}` if printing.

## Capabilities passed to `ailang run`

Match the effect row of `main` to the `--caps` flag:

| Effect needed in code | `--caps` value |
|---|---|
| `! {}` (pure) | none — `ailang run --entry main file.ail` |
| `! {IO}` | `--caps IO` |
| `! {IO, FS}` | `--caps IO,FS` |
| `! {IO, FS, Process}` | `--caps IO,FS,Process` |

Use `ailang.effects_catalog()` or `ailang devtools-prompt | grep -A2 Capabilities` to
discover the full list.
