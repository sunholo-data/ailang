## The defect (reproduced by the controller at HEAD 02e1429d3)
Under a non-Claude controller the driver sets `MISSION_ANTHROPIC_AVAILABLE=0` (tools/launchd/mission-control.sh:988-989). The planner arm of `tools/launchd/resolve-role-spawn.sh` already honours it (via derive-planner-lane.sh, emitting `recipe codex:gpt-6.1-sol anthropic-fallback:...`). But for the designer, executor and evaluator, a BARE ALIAS pin (no `:` — e.g. `sonnet`, `opus`, `fable`, `haiku`) still resolves to `agent-tool <alias> declared:alias-pin`, byte-identical to the Claude-controller reading:

    MISSION_ANTHROPIC_AVAILABLE=0 MISSION_EVALUATOR_MODEL=sonnet bash tools/launchd/resolve-role-spawn.sh evaluator
    -> agent-tool sonnet declared:alias-pin      (same as with =1)

A codex controller's native spawn cannot run a Claude alias (`Unknown model sonnet for spawn_agent`), so 7 tickets / 25 lost slots come from this.

## The change (option A, as worded in the ruling)
"When a codex or pi controller executes a role pinned to a Claude alias (`sonnet`, `opus`), the resolver skips to the role's next provider-pinned fallback (no Claude)."

In `resolve-role-spawn.sh`, in the non-planner bare-alias branch, when and ONLY when `MISSION_ANTHROPIC_AVAILABLE` equals exactly `0`:
1. Walk `MISSION_<ROLE>_FALLBACK` (comma-separated, left to right; trim surrounding whitespace on each entry; ignore empty entries).
2. Skip an entry if ANY of: it has no `:` (a bare alias); it starts with `claude:` (no Claude); `_rs_over` says its bucket is over ration (reuse the existing function, do not duplicate the bucket logic); for the evaluator role only, it equals the executor's resolved value (`MISSION_EXECUTOR_RESOLVED`, else `MISSION_EXECUTOR_MODEL`) or has the same `family` as it (generator != judge; reuse the existing `family` function).
3. Emit `reroute <first surviving entry> anthropic-unavailable` (exactly that reason token).
4. If no entry survives (or the variable is unset/empty), emit `refuse fail-closed:anthropic-unavailable-no-fallback`.
This check runs BEFORE the existing evaluator generator-equals-judge collision check (the alias cannot be spawned at all, so the collision is moot). When `MISSION_ANTHROPIC_AVAILABLE` is unset, empty, `1` or anything other than `0`, behaviour must be byte-identical to today for every role and input. Do not change the planner arm, `emit_recipe`, provider-pin handling, or `_rs_bucket`. Keep the script's contract: always exit 0, exactly one stdout line. Add a short comment above the new block citing D-FLEET-24 option A.
