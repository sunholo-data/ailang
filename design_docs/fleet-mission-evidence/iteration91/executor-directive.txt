## WHAT TO BUILD

### A. `tools/launchd/lib/idle-fingerprint.sh` — the generic no-pick fingerprint
Usage: `idle-fingerprint.sh [--record]`. Exit 2 on bad usage. Refuse (exit 2, message) when `MISSION_NAME` is empty, `fleet` or `triage` (they have their own idle checks).
Inputs (env): `MISSION_NAME`, `MISSION_REPO`, `MISSION_DOC` (charter path relative to the work repo), `MISSION_WORKDIR` (a checkout of the mission's WORK repo; for World this is a clone of sunholo-data/ailang-world, NOT this repo), `MISSION_DIRECTIVE_AUTHORS` (default `MarkEdmondson1234`, same parsing as triage), state dir `${IDLE_STATE_DIR:-$HOME/.ailang/state}`.
Branch: the work repo's `origin/HEAD` symbolic ref (`git -C "$MISSION_WORKDIR" symbolic-ref --short refs/remotes/origin/HEAD`), falling back to `origin/dev` only if that ref is absent; say which in a comment. `git fetch -q origin <branch>` first (a failed fetch is a failed read).
Fingerprint = sha256 over these sorted sections:
- `head <sha>` — the newest commit on origin/<branch> that touches ANY path outside the mission's own record paths, i.e. `git log -1 --format=%H origin/<branch> -- . ':(exclude)design_docs/<name>-mission*' ':(exclude)verification/<name>-iter*'`. (World's record commits touch `design_docs/world-mission*.md` and `verification/world-iterNNN/...`; measured on ailang-world origin/dev, e.g. `8cde156b`.) Verify the exclude pathspec works on the rig's git with a real temp repo in your test. Empty output = failed read.
- `ledger <ID>:<STATUS>` — every row of the charter's decision ledger, read from `git show origin/<branch>:$MISSION_DOC` (NOT the working tree). The block is delimited by `<!-- decision-ledger:start -->` / `<!-- decision-ledger:end -->`; see how `scripts/mission_decisions.sh` parses it and reuse its parsing rule (ID = first cell, STATUS = second cell). A charter with no ledger block is a legitimate zero-row reading only if the markers are absent entirely; a start without an end (or vice versa) is a failed read. An attended ruling flipping OPEN→RESOLVED must change the hash.
- `directive <comment id>:<updated_at>` — allowlisted-author comments on the current bookkeeping issue, whose number is in `$state_dir/mission-<name>-gh-issue` (die if that file is absent or non-numeric). Same jq as triage. The loop's own report comments are not allowlisted and must NOT move the hash.
- `inbox <message id>` — unread messages in inbox `mission-<name>`: `ailang messages list --unread --inbox "mission-<name>" --json --limit 1000` (stdout only; the binary prints warnings on stderr). Check what the JSON shape actually is from the source (`cmd/ailang/messages*.go`) rather than guessing; an unparseable result or a result at the limit is a failed read. Do not change how the store is selected — the driver's environment (`AILANG_STORAGE_MESSAGING` etc.) already decides it.
- `red <check name>:<conclusion>` — check-runs on the origin/<branch> TIP commit (`gh api repos/$MISSION_REPO/commits/<tip sha>/check-runs --paginate`) whose conclusion is failure, timed_out, cancelled, action_required or startup_failure. Pending/success/skipped/neutral are NOT included (a run finishing green must not wake the loop). `total_count` of 0 is a legitimate reading (do not die), but an unparseable response is a failed read.
Output: ONE stdout line, last line: `<sha256> head=<sha7> ledger=<rows> open=<OPEN rows> directives=<n> inbox=<n> red=<n>`.
`--record` writes that line plus ` at=<epoch seconds>` to `$state_dir/mission-<name>-idle-fingerprint` atomically (tmp + mv), and is the ONLY writer of that file.
