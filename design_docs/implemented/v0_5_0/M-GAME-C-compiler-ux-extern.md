## Problem Statement

**Current State:**
- No CLI command to generate Go code from AILANG
- No way to call Go-implemented performance-critical functions from AILANG
- Error messages don't explain Go interop issues clearly
- Game developers must manually wire types between languages

**Impact:**
- Game developers can't use AILANG's type safety for logic while keeping Go's performance
- Build toolchain is incomplete - can't compile AILANG → Go in one step
- Interop errors are confusing and don't guide developers to solutions

## Goals

**Primary Goal:** Enable seamless compilation from AILANG to Go with extern function support for performance-critical code.

**Success Metrics:**
- `ailang compile --emit-go` generates valid, runnable Go code
- Extern functions with monomorphic types work end-to-end
- Error messages for interop issues include actionable suggestions
- 100% of generated Go code compiles with `go build`

## Solution Design

### Overview

Add compiler flags for Go code generation, implement extern function syntax for Go-implemented helpers, and improve error messages for interop issues.

### Architecture

**Components:**
1. **Compiler CLI**: Add `--emit-go`, `--out`, `--package-name` flags
2. **Extern Parser**: Add EXTERN token and `extern func` parsing
3. **Extern Codegen**: Generate Go function stubs from extern declarations
4. **Error Reporting**: Enhanced messages for type mismatches and interop issues

### Design Decisions (Locked)

#### D1: Extern Functions are Monomorphic Only

**Supported types (v0.5.x):**
- Primitives: `int`, `float`, `bool`, `string`
- Structs/records already generated by AILANG
- Lists/arrays that map to `[]T`

**NOT supported (deferred to v0.6.0+):**
- Polymorphic externs: `extern func map[a,b](f: a -> b, xs: [a]) -> [b]`
- Higher-kinded types
- Function parameters

**Rationale:** Keeps implementation manageable. Games only need pathfinding, influence maps, etc.

## Examples

### Example 1: Compiler Usage

**Usage:**
```bash
ailang compile --emit-go --package-name game --out gen/ world.ail
```

**Output:**
```
gen/
├── game/
│   ├── world.go       # Generated types and functions
│   └── stubs.go       # Extern function stubs (implement these)
```

### Example 2: Extern Function Declaration

**AILANG code:**
```ailang
extern func find_path(world: World, from: Coord, to: Coord) -> Path
extern func compute_influence_map(world: World, source: Coord) -> [[float]]
```

**Generated Go stub (stubs.go):**
```go
// FindPath must be implemented in your game code.
// Signature: func FindPath(world World, from Coord, to Coord) Path
//
// Example implementation in path_impl.go:
//   func FindPath(world World, from Coord, to Coord) Path {
//       // A* or other pathfinding algorithm
//       return Path{Nodes: []Coord{from, to}}
//   }
func FindPath(world World, from Coord, to Coord) Path {
    panic("extern func FindPath not implemented")
}

// ComputeInfluenceMap must be implemented in your game code.
func ComputeInfluenceMap(world World, source Coord) [][]float64 {
    panic("extern func ComputeInfluenceMap not implemented")
}
```

### Example 3: Improved Error Messages

**Before (unclear):**
```
Error: type mismatch in codegen
```

**After (actionable):**
```
Error: Cannot generate Go code for extern function 'find_path'

  extern func find_path[T](graph: Graph[T], from: T, to: T) -> [T]
                       ^^^
  Polymorphic extern functions are not supported in v0.5.x.

  Suggestion: Use a monomorphic signature instead:
    extern func find_path(graph: Graph, from: Coord, to: Coord) -> [Coord]

  See: docs/guides/go-interop.md#extern-functions
```

## Testing Strategy

**Unit tests:**
- Lexer recognizes EXTERN token
- Parser creates correct ExternFunc AST nodes
- Codegen produces valid Go stubs
- Error messages contain expected content

**Integration tests:**
- End-to-end: AILANG file → Go code → compiles with `go build`
- Extern functions callable from generated code
- Missing implementation panics with helpful message

**Manual testing:**
- Compile examples/sim_stub with new CLI
- Verify stubs are usable

## Non-Goals

**Not in this feature:**
- Polymorphic extern functions - Deferred to v0.6.0+
- Higher-kinded types - Complex, not needed for games
- Function parameters in externs - Requires closure handling
- `ailang gen --stubs` subcommand - Use `--emit-go` instead
