## Problem Statement

Go codegen produces excessively nested code for list literals and chained bool matches, causing:
- Difficult-to-debug generated code
- Potential stack overflow during Go compilation
- Poor readability of generated code
- Excessive indentation (58+ chars in starmap.go)

**Current State:**

1. **List literals with expressions create O(n) nested closures**

   AILANG source:
   ```ailang
   let stars = [
       makeSol(),
       makeStar(1, "Proxima", -1.55, -1.32, -3.77, M, true),
       -- 19 more stars...
   ]
   ```

   Generated Go (simplified):
   ```go
   return func() interface{} {
       var tmp1 = makeSol()
       return func() interface{} {
           var tmp2 = NegFloat(1.55)
           return func() interface{} {
               var tmp3 = NegFloat(1.32)
               return func() interface{} {
                   // ... 60+ levels deep for 21 stars
               }()
           }()
       }()
   }()
   ```

   Each list element with any sub-expression (like negative numbers) adds nested closures.

2. **Chained match on booleans creates nested closures**

   AILANG source:
   ```ailang
   match roll < 0.76 {
       true => M,
       false => match roll < 0.88 {
           true => K,
           false => match roll < 0.955 { ... }
       }
   }
   ```

   Generates 7 levels of nested `func() interface{} { switch ... }()` for 7 spectral types.

**Impact (stapledons_voyage):**
- starmap.go: 58 chars indentation (~14 nesting levels)
- bridge.go: 101 closure wrappers, 172 suppress-unused comments
- initLocalCatalog_impl: 60+ nesting levels for 21-star list
- Extremely difficult to debug generated code

## Goals

**Primary Goal:** Eliminate O(n) closure nesting in list literals and bool match chains.

**Success Metrics:**
- ✅ List literal nesting: O(n) → O(1) (single IIFE with flat bindings)
- ✅ Bool match nesting: O(n) → O(1) (flat if-else chain)
- ✅ starmap.go indentation: 58 chars → <20 chars
- ✅ Generated code is debuggable by humans

## Solution Design

### Overview

Two targeted fixes to the Go codegen:

1. **List flattening**: Detect Let chains in function bodies and use Block IR to flatten before generating
2. **Bool match flattening**: Convert nested Let-Bool-Match patterns to flat if-else chains

### Architecture

**Component 1: Let Chain Detection and Flattening**

The key insight is that ANF (A-normal form) turns list literals into Let chains:

```ailang
[makeSol(), makeStar(...)]
```

Becomes Core AST:
```
Let tmp1 = makeSol() in
Let tmp2 = ... in
Let tmp3 = makeStar(...) in
[tmp1, tmp3]
```

The `generateFlatBody` function (from M-CODEGEN-V2) already uses Block IR to extract top-level Let bindings. The fix ensures this works for all Let chains, not just simple cases.

**Component 2: Bool Match Flattener**

Detect pattern: `Let $cmp = <comparison> in Match $cmp { true => A, false => <recurse> }`

This pattern is generated by ANF from `match <bool-expr> { true => ..., false => ... }`.

Convert to if-else chain:

```go
// Before: Nested switches in IIFEs
func() interface{} {
    var tmp1 = LtFloat(roll, 0.76)
    switch tmp1 {
    case true: return M
    case false: return func() interface{} {
        var tmp2 = LtFloat(roll, 0.88)
        switch tmp2 {
        case true: return K
        case false: return func() interface{} { ... }()
        }
    }()
    }
}()

// After: Flat if-else
if LtFloat(roll, 0.76).(bool) {
    return NewSpectralTypeM()
} else if LtFloat(roll, 0.88).(bool) {
    return NewSpectralTypeK()
} else if LtFloat(roll, 0.955).(bool) {
    return NewSpectralTypeG()
} else {
    return NewSpectralTypeO()
}
```

### Implementation Notes

**Key Discovery: LitPattern.Value is the Go value directly**

The most important lesson from implementation: In Core AST `LitPattern`, the `Value` field is the Go value directly (e.g., `true`/`false` as `bool`), NOT a `*core.Lit` struct.

```go
// ❌ WRONG - This never matches!
if lit, ok := lp.Value.(*core.Lit); ok {
    if boolVal, ok := lit.Value.(bool); ok { ... }
}

// ✅ CORRECT - LitPattern.Value is the Go value directly
if val, ok := lp.Value.(bool); ok {
    if val {
        trueArm = arm
    } else {
        falseArm = arm
    }
}
```

**Detection Order Matters**

The `generateFlatBody` function must check for Let-Bool-Match chains BEFORE calling `block.Lower()`, because Block IR extraction loses the context needed to detect the pattern:

```go
func (g *Generator) generateFlatBody(body core.CoreExpr) error {
    // Check for bool match chain BEFORE lowering
    if let, ok := body.(*core.Let); ok && isLetBoolMatchChain(let) {
        return g.generateFlatBodyBoolMatchChain(let)
    }

    // Then proceed with normal Block IR lowering
    blk := block.Lower(body)
    // ...
}
```

## Examples

### Example 1: List Literal with Expressions (initLocalCatalog)

**AILANG:**
```ailang
let stars = [
    makeSol(),
    makeStar(1, "Proxima Centauri", -1.55, -1.32, -3.77, M, true),
    -- 19 more stars...
]
```

**Before (60+ nested IIFEs):**
```go
return func() interface{} {
    var tmp37 interface{} = makeSol_impl(struct{}{})
    return func() interface{} {
        var tmp38 interface{} = NegFloat(float64(1.55))
        return func() interface{} {
            var tmp39 interface{} = NegFloat(float64(1.32))
            return func() interface{} {
                // ... 60+ more levels
            }()
        }()
    }()
}()
```

**After (single IIFE with flat bindings):**
```go
return func() interface{} {
    var tmp37 interface{} = makeSol_impl(struct{}{})
    var tmp38 interface{} = NegFloat(float64(1.55))
    var tmp39 interface{} = NegFloat(float64(1.32))
    var tmp40 interface{} = NegFloat(float64(3.77))
    var tmp41 interface{} = makeStar_impl(int64(1), "Proxima Centauri", tmp38, tmp39, tmp40, NewSpectralTypeM(), true)
    // ... all bindings flat
    return sim_starmap.RecordStarCatalog{/* ... */}
}()
```

### Example 2: Bool Match Chain (spectralFromRoll)

**AILANG:**
```ailang
pure func spectralFromRoll(roll: float) -> SpectralType {
    match roll < 0.76 {
        true => M,
        false => match roll < 0.88 {
            true => K,
            false => match roll < 0.955 {
                true => G,
                false => match roll < 0.985 {
                    true => F,
                    false => match roll < 0.991 {
                        true => A,
                        false => match roll < 0.99913 {
                            true => B,
                            false => O
                        }
                    }
                }
            }
        }
    }
}
```

**Before (7 nested IIFEs with switches):**
```go
func() interface{} {
    switch tmp1 {
    case true: return NewSpectralTypeM()
    case false: return func() interface{} {
        switch tmp2 {
        case true: return NewSpectralTypeK()
        case false: return func() interface{} {
            // ... 5 more nesting levels
        }()
        }
    }()
    }
}()
```

**After (flat if-else chain, 16 lines):**
```go
if LtFloat(roll, float64(0.76)).(bool) {
    return NewSpectralTypeM()
} else if LtFloat(roll, float64(0.88)).(bool) {
    return NewSpectralTypeK()
} else if LtFloat(roll, float64(0.955)).(bool) {
    return NewSpectralTypeG()
} else if LtFloat(roll, float64(0.985)).(bool) {
    return NewSpectralTypeF()
} else if LtFloat(roll, float64(0.991)).(bool) {
    return NewSpectralTypeA()
} else if LtFloat(roll, float64(0.99913)).(bool) {
    return NewSpectralTypeB()
} else {
    return NewSpectralTypeO()
}
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|-----------|
| Evaluation order changes | High | Preserved left-to-right order in flattened output ✅ |
| Variable name collisions | Medium | Used existing tmp naming from ANF ✅ |
| Recursive lists | Medium | Block IR handles nested Let chains ✅ |
| ADT patterns mixed with bool | Medium | Only flatten pure bool chains, fall back for ADT ✅ |
