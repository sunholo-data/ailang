## Problem Statement

### Two regressions live in prod right now

`mcp.ailang.sunholo.com` advertises 21 tools but **two of them return errors on every call**:

```bash
$ curl -X POST https://mcp.ailang.sunholo.com/mcp/ ... \
    -d '{"method":"tools/call","params":{"name":"docs_search","arguments":{"query":"install","forVersion":""}}}'

{"error": "snapshot_read_failed",
 "detail": "missing:/srv/snapshot/versioned/latest/docs_search_index.json"}
```

The tools were defined in M1 but the corresponding **snapshot indexes were never generated by `tools/build-snapshot/`**:

| Tool | Expected snapshot file | Status |
|---|---|---|
| `docs_search` | `versioned/<ver>/docs_search_index.json` | ❌ never generated |
| `example_for_concept` | `versioned/<ver>/example_concept_index.json` | ❌ never generated |
| `examples_list` | `versioned/<ver>/examples_index.json` | ✅ exists (passthrough of `examples_report.json`) |
| `stdlib_search` | `versioned/<ver>/stdlib_search_index.json` | ❌ never generated (third broken tool — found while writing this doc) |

This is a **silent contract violation** — the AILANG-side tool happily registers and advertises its schema, but every call fails with the same generic `snapshot_read_failed` envelope. Agents can't tell from `tools/list` that these are broken.

### Missing capability: install + onboarding

There is **no tool** that answers an agent's most fundamental questions:

- "How do I install AILANG?"
- "Is this version current, or should I upgrade?"
- "I just installed AILANG — what's the right way to use it from my coding agent?"

Today the agent has to:
1. Call `prompt_get` (which mentions `make install` once in passing)
2. Or scrape `getting-started.mdx` (which the broken `docs_search` would help with if it worked)
3. Or already know about [`ailang_bootstrap`](https://github.com/sunholo-data/ailang_bootstrap) (the canonical install + onboarding plugin)

The `ailang_bootstrap` plugin's README + `skills/ailang/SKILL.md` contain the canonical answers. Those should be exposed structurally via MCP, not just to humans browsing the website.

### Why agent-driven install matters

The MCP server's whole point is "agents stop scraping HTML and start calling typed tools." Forcing them to scrape `getting-started.mdx` for install commands defeats it. An agent that's just learned about AILANG via the MCP should be able to ask the same MCP "how do I install you?" and get a structured, harness-aware answer.

## Proposed Tool Surface

### Fix 3 broken existing tools (no API change)

Generate the three missing snapshot indexes in `tools/build-snapshot/`. Tool schemas already documented; this is purely a snapshot data fix.

| Index file | Built from | Used by |
|---|---|---|
| `versioned/<ver>/docs_search_index.json` | `docs/docs/**/*.{md,mdx}` — flat array `[{path, title, body, headings}]` | `docs_search(query, forVersion)` |
| `versioned/<ver>/example_concept_index.json` | `examples/examples_report.json` + tags from each `.ail` file's header comments — `[{path, title, concepts: [...], why}]` | `example_for_concept(concept, forVersion)` |
| `versioned/<ver>/stdlib_search_index.json` | `std/*.ail` exports parsed into flat `[{module, name, signature, doc, keywords}]` | `stdlib_search(query, forVersion)` |

For v1, simple substring/keyword matching in the AILANG-side tool is fine — the JSON is small (<100 KB total). If query latency becomes an issue, swap to FTS5 in v2 once `std/sqlite` lands.

### New tools

Two new tools that read from new snapshot files.

#### `install_guide(harness, platform?)`

Returns harness-specific install instructions, derived from `getting-started.mdx` + `ailang_bootstrap/README.md`.

**Inputs:**
- `harness`: `"claude-code"` | `"gemini-cli"` | `"codex-cli"` | `"manual"` | `""` (returns all)
- `platform`: `"darwin-amd64"` | `"darwin-arm64"` | `"linux-amd64"` | `"linux-arm64"` | `"windows-amd64"` | `""` (manual install only — others auto-detect)

**Output:**
```json
{
  "harness": "claude-code",
  "commands": [
    "/plugin marketplace add sunholo-data/ailang_bootstrap",
    "/plugin install ailang"
  ],
  "what_you_get": [
    "AILANG binary (auto-installed for your platform)",
    "MCP tools: ailang_prompt, ailang_check, ailang_run, ailang_builtins",
    "Slash commands: /ailang:prompt, /ailang:new, /ailang:run, /ailang:challenge",
    "Teaching prompts: current syntax loaded automatically",
    "Plus the remote ailang-docs MCP at mcp.ailang.sunholo.com"
  ],
  "verify": [
    {"command": "ailang --version", "expect_pattern": "^v0\\.\\d+\\.\\d+"}
  ],
  "post_install": [
    "Run `ailang prompt` to load current syntax rules",
    "Try `ailang examples list` to find working code samples",
    "Add the remote MCP to your harness for live docs (auto-included via this plugin in Claude Code/Gemini CLI)"
  ],
  "docs_url": "https://ailang.sunholo.com/docs/guides/getting-started",
  "source_repo": "https://github.com/sunholo-data/ailang_bootstrap"
}
```

#### `onboarding_guide(role?)`

Returns a stepwise guide for agents/users picking up AILANG for the first time. Derived from `use-ailang` skill + `ailang_bootstrap/skills/ailang/SKILL.md`.

**Inputs:**
- `role`: `"agent"` | `"developer"` | `""` (defaults to `"agent"`)

**Output:**
```json
{
  "role": "agent",
  "steps": [
    {"n": 1, "title": "Install", "actions": ["Call install_guide(harness=...)", "Run the install commands", "Verify with ailang --version"]},
    {"n": 2, "title": "Add the live MCP", "actions": ["Add https://mcp.ailang.sunholo.com/mcp/ to your harness", "Verify connection: ailang mcp status (CLI) or check tools/list"]},
    {"n": 3, "title": "Load the prompt", "actions": ["Call prompt_get(forVersion=$AILANG_VERSION, kind='agent') for the agent-shaped guide (~180 lines)", "Or kind='' for the full ~50 KB reference"]},
    {"n": 4, "title": "Discover stdlib", "actions": ["Call stdlib_modules to see what's available", "Call stdlib_search before guessing imports"]},
    {"n": 5, "title": "Find examples", "actions": ["Call example_for_concept(concept='...') for a working pattern", "Call examples_list(features='effects,records') to filter"]},
    {"n": 6, "title": "Write code", "actions": ["Follow the prompt's syntax (use ${var} for string interpolation, NOT ++; use _ for unused; etc.)", "Type-check before running: ailang check file.ail"]},
    {"n": 7, "title": "Run with caps", "actions": ["ailang run --caps IO,FS --entry main file.ail", "Flags MUST come before the filename"]},
    {"n": 8, "title": "When stuck", "actions": ["Check limitations_list for known gaps", "Call submit_feedback to file a bug/limitation report from inside this session"]}
  ],
  "common_pitfalls": [
    "++ is list-only (use \"${var}\" interpolation for strings)",
    "module is a reserved word (don't use as parameter name)",
    "Module paths use underscores not hyphens (mcp_tools/lib not mcp-tools/lib)",
    "ailang run flags MUST come before the filename"
  ],
  "verification_path": "After step 7, you should have a working .ail file that prints something. If not, call submit_feedback with category=docs and what blocked you."
}
```

### Implementation choice: AILANG-side or Go-side?

Both new tools fit the AILANG-side pattern (read JSON from snapshot, return wrapped response) — same as `examples_list`, `prompt_get`, etc. **Recommend AILANG-side** for consistency, dogfood, and so adding more harnesses later (e.g. `cline`) is just a JSON edit, not a Go change.

## Architecture

No changes to the deployed Cloud Run service surface. All work lands in:

1. **`tools/build-snapshot/main.go`** — three new index generators (~200 LOC total) plus two new content generators (`install_guide_index.json`, `onboarding_guide_index.json`)
2. **`mcp_tools/install.ail`** (new file) — `install_guide` tool reading from `versioned/<ver>/install_guide.json`
3. **`mcp_tools/onboarding.ail`** (new file) — `onboarding_guide` tool reading from `versioned/<ver>/onboarding_guide.json`
4. **No Terraform/IAM/Dockerfile changes** — existing image just gets fatter snapshot

Snapshot size impact: estimated +50 KB total (mostly the docs_search_index). Image stays well under 50 MB.

## Implementation Plan (1.5 days)

### M1 — Fix broken indexes (0.5 day)

`tools/build-snapshot/main.go`:
- New `writeDocsSearchIndex()` — walks `docs/docs/**/*.{md,mdx}`, strips frontmatter, extracts title (first `#`) and body, splits into searchable tokens. Output: `versioned/<ver>/docs_search_index.json` with `[{path, title, headings, body}]`.
- New `writeExampleConceptIndex()` — reads `examples/examples_report.json` (handle the JSONL/JSON ambiguity I hit while writing this doc) + parses each `.ail` file's leading `--` comment block for tags. Output: `[{path, title, concepts: [...], why}]`.
- New `writeStdlibSearchIndex()` — extends the existing stdlib_summary builder to also emit per-export `{module, name, signature, doc, keywords}` rows.

`mcp_tools/discovery.ail` (existing) and `mcp_tools/language.ail` (existing): update the AILANG implementations to actually substring-match against the loaded indexes (currently they're stub passthroughs).

**Acceptance:**
- `tools/call docs_search query="install" forVersion=""` returns ≥1 hit pointing at `getting-started.mdx`
- `tools/call example_for_concept concept="effects" forVersion=""` returns a real example path
- `tools/call stdlib_search query="readFile" forVersion=""` returns `{module: "std/fs", name: "readFile", ...}`
- All three tools tested locally + smoke-tested against dev MCP after redeploy

### M2 — install_guide tool + index (0.5 day)

`tools/build-snapshot/main.go`:
- New `writeInstallGuideIndex()` — hand-curated for v1: parses `docs/docs/guides/getting-started.mdx` headings + `ailang_bootstrap/README.md` install sections, produces `[{harness, commands, what_you_get, verify, post_install, docs_url, source_repo}]`. Optionally takes a hand-edited override file `tools/build-snapshot/install_guide_overrides.json` for cases the parser misses.

`mcp_tools/install.ail` (new):
- `install_guide(harness, platform)` reads `versioned/<ver>/install_guide.json`, filters by harness if specified, returns the structured guide.

**Acceptance:**
- `tools/call install_guide harness="claude-code"` returns the `/plugin marketplace add ...` commands and what_you_get list
- `tools/call install_guide harness=""` returns ALL harnesses
- Manual platform variants (darwin/linux × amd64/arm64) covered
- Tool registered in `tools/list` and visible at `tools/call`

### M3 — onboarding_guide tool + index (0.5 day)

`tools/build-snapshot/main.go`:
- New `writeOnboardingGuideIndex()` — hand-curated `agent` and `developer` flows derived from `use-ailang` SKILL.md + `ailang_bootstrap/skills/ailang/SKILL.md`. Same override-file pattern as install_guide.

`mcp_tools/onboarding.ail` (new):
- `onboarding_guide(role)` reads `versioned/<ver>/onboarding_guide.json`, filters by role.

**Acceptance:**
- `tools/call onboarding_guide role="agent"` returns the 8-step flow listed above
- `tools/call onboarding_guide role=""` defaults to `agent`
- `common_pitfalls` includes the AILANG-syntax gotchas surfaced during M-AGENT-MCP execution (string `++`, module keyword, module-path hyphens, flag ordering) — those were learned the hard way; let's not make agents learn them the same way

### M4 — CHANGELOG + verify-mcp-tools + ship (0.5 day, runs in parallel with above)

- Update `make verify-mcp-tools` (already in CI) — should pass for the new `install.ail` and `onboarding.ail` automatically
- CHANGELOG entry under M-AGENT-MCP-ONBOARDING with what shipped + how to query the new tools
- Push dev → test → prod (the dance is now well-rehearsed; force `gcloud run services update` after each prod deploy because of the `:latest` SHA quirk we hit in M-AGENT-MCP)
- End-to-end smoke test: `curl https://mcp.ailang.sunholo.com/mcp/` → call all 4 fixed/new tools → verify real responses

### Optional M5 — `latest_release()` tool (skip for v1)

A live-querying tool that returns the latest GitHub release URL + version + date. Needs to do an HTTPS GET to `api.github.com` and respect rate limits.

**Defer**: the `--caps Net` is already enabled (M7 added it for feedback), so technically free. But maintaining a GitHub API quota and caching layer is its own small project. Let `install_guide` return a hand-curated "latest known release: vX.Y.Z" string for v1, refresh it on every release deploy.

## Risks & Tradeoffs

1. **Index quality** — substring matching is dumb. An agent searching `docs_search("install")` will get a hit on `getting-started.mdx` but might also get noise from other pages mentioning "install" in passing. Mitigation: weight title matches > heading matches > body matches in the index ranking, return top-5 only.
2. **Hand-curated install_guide goes stale** — if `ailang_bootstrap` adds a new harness or changes a command and we forget to update the index, the MCP returns wrong info. Mitigation: add `make verify-install-guide` that diffs the snapshot's commands against the actual `ailang_bootstrap/README.md` install sections; CI fails on drift.
3. **Onboarding guide opinionation** — different agents/harnesses may want different sequences. Mitigation: ship both `agent` and `developer` flows in v1; add more roles when actual feedback comes in via `submit_feedback`.
4. **Snapshot size growth** — adding three indexes + two guide files. Mitigation: still tiny (<200 KB combined); monitor `make snapshot` output. Hard cap remains 50 MB.
5. **The `:latest` SHA Cloud Run quirk** — we hit this twice in M-AGENT-MCP. M-AGENT-MCP-ONBOARDING should switch to image-SHA pinning in Terraform OR the cloudbuild.yaml deploy step should run `gcloud run services update --image=:latest` automatically. Handle as a small first-step fix in M1.

## Out of Scope (for v1)

- Live GitHub API queries for `latest_release` (defer to a v2 with caching)
- Per-platform binary URL discovery (manual install flow gives the GitHub releases page link; don't reinvent the wheel)
- Interactive onboarding (the MCP can't drive interactive flows; agent harnesses do that)
- A `verify_install` tool that actually runs `ailang --version` for the user (out of scope for a docs MCP — needs Process cap, harness should handle it)

## Open Questions

1. **Should `install_guide` include the AGENT MCP setup step?** (e.g. "Add `ailang-docs` to your MCP config"). Recommend YES — it's THE signal that they should use this MCP, and the tool calling it is literally proof the MCP is reachable.
2. **Should `onboarding_guide` be version-scoped?** The flow steps don't change much between versions. Recommend NO (unscoped, same as `roadmap`/`design_docs`) — saves snapshot space, simpler tool signature.
3. **`install_guide` parsing vs hand-curation?** Auto-parsing `getting-started.mdx` headings risks fragility (every doc edit could break the parse). Recommend hand-curated `install_guide_overrides.json` checked into `tools/build-snapshot/`, generated once and edited as needed; CI gate (`make verify-install-guide`) catches drift against the canonical sources.

## Success Metrics

- **Regression closed**: `docs_search`, `example_for_concept`, `stdlib_search` all return real results in prod within 1 release
- **Install tool adoption**: ≥10 calls to `install_guide` per week within 30 days of launch (Cloud Run logs)
- **Onboarding tool adoption**: ≥5 calls to `onboarding_guide` per week within 30 days
- **Bootstrap skill simplification**: `ailang_bootstrap/skills/ailang/SKILL.md` shrinks by another ≥20% LoC after M3 (it can stop embedding the install + step-by-step flow that's now in MCP)
- **Drift detection**: `make verify-install-guide` runs in CI and catches at least one drift event (i.e. does its job)
