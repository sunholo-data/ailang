# M-EVAL-DASHBOARD-REDESIGN: Surface ELO ratings, difficulty bands, and regraded scores on the website

**Status**: Planned
**Target**: v0.26.0
**Priority**: P2 (the new data is the point — without a display it stays in tools/ output)
**Estimated**: 2–3 days (schema + pipeline 1d; React components 1–2d)
**Dependencies**: [M-EVAL-OUTPUT-NORMALIZE](m-eval-output-normalization.md) (regraded scores — landed), [M-EVAL-RATING-EFFICIENCY](v0_24_0/m-eval-rating-efficiency.md) (ELO — `tools/eval-elo` part 1 landed; part 2 persists ratings), [M-EVAL-FRONTIER-TIER](m-eval-frontier-tier.md) (the tier the difficulty view will graduate into).

## Problem statement

Three things changed under the hood that the website does not yet show:
1. **Regraded scores** (M-EVAL-OUTPUT-NORMALIZE) — the public Model Leaderboard still renders raw pass rates, which were artifact-depressed on Python (field Python 85.5% → **92.1%** after re-grade; AILANG ~93%, essentially even). The site currently tells a wrong AILANG-vs-Python story.
2. **ELO difficulty** (`tools/eval-elo`) — benchmarks now have a *derived* difficulty (Trivial→Very-hard bands) instead of the hand-assigned `tier`. Nothing displays it.
3. **Model capability ELO** — a single-number ranking that works across models tested on *different* benchmark subsets (e.g. fable **2154** › gpt5-5 2101 › gemini-3-1-pro 2010). The current leaderboard can only compare models on the *same* set.

The displays also can't express the curation story this analysis produced: which benchmarks are **saturated** (demotion candidates), which are **grader-artifact-hard** (`contract_sorted_merge`, `decision_block_capture` — should be fixed, not celebrated as hard), and where the genuine frontier is.

## Current state (inventory)

Data: `docs/static/benchmarks/latest.json` — keys `aggregates, tiers, tags, models, agentModels, benchmarks, languages, executors, harnesses, history, events, sweet_spot_global`. Generated by `update_dashboard.sh` → `ailang eval-report`.

Components (`docs/src/components/`): `LanguageLeaderboard`, `BenchmarkExplorer`, `BenchmarkDashboard/{ModelChart,SpeedRadar,QualityScatter}`, `BenchmarkOverview`, `ValueDashboard`, `HarnessComparisonTable`, `DimensionSelector`, `BenchmarkMini`. Pages: `docs/docs/benchmarks/{explorer,value,gallery,performance}.md`, `reference/os-model-leaderboard`.

The components are healthy; this is an **additive** redesign (new fields + 2 new views + relabel one), not a rewrite.

## Design

### 1. Schema additions to `latest.json` (the unblocker)

Per-benchmark object gains:
```
elo:       1764,            // derived difficulty (tools/eval-elo)
eloBand:   "Hard",          // Trivial|Easy|Moderate|Hard|VeryHard
saturated: false,           // ≥95% across all 4 std/agent×lang dims (demotion candidate)
graderFlag: null            // e.g. "set-repr" | "free-text-exact-match" — artifact-hard, not real
```
Per-model object gains:
```
elo:        2154,           // capability rating
eloRank:    1,
scoreRegraded: { ailang: 97.3, python: 94.6 }   // post M-EVAL-OUTPUT-NORMALIZE
```
Top-level gains a `grading: { version, regradedAt }` stamp so the page can label numbers as regraded.

### 2. New / changed displays

- **ELO Model Leaderboard** (new, primary): single-axis capability ranking with confidence band, replacing pass-rate as the headline ordering (pass-rate kept as a column). Works across partial benchmark coverage — the payoff of the rating system.
- **Difficulty-banded Benchmark Explorer** (augment existing): color/sort by `eloBand` instead of (or alongside) hand `tier`; show pass-rate as a secondary signal. Saturated benchmarks visually de-emphasized; `graderFlag` benchmarks badged "measurement artifact — fix pending" so nobody reads them as genuine difficulty.
- **Curation panel** (new, small): "N benchmarks saturated (demotion candidates) · M grader-flagged · frontier tier: K benchmarks" — the rig's self-assessment, straight from the data.
- **AILANG-vs-Python**: switch the comparison to **regraded** scores with a footnote linking M-EVAL-OUTPUT-NORMALIZE; show the corrected ~even gap, not the artifact gap.

### 3. Data pipeline

`tools/eval-elo` must emit JSON (not just the table) so `update_dashboard.sh`/`eval-report` can merge `elo`/`eloBand`/model-elo into `latest.json`. Couples to **M-EVAL-RATING-EFFICIENCY part 2** (ratings persistence): the dashboard reads persisted ratings rather than recomputing. Saturation + graderFlag come from the curation audit (`audit_saturation.sh` + the M-EVAL-OUTPUT-NORMALIZE re-grade leftovers).

## Non-goals
- No visual framework change (stay in the existing Docusaurus/React component set).
- Not a history rewrite — `history` keeps raw past versions; the regraded stamp marks v0.25.0+ as regraded.
- Speed/cost views (`SpeedRadar`, `QualityScatter`) unchanged.

## Phasing
1. **Schema + pipeline**: emit ELO/regrade/saturation into `latest.json` (depends on ELO part 2). Regenerate v0.25.0.
2. **ELO leaderboard + difficulty bands** (the two headline views).
3. **Curation panel + grader-artifact badging + regraded AILANG-vs-Python relabel.**
