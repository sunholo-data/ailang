**Answer to the reporter's question first: yes, the mechanism is tracked — `design_docs/planned/m-package-test-discovery.md` (Planned, Target v0.38.x, P1, est. 2 days, sourced from issue #959) — but it is roughly nowhere in the queue: it has NO charter queue row in `design_docs/v1-mission.md` and no backlog row, and it has slipped v0.38.x → v0.40 (cited as a dependency by `m-pkg-quality-ladder` and by the shipped `m-pkg-bin-entrypoints` doc as "test discovery, not entrypoints") → still unlanded at v0.41.0. A doc that exists but nothing pulls is the same operational state as untracked, which is why World measured the gap live.**

The reason this report is not a duplicate-of `m-package-test-discovery.md`: that doc rules on `ailang test --package` discovery, not on what `pkg quality` prints when discovery is absent — and the interim the ladder sprint plan ruled ("report `files` only and say so in `notes`", `implemented/v0_40_0/m-pkg-quality-ladder-sprint-plan.md`) DID land and already says the true thing in the low-precedence field: `cmd/ailang/pkg_quality.go:192` (`runAttestedChecks`) sets `tests.Notes = "no *_test.ail files; inline test blocks are not yet discovered in package mode (m-package-test-discovery)"`. The false negative lives in the finding text itself: `internal/pkg/quality.go:331` (`QualityReport`, PUB012 switch) still prints "no tests discovered (*_test.ail or inline test blocks)" — claiming a search of inline blocks that never ran — and `quality.go:231` (`hard := StabilityGates(...) || strict`) turns exactly that finding into a gate under `--strict`, so the reporter's fear is measured in code, not hypothetical: strict adopters with healthy inline-only suites are blocked by a discovery gap wearing an absence badge. The neighbouring PUB011/PUB001/PUB002 comparisons are consistent: those reflect real searches.

The interim ask — PUB012 distinguishing "no tests found by either mechanism" from "no *_test.ail files; inline blocks not yet discoverable (m-package-test-discovery)" — is a design-doc, not a direct fix, for three rubric reasons: (row 3, the decisive one) the *level* of the interim variant under `--strict` is a genuine decision someone could disagree with — demote to `info` so discovery gaps never gate-block (World's ask), at the cost of weakening the no-tests signal for packages that genuinely have none; (row 4) PUB0xx message text is part of the report's public contract consumed by `--json` and the registry table (`m-pkg-quality-ladder` PUB table); (row 5/6) the change spans `internal/pkg/quality.go` + `cmd/ailang/pkg_quality.go` plus tests, over the 1-file/2-line direct-fix caps. The underlying union-discovery fix itself remains `m-package-test-discovery.md` and needs its queue row either way — this report's most useful output is that observation: the doc is tracked but unlanded and unpulled across three releases.
