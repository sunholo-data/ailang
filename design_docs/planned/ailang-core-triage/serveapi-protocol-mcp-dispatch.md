# ailang#885 — serveapi/protocol has no SDK-free MCP JSON-RPC dispatch (World 1.0 blocker)

- **Date**: 2026-09-26
- **Class**: feature
- **Recommend**: design-doc
- **Searched**: `grep -ril "MCP" design_docs/`, `grep -rn "885" design_docs/`, `grep -rln "JSON-RPC" design_docs/`, `grep -rn "dispatch" serveapi/ design_docs/planned/`; found `design_docs/planned/m-serveapi-protocol-only-module.md` (+ its sprint plan), `design_docs/v1-mission.md:1011` (the [NEXT] cross-mission row for this same issue).
- **Estimate**: omitted — recommendation is `design-doc` (rubric rows 3 and 4 both fire)

The mechanism is confirmed in this worktree: `serveapi/protocol/` (4 non-test files: `a2a_wire.go`, `envelope.go`, `descriptor.go`, `interfaces.go`) carries A2A JSON-RPC wire types/writers and MCP *envelope* helpers (`WriteMCPEnvelope`, `RequestID`, `CallbackMessage`, `AuthorizationStatus` — see `descriptor.go` for `ValidateMCPName`) but has **no method dispatch**; the only MCP dispatch in the repo is `serveapi/mcp_handler.go` (`embeddedMCPHandler`/`serverForRequest`), which imports `github.com/modelcontextprotocol/go-sdk/mcp` — the SDK subtree measured (per the report and `v1-mission.md:1011`) at 34 packages across 5 module roots, 28 disallowed by World's `TestDaemonDependencyAllowlist`, which is exactly why World's zero-cloud consumer cannot use it. The SDK-free existence proof lives next door: `serveapi/a2a_handler.go` implements the same seam for A2A in ~180 lines, stdlib + protocol only. **This is a design-doc, not a direct fix, for three reasons.** (1) Rubric row 3 — at least three acceptable dispatch surfaces exist and the ask explicitly invites a counter-proposal: (a) a protocol-level JSON-RPC method table (initialize / tools/list / tools/call) mirroring the A2A seam with the handler in `serveapi`; (b) a fuller SDK-free streamable-HTTP subset inside `protocol`; (c) keeping the SDK path behind a build tag or leaving `serveapi` on the SDK and giving World only the protocol seam. Which of these is chosen decides World's dependency closure for clause 6 and row 108. (2) Rubric row 4 — `serveapi/protocol` is a published public surface, and the change contradicts a **ratified Non-Goal**: `m-serveapi-protocol-only-module.md` §Non-Goals explicitly de-scoped stdlib-only MCP machinery as "a large, drift-prone project with no downstream demand" — that premise is now falsified by #885's demand evidence, and a doc must dispose of the objection rather than silently overturn a quorum-ratified scope (the same doc's quorum record already blocked once for a minimal-frozen-core violation). (3) The scheduling ask ("schedule it, or reply with an ETA") is a queue decision that `v1-mission.md:1011` already ranks `[NEXT]` — the design doc is the concrete deliverable that unblocks it.

**Verification notes (honest caveats):** the report's "all five blobs byte-identical at v0.33.2 and v0.42.0" and the closed-2026-09-13/reopened-2026-09-25 timeline could **not** be independently re-verified from this machine — this clone is shallow (depth 1, `git tag` count 0), so the tag-level diff is not runnable here; the local `git log -- serveapi/protocol` shows a single commit (`76d4d5a3`, PR #1312) and the package's file set (4 non-test files, 5 with tests) is consistent with "no dispatch has shipped". What *was* re-verified locally: the protocol package genuinely lacks dispatch (`grep -n "Dispatch" serveapi/protocol/*.go` → 0 hits outside A2A wire writers), `mcp_handler.go` genuinely imports the SDK, and `a2a_handler.go` imports neither the SDK nor `internal/apiserver`.

**Routing:** `design-doc-creator` (the surface decision in (1) is exactly what needs a quorum, since it reopens a ratified Non-Goal), then sprint-planner. Rows 106/107 are confirmed routable per the report; this is the sole external blocker, matching the `v1-mission.md` ranking.
