# Ordinary pi agent evals should not depend on rig-installed skills/templates (lean baseline boundary)

- **Date**: 2026-11-06
- **Class**: question
- **Recommend**: design-doc
- **Searched**: `tool profile`, `lean`, `no-skills`, `pi agent`, `elo`, `baseline boundary` in design_docs/ and docs/docs/; `MinimalHarnessContext` and `ToolProfileLean` in internal/
- **Estimate**: n/a (design-doc)

The mechanism already exists but is scoped to the fine-tune lane: `--tool-policy lean` sets `MinimalHarnessContext` only when the profile is lean (`internal/eval_harness/agent_task.go`, `task.MinimalHarnessContext = config.ToolPolicy == executor.ToolProfileLean`), which is what makes `internal/executor/pi/args.go` append `--no-skills --no-prompt-templates` and the fixed `LeanSystemPrompt` — so an ordinary agent eval run without `--tool-policy` still pays the measured 7,338-token ambient prefix, including the 3,625-token skills catalog discovered from whatever happens to be installed on the machine. Existing decision D-FT-9 (`docs/docs/finetuning/decisions.md:30`) explicitly scopes the lean profile to the fine-tune lane ("The fine-tune lane runs on a lean pi profile"), and D-FT-6 (line 27, fix `5dc3ba42b`) is the precedent for declaring a harness-change baseline boundary; nothing rules on the default eval lane, so this is a genuine gap (search terms above; no doc found). It should not be a direct fix because the decision is a benchmark-policy choice with at least three defensible answers — (a) make lean (or at least `--no-skills`) the default for all agent evals, (b) keep the default but pin and record ambient-context composition per run so results are comparable with disclosure, (c) drop discovery only while keeping pi's default system prompt — and any of them re-draws comparability against the ~9.6k historical agent runs already in `eval_results/`, exactly the kind of baseline-boundary call D-FT-6 made for the session gate. Design doc should pick the lane default, define the boundary annotation for pre-change results, and reconcile with D-FT-9's lane scoping.
