# Teaching prompt v0.16.11 teaches six mistakes (semicolons, `**`, mapSlicesJoin, verifyWithKid, record patterns, `{`-after-`let`)

- **Date**: 2026-11-06
- **Class**: bug (wrong teaching content in the active prompt; items 1–2 additionally carry a decision)
- **Recommend**: design-doc
- **Searched**: `M-FMT-DIALECT-ALIGNMENT` (design_docs/implemented/v0_32_0/), `mapSlicesJoin`, `verifyWithKid` across design_docs/, prompts/, docs/, std/; `ls design_docs/planned/ailang-core-triage/`
- **Source**: coordinator task task-c06dd4e2, reported from a session writing 63 canonical examples (`examples/runnable/stdlib/`, commit f06cb6e84 — **not present in this worktree at HEAD d9a6e665**, so the examples themselves are not reviewable here; every claim below was re-verified independently against the v0.57.4 binary and HEAD sources).

Every one of the six claims was re-verified against the toolchain before triage; none is stale or speculative:

1. **Semicolons vs fmt — confirmed, and it is the M-FMT-DIALECT-ALIGNMENT failure class again.** `prompts/v0.16.11.md` teaches `let x = a; let y = b; finalExpr` (line 21, "Block body … semicolons between lets"), "Inside `{ }` blocks, use SEMICOLONS" (line 236) and "See `{` -> use `;`" (line 260). `ailang fmt` strips every sequence semicolon and emits newline-separated statements (verified live; matches docs/docs/reference/formatter.md "Canonical form": "no sequence semicolons"). Newline-separated blocks type-check fine, so the corpus split is stylistic, not a correctness bug — which is exactly the shape the v0.32_0 dialect-alignment doc measured as +62% output tokens / p=0.0112 when fmt contradicts the prompt on every write. That doc's divergence inventory did **not** cover the semicolon rule; it is unfixed residual. Picking a direction is a real decision (see below).
2. **`**` in the operators table — confirmed dead.** `prompts/v0.16.11.md:1221` lists `**` under Arithmetic; no `**` token exists in `internal/lexer`/`internal/parser`/`internal/eval` (grep clean), and `2 ** 10` fails with `PAR_NO_PREFIX_PARSE at :3:19: unexpected token in expression: *` (verified live). Power is `std/math.pow` (float-only). Either remove one table cell or implement an operator — the latter is a language-semantics change.
3. **mapSlicesJoin example wrong — confirmed.** `prompts/v0.16.11.md:1156-1159` shows `mapSlicesJoin(csv, ",", \field. toUpper(field))` captioned "Uppercase each CSV field". `std/string.ail` (the `mapSlicesJoin` docstring, ~line 195) states it is equivalent to `join("", map(f, split(s, delim)))` — the output is joined with **no separator** ("a,b,c" → "ABC"), so the example silently produces a concatenated blob, not CSV. The `delim` argument is the *input* split delimiter only. One-line comment fix, but it must land in all mirror surfaces (below).
4. **verifyWithKid signature wrong — confirmed, and worse than reported.** `prompts/v0.16.11.md:2092` shows `verifyWithKid(token, \kid. lookupKey(kid, jwks))`; the real signature (`std/jwt.ail`, `verifyWithKid`) is `verifyWithKid(token: string, keys: Json) -> Result[Json, string]` where `keys` is a JObject mapping kid → PEM string — no callback. Additionally the snippet's `Ok({header, payload, signature})` destructuring of `decodeJWT` **fails type check**: `decodeJWT` returns a 4-field record `{header, payload, signature, signed}` and the pattern is rejected with "record field mismatch: expected 4 fields, got 3" (verified live). The JWT snippet needs a rewrite plus `ailang check` verification before landing, per the prompt-version discipline recorded in prompts/versions.json.
5. **Nested record pattern on declared types — confirmed.** `{user: {email: e}}` type-checks on an anonymous record but fails on a declared record type with "record field mismatch: expected 2 fields, got 1" (verified live); `{user: {email: e, ...}}` with the rest pattern works. `prompts/v0.16.11.md:1398/1402-1406` presents the nested pattern without the declared-type caveat. One line + example tweak.
6. **`{`-starting final expression after a bare `let` — confirmed as a real parser trap.** In a semicolon-free block, `let x = 1` followed by a final record-update expression `{ x | y: 2 }` fails with `PAR_UNEXPECTED_TOKEN at :4:3: expected next token to be }, got { instead`; writing `let x = 1;` disambiguates and fmt preserves that final semicolon (verified live). Worth one trap line next to the existing `= {` trap (line 23), and it interacts with item 1: it is the reason the semicolon rule was probably taught.

**Why design-doc, not direct-fix:** three of the six items are decisions, not edits — (1) semicolons-vs-newlines must be picked with the item-6 parser trap in mind (newlines are fmt-canonical but reintroduce the `{`-ambiguity unless the trap rule is added), (2) `**` is implement-or-remove, and (4) requires choosing and verifying a replacement JWT snippet. The full fix also spans more than one file by construction: the active head `prompts/v0.16.11.md` plus its mandated mirrors — `docs/docs/prompts/v0.16.11.md` (currently byte-identical, md5 14ddaed1…), `docs/docs/prompts/current.md`, the three `llms.txt` bundles, and the binary-embedded copy — per the precedent recorded in prompts/versions.json (M-DATETIME-UNITS-DOC et al.). Under the rubric this is rows 3 and 5.

**Cross-reference:** `design_docs/implemented/v0_32_0/m-fmt-dialect-alignment.md` is the same failure class (prompt teaching a dialect fmt contradicts) and supplies the measurement methodology and the "verify every snippet with `ailang check`/`run` before it lands" discipline this doc should inherit — but it rules on none of these six items, so this is not a duplicate. Note also the fine-tune angle from the report: the prompt is now fine-tune training context (`prompts/ft-*`, m-eval-finetuning-data-pipeline), so wrong teaching text propagates into training data, not just eval sessions — worth one section in the design doc on whether ft corpus regeneration is needed after the fix.

**Suggested shape:** one design doc under `design_docs/planned/` cut against the unfrozen v0.16.11 head (amend-in-place precedent, since no eval baseline pins it) covering all six items with per-item verification evidence, the semicolon decision made explicitly, a verified JWT/mapSlicesJoin replacement snippet each, and the mirror-sync + hash-update checklist from versions.json.
