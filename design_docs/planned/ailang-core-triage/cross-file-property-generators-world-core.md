## The verdict

The report asks two questions and asserts two gaps. Measured first-party on the **exact v0.41.0 binary** the reporter used, both assertions need correcting before this becomes work:

**1. "Is M4 tracked?" — No, because M4 is not outstanding.** Lane B1 milestone M4 (ADT derivation, recursion/size budgets, `TypeApp` substitution) **landed 2026-08-11 (iter-176), PR #653 → squash `03ab3e7de`** (`design_docs/v1-mission.md:3191`), with same-file ADT coverage pinned in `internal/testing/derive_adt_test.go` (`TestM4B1_6_ADTConstructorCoverage`, `TestM4_TypeAppSubstitution`, …). Verified live on v0.41.0: `ailang test examples/runnable/contracts/shapes_verify.ail` derives the same-file ADT `Shade` and runs `level_property_1` **100/100, 0 skips**. The reporter's premise rests on a **stale comment in the code, not missing code**: `deriveType`'s doc comment (`internal/testing/derive.go:73-75`) and two more stale sites (`:264-267`, `:281-282`) still say "AlgebraicType (ADTs) … intentionally M4 and fall through to nil, nil until then" — written before M4 and never refreshed when M4 wired `deriveAlgebraicType` (`derive.go:286`) directly into `deriveTypeDef` (`:278-279`). **That stale comment is the one genuinely new actionable artifact in this report** — it misdirected a real user's triage, and refreshing it is a few comment-only lines in one file that should ride along with whatever doc covers cross-module resolution (it exceeds the 2-line direct-fix threshold only by being comments; no semantics decision involved).

**2. "Are the two gaps separable?" — There is one gap, not two.** All four world/core skips share a single root cause: `findTypeDecl` (`internal/testing/derive.go`) resolves named types **only from `r.executor.sourceFile.Decls`** — the file under test — and `ailang test` feeds it exactly one file (`cmd/ailang/test.go` parses per-file and calls `SetSourceFile` once, `internal/testing/runner.go:597`; no sibling-module ASTs reach the runner). `World` (record) and `Evidence` (ADT) are both declared in `world/types.ail`, so *neither* resolves, and the ADT arm is unreachable for `Evidence` for the same reason the record arm is unreachable for `World` — the declaration is never found, so which derivation arm the declaration would take is moot. Re-verified live: on `cross_module_types.ail`, both the cross-file record `Cell` and the cross-file ADT `Tree` skip with `no generator for parameter …`, while the same-file ADT derives — reproducing the reporter's 4-skip shape with the one-mechanism explanation.

**The cross-file bound itself is a recorded design decision, not an unnoticed bug.** `m-property-generator-coverage.md` states it twice (design-decision table: *"imported/cross-module named types stay vacuous-skip in v1 (honest, loud)… a typechecker-env approach is strictly better but ~2× the work — wrong trade for P2"*, and Lane B scope: *"Refined types and imported types remain B2/out-of-scope"*), and its Future Work names the path (*"Typechecker-env-based type resolution (unlocks imported types) — supersedes the same-file bound"*). The B1 closeout already measured the residue as exactly this class: vacuous skips 111 → 24, all remaining ones imported + refined types (F-1 confirmed in the field — B1 deliberately does NOT fix imported-type packages). A sibling triage of the same subject (`imported-type-generator-skips-json.md`, 2026-09-15, std/json `Json`) already concluded duplicate-of this doc, with the sanctioned remedy being **Lane B2 (user-supplied/registered generators), deferred and BLOCKED ON a deterministic evaluator fuel/step budget** (quorum 2026-07-29) — and a small design doc suggested for either part-delivering B2 or adding a distinct `skip_kind` so structural skips don't poison `ailang test` package suites.

## What is new here, and worth banking

1. **The evidence, not the mechanism**: a published package (`world/core@0.1.0`) carrying 4 properties that have *never* run, with a pinned gate asserting them by name. That is the strongest demand signal yet for the already-named follow-up, and stronger than the std/json row's numbers.
2. **A narrower framing than B2**: the reporter's package is *same-package cross-file* — `ailang test world/` loads every module of the package, so the `TypeDecl` ASTs for `World`/`Evidence` are plausibly reachable without the fuel-budgeted *evaluation* that B2's deferral guards (B2's blocker is about executing user generators; structural derivation of a sibling module's decl needs only source access the loader already has). The design doc's own "~2×" price was for the typechecker-env approach; a package-scoped decl lookup may be cheaper. That is a genuine design question — one of several acceptable architectures (per-import surface-AST lookup vs typechecker env vs B2 registration), plus a wrinkle the doc does not carry: cross-file ADT derivation must source `deriveAlgebraicType`'s `modulePath` from the **declaration's** module, not the test module, or generated `TaggedValue`s lose their identity in the harness.
