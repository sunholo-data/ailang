# std/ai single-shot calls carry no HTTP deadline; named-test round-trip breaks on integral float literals (and brace-bearing strings, via the stripper)

- **Date**: 2026-09-18
- **Class**: bug
- **Recommend**: design-doc
- **Searched**: `timeout`, `deadline`, `std/ai`, `ai-timeout` in `design_docs/planned/ailang-core-backlog.md` (no row exists — see below); `PrintAILANGSource`, `named-test`, `named test` in `design_docs/`; prior triage rows `ailang-core-triage/named-test-float-dict-resolution.md` and `ailang-core-triage/source-strip-string-brace-skip-ranges.md`
- **Estimate**: omitted (design-doc)

**Defect 1 — verified in code, and the backlog filing it references does not exist.** `internal/ai/httpjson.go` (`DoJSON`: `client == nil` → `http.DefaultClient`) and `internal/ai/openrouter/client.go` (`NewClient`: `httpClient: http.DefaultClient`) fall back to Go's zero-timeout default client; grepping `Timeout|Deadline|WithTimeout` across `internal/effects/ai*.go`, `internal/builtins/ai*.go`, and `internal/ai/handler.go` finds only doc strings and test error-code names, exactly as the report claims. Every oracle except this one is bounded (`std/net` enforces `ctx.Net.Timeout`, 30 s default, `--net-timeout`; even the Ollama path has its own budgets in `internal/config/ollama.go`). Notably, `m-ai-decide-system-one.md` Future Work (":417", the AILANG-fix backlog bullet) states this gap was "filed to the AILANG-fix backlog", but `ailang-core-backlog.md` contains no such row — this report is the filing that never landed, so it should be tracked from here. A design doc (not a direct fix) is warranted because the change is a public surface (`--ai-timeout` flag + new `ctx.AI.Timeout` config area) spanning `internal/config`, `internal/effects` context plumbing, both client construction sites, and `cmd/ailang/main_run.go`/help, with several genuinely open choices: the default value (mirror Net's 30 s? LLM calls routinely exceed 30 s in streaming mode — the report's own shadow runs hit 3 timeouts at 30 s), env-var spelling, and how it interacts with the Ollama-specific timeout config that already exists.

**Defect 2 splits in two, and the report's mechanism is right for one half and wrong for the other.** (a) The `PAR_NO_PREFIX_PARSE "unexpected }"` from strings like `"a{b"` inside a test body is **not** a printer bug — `PrintAILANGSource` (`internal/testing/executor_helpers.go`, `*ast.Literal`/StringLit case) correctly re-escapes `\`, `"`, `\n`, `\t`, `\r`. It is the string-blind brace scan in `testAndPropertySkipRanges` (`internal/testing/source_strip.go`) leaking body lines plus a stray `}` into the stripped base for *every* test in the module — I reproduced this exactly (a trivial first test fails with `unexpected }` at the generated file solely because a later sibling contains `"a{b"`), and it is already triaged: **duplicate-of `design_docs/planned/ailang-core-triage/source-strip-string-brace-skip-ranges.md`** for that half. (b) The integral-float half **is** the printer, verified by repro: `one() == 1.0` (with `export pure func one() -> float = 1.0`) evaluates `true` under `ailang run` but fails in `ailang test` with "expected float arguments" / "expected int arguments", because `PrintAILANGSource` delegates floats to `Literal.String()` → `fmt.Sprintf("%v", float64(1.0))` = `"1"`, which re-parses as an int literal — the printer comment's claim that "float has correct String()" is false. This refines the mechanism hypothesis in `ailang-core-triage/named-test-float-dict-resolution.md` (which guessed elaboration dictionary divergence): the design doc for the float family should start from printer float formatting, not elaboration. Either way the report's severity judgement stands — a test body that round-trips into a type/eval error (or a silently-false comparison) is the worst failure mode, and "hoist every literal into a `pure` top-level helper" is a workaround, not a fix (note the helper must be *explicitly* `pure` or `! {}`, or `stripNonPureFunctions` deletes it from the base and the test fails with "undefined variable" — also reproduced).
