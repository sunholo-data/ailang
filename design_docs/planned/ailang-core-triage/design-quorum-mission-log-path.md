The design-doc-creator skill's quorum step (SKILL.md, the "Run design-quorum" block at lines 359–374 — the report said "~393"; the `--mission-log design_docs/v1-mission-log.md` invocation is at line 364) hard-codes the **ailang** repo's log path into a skill that also runs, verbatim, inside other repos. When `design-doc-creator-daneel` runs against sunholo-data/daneel, it commits the quorum's human log to `design_docs/v1-mission-log.md` there, and daneel's proven `tools/ci_gate.ail` predicate — which reads every `design_docs/**/*.md` as a design document and requires a `# Design:` first line — rejects it (first line is `#### Design-quorum review …`); measured on daneel PR #61 (M-DANEEL-SOUL), guard FAILURE, run 35186177655. Worse, daneel's agent config sets `artifact_patterns: design_docs/**/*.md` with `auto_merge: true`, so had the check passed the log would have auto-merged into the agent's entire safety scope unreviewed. The machine artifact under `.ailang/state/mission-quorum/` already persists the quorum result, so the fix is about the *optional human log's destination*, and the report offers two acceptable remedies — drop `--mission-log` for non-ailang repos, or a per-agent `mission_log:` setting in config.cloud.yaml that the skill reads, defaulting to `design_docs/v1-mission-log.md` for ailang — which is exactly the row-3 "someone could disagree with this" case. A design doc should also rule on the second-order smell the report documents: daneel's soul doc learned to write `**Status**: Planned` *and* `Status:` both to satisfy the two gates ("bold metadata repeated for the house format"), and while daneel has since fixed its gate to accept both forms (`isStatusLine`, daneel PR #64), the pattern of one repo carving exceptions for another repo's conventions is what should be decided once, centrally, in the skill's contract.
