# Chains: no PR linkage, no PR-driven status, no title; attended sessions never become chains; interspersed --remote silently dropped

- **Date**: 2026-09-29
- **Class**: feature (asks a, b, c, e) + bug (interspersed flags)
- **Recommend**: design-doc
- **Searched**: `grep -ril chain design_docs/`, `grep -ril observatory design_docs/`, `grep -rli "pull_request|pull request|pr_url" design_docs/`, `ls design_docs/planned/ailang-core-triage/`, `grep -rli "remote|flag" design_docs/planned/ailang-core-triage/` — no existing doc rules on PR linkage, chain titles, or interspersed flag parsing. Closest is `design_docs/planned/m-feature-provenance-chains.md` (see below).
- **Estimate**: n/a (design-doc; see per-item estimates below)

**Verified against the code.** `ExecutionChain` (`internal/observatory/models_chains.go`) carries `GitHubRepo` + `GitHubIssueNumber` only — no PR number/URL on the chain or `ChainStage`, and no title/summary field anywhere; `internal/observatory/schema_chains.sql` (`execution_chains`, `chain_stages`) confirms no columns for either. Chain status is written by the completion path only (see `ChainStatusAbandoned` comment in `models_chains.go` and `chain_reconcile.go` `FindStrandedChains`/`AbandonChain`); nothing consults a PR. Attended-session capture not landing in `execution_chains` is exactly the measured failure table in `design_docs/planned/m-feature-provenance-chains.md` ("Interactive sessions → sessions/tools: captured by hooks, 2 tool rows since April") — that doc's fix (`8131b4101`) repaired session→chain *correlation* columns on `sessions`, but sessions still never become chains in their own right, so Daneel's ask (a) is only partially covered by that doc. The flag bug is real and larger than reported: `fs.Parse(flag.Args()[2:])` with Go stdlib `flag` (which stops at the first positional arg) appears in **13 files** under `cmd/ailang/` — `chains.go` (view/tree/journey), `chains_chat.go`, `chains_diagnostics.go` (×2), `chains_diff.go`, `chains_find.go`, `chains_import.go`, `chains_live.go`, `chains_post.go`, `chains_stats.go`, `chains_tree.go`, `eval_chains.go`, `eval_saturation.go`, `eval_trend.go` — every one silently drops `--remote`/other flags placed after the positional argument, which is a direct violation of the no-silent-fallbacks principle (CLAUDE.md §2).

**Why design-doc, not direct-fix.** Each ask independently clears the rubric, and together they are one schema + semantics decision:

- **(b) PR on chain/stages** — new public surface: a Firestore schema change (`execution_chains` + optionally `chain_stages`), a backfill question for 599 existing 30d chains, and at least two defensible designs (single `github_pr_number`/`github_pr_url` on the chain vs. a link table allowing multiple PRs per chain, since one chain may spawn retries/stacked PRs). Row 3 + row 4.
- **(c) status follows PR** — a semantics change with multiple acceptable mechanisms (poll GitHub on read vs. webhook/gh-event ingestion vs. reconcile sweep extending `chain_reconcile.go`), and a real collision with the existing status vocabulary: what happens to `abandoned` (deliberately *not* an outcome, per its own comment) when a PR later merges? Row 3.
- **(e) title** — small column, but the source is a decision: first message body truncated? task prompt? human-supplied? Whoever picks wrong gets a list of titles that are again unreadable. Row 3.
- **(a) attended sessions as chains** — the hook currently POSTs to `sessions`/`session_tools` via `scripts/hooks/coordinator_hook.sh`; promoting sessions to chains changes what `chains list` shows (flooding it with interactive sessions unless source_type `manual`/new `attended_session` is filtered) and touches capture topology (local-only today; Firestore obs_sessions=0). Row 3 + row 4.
- **Bug: interspersed flags** — spans 13 files; even the mechanical fix (manual re-parse or two-pass parse (`flag.ErrHelp`-style interspersed acceptance)) exceeds 2 lines × 1 file, and the remedy is a decision (error on post-positional flags vs. accept interspersed everywhere) that sets a CLI-wide convention also affecting `chat`/`diagnose`/`diff`/`eval-*`. The codebase already contains the mechanical remedy — `normalizeArgsForFlags` in `cmd/ailang/messages_send.go` (used by `messages send`) moves trailing flags before positional args — so the fix is proven but systematic, not 2 lines in 1 file. Row 5.

**Recommendation.** One design doc covering the chain-model enrichment — title, PR linkage, PR-derived status, and attended-session capture as a chain source — with the interspersed-flag parsing convention either folded in (it gates every `--remote` read surface the doc touches) or split as its own small doc. It should build on, and cross-reference, `design_docs/planned/m-feature-provenance-chains.md` rather than replace it: that doc owns the "every link fails silently" diagnosis and the session-correlation substrate this report extends. Note (b)+(c) directly serve Daneel's routing use case and the doc should treat "35 completed / 170 abandoned of 500" as the baseline to beat.
