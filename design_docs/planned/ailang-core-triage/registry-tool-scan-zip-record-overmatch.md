# Registry tool-name scan over-matches std/zip `{ name, content }` records (sunholo/specstore publish rejected) — and check is server-side only

- **Date**: 2026-10-29
- **Class**: bug
- **Recommend**: design-doc
- **Searched**: `tool_name|validateToolNames` across `internal/` `cmd/`; `provided_tools|on_describe_tools` in `design_docs/`; `M-EXT-AUTHOR-DX`; prior triage `registry-validator-tool-name-overmatch.md` and `ailang-core-backlog.md` (see below)
- **Estimate**: omitted (design-doc)

The gate is `cmd/registry-validator/tool_names.go` (`validateToolNames`, called from `handlePublish`, `cmd/registry-validator/main.go:243`). Pattern 2 (`nameFieldPattern = \bname\s*:\s*"([^"]+)"`) deliberately over-matches every `name: "X"` string literal in any `.ail` file — its own comment admits "it'll also catch `name:` fields from other record literals." The #1133 exemption only covers flat records with a `value` sibling, so `{ name: "[Content_Types].xml", content: "..." }` — the entry shape `std/zip` itself uses, i.e. every zip/OOXML/epub package — is caught, and `[Content_Types].xml`/`META-INF/...` fail `safeToolNamePattern`. The report's helper-built repro confirms the scan is purely syntactic. This is now the third recurrence of the same false-positive class (original over-match → #1133 header exemption → prior triage `registry-validator-tool-name-overmatch.md` 2026-09-15 → this report), exactly the exemption-patch treadmill that triage warned about. Verified: the scanner lives in the validator binary's `package main` only; `cmd/ailang/pkg_publish.go` and `cmd/ailang/pkg_quality.go` never run it, so `--dry-run`/`quality` passing while real publish fails is structural, not a bug in those commands. The report's three asks (scope to actual tool declarations; mirror the check in `publish --dry-run`/`pkg quality` with a PUB code; put offending file:line in the refusal) require moving/sharing the scanner into an importable package, wiring it into two CLI commands with a new PUB code, and tracking positions through the regex — a multi-file change that also re-scopes a gate whose contract exists to close the v0.18.1 Bedrock/Vertex incident class (naive narrowing risks false negatives). That trade-off is a decision worth a doc, not another exemption patch.

Note: same root cause already triaged as `design_docs/planned/ailang-core-triage/registry-validator-tool-name-overmatch.md` (2026-09-15) and in `design_docs/planned/ailang-core-backlog.md` (2026-09-15, design-doc). Those rows cover only the scoping ask; this row adds the dry-run parity, PUB code, and file:line asks, so a combined design doc should supersede both.
