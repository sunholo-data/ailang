## Problem and goals

The paired tickets `mission:rotate-log-registry-cwd` and `rotate-log:status-flag-mutates-and-world-resolves-to-status-archive` concern one command. Fleet's dated human queue reports 3 + 1 lost slots. The existing CLI can load a registry from an explicit absolute directory but rediscover the shared-repository log root from CWD, silently using Workdir if discovery fails in rotate-log (re-verified at HEAD, V2); `mission normalize` runs the same second CWD walk separately from its registry load — failing loudly rather than silently, but still able to resolve a different checkout than the loaded registry (re-verified at HEAD, V23). From a product checkout with no registry, legacy controller calls cannot locate the shared registry without explicit configuration (re-verified: the legacy controller branch of `tools/launchd/mission-control.sh` has no `AILANG_MISSION_REGISTRY` export at HEAD, V20). `--status` selects a STATUS archive and invokes the write path; it is not a report. Even an under-threshold rotation rewrites the index.

Success means one resolved registry determines shared-repo targets for both `rotate-log` and `normalize`, legacy controller children receive the pinned registry, the misleading `--status` spelling is rejected before any registry load or write with migration text pointing at `--stream status`, and archive mutation has an explicit name. Failures before mutation leave synthetic target files byte-identical.

## Solution design

1. Resolve registry paths once in `loadMissionRegistry` (cmd/ailang/mission_cmd.go:156–187 at HEAD, V1). Preserve explicit `AILANG_MISSION_REGISTRY` precedence and its absolute existing-directory validation (internal/config/mission.go:76–77; pinned by mission_registry_env_test.go). Preserve attended CWD/ancestor discovery when no override exists. On failure, name the attempted locations and explain the absolute override; do not guess `$HOME`, binary installation roots, `AILANG_DRIVER_SRC`, or another checkout. Preserve the loaded registry's absolute origin using its existing Mission.Path/root provenance (internal/mission/registry.go:79–84, 243–246; root is already absolute — LoadFile sets it to the PARENT of the registry directory, one level up from the registry dir that holds the TOML, V3/V24) rather than duplicating discovery; expose a small read-only root accessor if needed. The loader's return signature `func() (*mission.Registry, error)` must not change — hermetic tests inject exactly that type (mission_iteration_cmd_run_test.go:62,98, V18).
2. Export `AILANG_MISSION_REGISTRY="$MC_DRIVER_ROOT/missions"` for the legacy controller path before launching it, mirroring the binary iterate branch which already does this at tools/launchd/mission-control.sh:1976 (V6, V20). Validate the driver root is nonempty, absolute, and has a readable missions directory; unavailable root fails loudly. Do not use the lagging source clone. This export selects the driver registry for the controller session's child process tree; no daemon reload or installed config edit is required. The export works through EXISTING loader precedence (env override checked first, V1), so no caller-side code changes are needed.
3. In rotate-log AND normalize, sharedRepoSlug missions use the loaded registry's origin root — not a second CWD walk. The formula is stated explicitly so no implementer can misread it: the shared-repo target root is `m.root`, which is the PARENT of the registry directory — the repo root, NOT `<repo>/missions`. LoadFile computes it as `filepath.Abs(filepath.Join(filepath.Dir(path), ".."))` where `path` is the registry TOML (internal/mission/registry.go:245–246), so `<repo>/missions/<name>.toml` yields `<repo>`; the field comment says exactly this (:83–84, "root is the registry directory's repo, i.e. where the shared driver lives", V24). Load builds every entry through LoadFile (:256–277), so every loaded Mission carries this root. In rotate-log, the read-only accessor from point 1 replaces the silent-fallback walk `repoRootFor(missionRegistryDir)` at cmd/ailang/mission_cmd.go:357 (V2). In normalize — whose registry load at :425 already precedes its walk — the SAME accessor replaces its OWN second walk at :429–431 (round-3 objection 1, widened in round 4): shared missions' docs map to the loaded registry's repo instead of a CWD-resolved checkout, and the loud failure when no registry is discoverable is preserved (the :425 load errors first; an empty root provenance fails loudly rather than guessing a target root). External repositories, including World, use their registered Workdir in both verbs (missions/world.toml:10–11, V4). With BOTH call sites replaced (:357 in rotate-log, :429 in normalize), the unexported `repoRootFor` helper has no remaining caller and its definition is DELETED in the same change (cmd/ailang/mission_cmd.go:383–396, body proven in V23) — leaving it orphaned would redden the repo's `unused` linter gate in CI (round-4 objection 1). Keep the two target filenames explicit: `design_docs/<name>-mission-log.md` (default) and `design_docs/<name>-mission-status-archive.md` (`--stream status`). Banked synthetic evidence confirms default World already selects its log correctly; preserve that behavior rather than claiming a default-stream bug. Missing selected input fails; do not switch streams or repositories. Preserve existing archive/index naming (`-old.md`, index naming), structural-heading refusal, and RotateLog mechanics (internal/mission/rotate.go:174–255, V5).
4. Parse `--stream log|status` strictly inside the flag loop (cmd/ailang/mission_cmd.go:311–336 at HEAD), and reject `--status` there. ORDERING IS LOAD-BEARING AND RULED: the entire flag loop runs before the `loadMissionRegistry()` call at :338, which precedes the only mutation call `mission.RotateLog(logPath, keep)` at :368 (V2). Therefore a `--status` rejection returned from the flag loop fires BEFORE registry load and BEFORE any write. The rejection error is: `--status was a mutating STATUS-archive selector; use --stream status to rotate that archive` (exit nonzero). It fires for `--status` alone and for any combination including `--stream status` — no legacy alias, no warning-only deprecation (D-FLEET-9 = A). Also reject before the load: invalid or missing `--stream` values, repeated `--stream`, more than one positional name, unknown flags; retain positive `--keep` behavior (`--keep 0` remains refused by RotateLog itself, rotate_test.go:146, V5). Update printMissionHelp (cmd/ailang/mission_cmd.go:74–153; the `--status` line is :137, "--status rotates the STATUS-stamp archive instead") to declare writes, `--stream log|status`, and this migration.

## Compatibility and conflict surface

Default `rotate-log <name> --keep N` remains mutating log rotation. `--stream status` retains the old archive-rotation behavior, including `-old.md` and status index output. Old `--status` commands deliberately stop with a nonzero exit and migration guidance BEFORE registry load and any write — ruled by D-FLEET-9 = A; this is no longer a pending approval choice. Existing `--status` callers enumerated by a WHOLE-REPO search at HEAD, not a directory-scoped one (round-4 objection 2): `grep -rn -- "rotate-log.*--status" .` across all file types returns ZERO live callers — the only matches are the CLI's own usage string (mission_cmd.go:336) and documentation records of a past REFUSAL (`design_docs/motoko-mission-status-archive.md:961`, the D-FLEET-9 ruling text, fleet log records); no script, launchd driver, test, or Go code invokes `rotate-log --status`. Positive controls in the same breath (V26): the same pattern family matches `--status` flags of OTHER commands (`cmd/ailang/coordinator_list.go:46`, `cmd/ailang/chains.go:359`, `cmd/ailang/examples.go:582`, `cmd/ailang/dashboard.go:88`), and `grep -rln "rotate-log" tools/ scripts/ internal/ cmd/` returns `internal/mission/rotate.go` and `cmd/ailang/mission_cmd.go` — proving the searches reach the code directories. Both gate-4 skill resources call default rotation and need no behavioral edit (V7). External consumers get the migration error text, not a silent behavior change.

The shared registry loader keeps its signature, precedence, validation, and discovery for all callers — see the audit above. `normalize` compatibility: its loud no-registry failure is preserved while shared-repo doc targets move to the loaded registry's origin (C7); one deliberate delta — an env-override registry loaded from a foreign CWD errors loudly at mission_cmd.go:429–431 today and instead resolves correctly to the override's repo, matching the ruled one-resolved-registry principle. This design touches CLI/harness code, not compiler or language semantics. Concurrency/transactional rotation improvements are outside this paired ticket. The flag break was ruled immediate: no deprecation period, no opt-in mutation guard, no sunset schedule (D-FLEET-9 = A over B).
