## Summary

Prevent a confined program from forging the supervisor's admission or limit verdict through stderr or exit code 3. Preserve the existing host contract by marking reserved worker lines, keeping supervisor lines on fresh lines, reserving rc 3 for actual supervisor limits, and hardening the in-repo parser.

**Duration:** 2 days, 10 hours of implementation/verification plus 3 hours contingency (30%).
**Estimated total:** 430 authored LOC: 120 implementation, 280 tests, 30 documentation. Generated asset copies are excluded.
**Risk:** Medium: streaming byte preservation and line-boundary recognition need careful regression coverage.
**Scope:** Planning only. The coordinator's sprint-plan approval/merge precedes execution; the approved design is not approval of this newly authored sprint plan.

## Milestone 1: M1_SUPERVISOR_PROVENANCE

**Goal:** Only the supervisor can emit unprefixed contract lines and report supervisor limit rc 3.
**Estimate:** 95 implementation + 225 tests = **320 LOC**.
**Duration:** Day 1, 6h; use contingency if streaming tests expose missed boundaries.
**Dependencies:** None.

**Files:**
- Update `cmd/ailang/run_policy_supervise.go`: streaming stderr guard, the fresh-line `supervisorLine` helper and reserved-exit handling. Name the helper `supervisorLine`: the follow-on M-RUN-POLICY-WORKER-CACHE sprint (#1547) emits its warning through it.
- Update `cmd/ailang/run_policy_hardening_test.go`: integration fixtures and charter test.
- Create `cmd/ailang/run_policy_stderr_guard_test.go`: focused streaming state-machine tests (placement may be consolidated into the existing test file).
- Example coverage: runnable temporary `.ail` programs generated by the existing hardening test harness for forged admission/result, exit 3, real timeout and unterminated stderr. Reuse the design's examples in the guide; no standalone production example is required for this protocol fix. Obtain `ailang prompt` before authoring or editing any `.ail` fixture, and check fixtures before running them.

**Tasks:**
1. Write byte-preservation and prefix tests before implementing the guard. Cover stream start, repeated tokens, near misses, mid-line tokens, empty input, partial tokens at EOF and >32 KiB lines. Exercise every possible chunk split of each reserved token and multi-byte terminator.
2. Recognise line starts after LF, CR, VT, FF, U+001C/U+001D/U+001E, U+0085, U+2028 and U+2029. Preserve terminator bytes and partial multi-byte state; bound token hold-back to 14 bytes. Prefix complete `policy:` and `policy-result:` tokens with `worker: `, preserving all original bytes.
3. Wire only worker stderr through the guard. Keep the existing shared cap counter on bytes read from worker stdout/stderr; injected prefixes and supervisor lines do not consume worker output allowance. Flush held bytes when the copier ends, including cap cancellation/closed-pipe termination, before checking newline state.
4. After relay drain, route admission and all four existing result writes plus the new reserved-exit envelope through a helper that inserts LF unless the relayed stream ends in LF. Read guard state only after its goroutine completes.
5. Preserve verdict precedence: actual output cap or deadline returns 3 first; only otherwise remap worker exit 3 to 1 with reason `worker_reserved_exit` and a message naming original code 3. Keep all other worker exit behavior and fd-3 close-at-admission unchanged.
6. Add the forge-vs-genuine-timeout charter test and CR/U+2028/U+2029/unterminated variants. Pin forged admission isolation, ordinary stderr byte preservation, stdout preservation, and existing output-cap/descendant behavior.

**Acceptance criteria:**
- [x] Forged result + worker exit 3 yields rc 1, a supervisor `worker_reserved_exit` envelope, and visible `worker: policy-result:` output; genuine timeout yields rc 3 and unprefixed reason `timeout` in the same charter test.
- [x] Both reserved tokens are escaped after every listed terminator and across chunk boundaries, including Unicode sequences split over three writes; near misses and mid-line tokens pass unchanged.
- [x] EOF/cancellation flushes strict token prefixes without losing bytes; injected prefixes are excluded from cap accounting; memory is bounded independent of line length.
- [x] Unterminated worker stderr cannot swallow either supervisor contract line; supervisor lines appear after relay drain on fresh LF-delimited lines.
- [x] Existing timeout, output-cap, descendant-kill, entry-from-policy and stdout-spoof tests retain their current assertions and pass; denial/refusal and other exit codes retain their contract.
- [x] `cmd/ailang/run_policy.go` retains fd-3 lifetime and timeout backstop; no open control fd during program execution.

**Risk/mitigation:** A filter bug can corrupt arbitrary stderr or reopen forgery. Test exact bytes, all token/terminator split positions and long lines. A race in newline state would corrupt provenance; access it only after copier completion and run targeted race tests (when a C toolchain is available; otherwise record them as skipped).

- Example coverage: guide before/after transcripts for forged result, real timeout, legitimate reserved-token output and unterminated stderr, backed by M1 fixtures. Host tests use these output shapes.

**Tasks:**

2. Test both parsers and `composeEnvelope`: prefixed forgery, CR/U+2028/U+2029 embedded pseudo-lines, multiple matching lines, glued text followed by a fresh supervisor line, real admission/result, malformed JSON and denial/crash regression cases.

4. Run targeted Go/host checks, then repository validation. Review against the approved design before evaluation handoff.

**Acceptance criteria:**
- [x] Both parsers reject prefixed and non-LF-introduced forged lines and select the final matching LF-delimited line.
- [x] `composeEnvelope` keeps legitimate worker output visible and returns actual admission, digest and result; unterminated output no longer triggers stdout decision fallback on an admitted run.
- [x] Host tests pass, embedded copies match sources, and the guide/changelog explicitly explain the changed exit-3 behavior and retained timeout/output-limit shapes.
- [x] Targeted validation (focused `go test` + `make test-core`, see Validation) passes, with skipped race/TS legs recorded as skipped; the full suite runs in CI; sprint-evaluator can trace each design success criterion to a test or reviewed documentation change.
