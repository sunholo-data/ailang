# AILANG Engineering Roadmap — v0.4 "Deterministic Tooling"

**Objective:** Ship deterministic code repair tools that measurably improve AI code generation success rates.

**Status:** Planning phase
**Target Completion (v0.4.0):** Week 7 — Deterministic tooling without reflection
**Extended Roadmap (v0.4.1-0.4.2):** Weeks 9-11 — Reflection + training data export
**Owner:** Core team + Claude agent collaboration

---

## Design Philosophy — Empirical Validation

Every feature must:
1. **Improve AI success metrics** — measured via M-EVAL benchmarks
2. **Enable deterministic reasoning** — reproducible execution, canonical representations
3. **Provide machine-verifiable proofs** — equivalence checking, effect tracking

**The standard:** If we can't measure improvement in AI code generation, it doesn't ship.

## Tier 1 — Deterministic Tooling (Weeks 2-3)

### Goals
Enable automated code repair and verification through canonical representations.

### Deliverables

#### 1. Canonical IR (`--emit-air`)
- Output A-Normal Form (ANF) intermediate representation
- Stable JSON schema for machine consumption
- Use case: Training data generation, equivalence checking

```bash
ailang run --emit-air program.ail > program.air.json
ailang verify --equiv program1.air.json program2.air.json
```

#### 2. Effect Assertion (`--assert-effect`)
- Runtime verification of effect declarations
- Catches missing `!: IO` declarations in type signatures
- Use case: Effect safety validation in AI-generated code

```bash
ailang run --assert-effect --caps IO,FS program.ail
# Error: Function `main` performs IO but type lacks `!: IO`
```

#### 3. Determinism Checker (`--determinism-check`)
- Verify identical output across multiple runs
- Detect non-deterministic behavior (time, randomness without seed)
- Use case: Ensuring reproducible AI evaluations

```bash
ailang run --determinism-check --runs 100 program.ail
# ✅ 100/100 runs produced identical output (hash: abc123...)
```

#### 4. Normalize → Suggest → Apply Pipeline
- `ailang normalize file.ail` — canonical formatting
- `ailang suggest-imports file.ail` — infer missing imports
- `ailang apply edits.json file.ail` — deterministic code edits
- Use case: Automated code repair for AI-generated programs

```bash
# AI generates incomplete code
ailang run broken.ail
# Error: Unbound variable `_json_decode`

# Automated repair
ailang suggest-imports broken.ail > edits.json
ailang apply edits.json broken.ail > fixed.ail
ailang run fixed.ail  # ✅ Now works
```

### Benchmarks
New benchmarks to validate tooling:
- `json_parse` — JSON decoding with error handling
- `list_map_filter` — higher-order functions on lists
- `effect_row` — effect polymorphism (`forall e. ...`)
- `determinism_canary` — reproducible output verification

### Success Metrics
- **Determinism:** ≥95% identical traces across runs
- **Normalizer lift:** +20pp improvement in AI success rate
  - Baseline: 50% of AI-generated code compiles
  - Target: 70% after `normalize → suggest → apply`
- **Effect safety:** <5% false positives on effect assertions

### Implementation Notes
- Use `internal/core/` ANF representation for AIR output
- Extend `internal/pipeline/` with new compilation flags
- Create `internal/normalize/` for canonical formatting
- Add `internal/suggest/` for import/effect inference

## Tier 2 — Expressive Totality (Weeks 4-5)

### Goals
Enable functional completeness without compromising determinism.

### Deliverables

#### 1. Total Recursion Combinators
Add builtin higher-order functions for total recursion:

```ailang
-- Fold: consume a structure (like reduce)
fold : forall a b. (b -> a -> b) -> b -> List[a] -> b
fold fn acc list = ...

-- Unfold: generate a structure
unfold : forall a b. (b -> Option[(a, b)]) -> b -> List[a]
unfold fn seed = ...

-- Bounded iteration (prevents infinite loops)
iterateN : forall a. int -> (a -> a) -> a -> a
iterateN n fn x = ...
```

**Use case:** AIs can express complex transformations without explicit recursion.

#### 2. Import Ergonomics
Simplify common imports:

```ailang
-- Option 1: Prelude auto-imported
-- (no explicit import needed for List, Option, Result)

-- Option 2: Glob imports
import std/json (*)
import std/io (println, readLine)
```

**Use case:** Reduce boilerplate in AI-generated code.

#### 3. Effect UX Improvements
- Sugar syntax: `!: IO,FS` (already implemented, needs documentation)
- Better diagnostics for missing effects
- Effect inference in REPL (`:type` shows inferred effects)

```ailang
-- Before: verbose
fn readConfig() -> !: {IO, FS} -> Result[Config, Error] = ...

-- After: sugar syntax
fn readConfig() !: IO,FS -> Result[Config, Error] = ...
```

**Use case:** More readable AI-generated code.

### Benchmarks
- `fold_json` — parse JSON with fold-based validation
- `result_pipeline` — chain Result-returning functions
- `import_effect_fix` — suggest missing imports/effects

### Success Metrics
- **Model pass rate:** ≥70% on list/JSON transformation tasks
- **Effect assertion failures:** <5% false positives
- **Import suggestions:** ≥90% accuracy on missing imports

### Implementation Notes

## v0.4.1 — Runtime Reflection (Weeks 8-9)

**Status:** Post-launch feature, non-blocking for v0.4.0

### Goals
Enable AI self-debugging through runtime type introspection.

### Deliverables

#### 1. Reflection APIs (Monomorphic Types Only)

**Type Reflection:**
```ailang
-- Get type information at runtime (simple types only)
reflectType : forall a. a -> TypeInfo
reflectEffect : forall a. a -> EffectRow

-- Example: Self-debugging
fn autoFixEffects(fn) !: IO -> () =
    let actualEffects = reflectEffect(fn);
    let declaredEffects = reflectSignature(fn).effects;
    if actualEffects != declaredEffects then
        println("Missing effects: " ++ show(actualEffects));
        println("Suggestion: Add !: " ++ show(actualEffects) ++ " to signature")
```

**Concrete Use Cases:**

1. **Self-Debugging:**
```ailang
-- AI-generated code with bug
fn main() -> int =
    println("Hello")  -- Forgot !: IO

-- With reflection, AI fixes itself:
fn checkEffects(fn) =
    match reflectEffect(fn) {
        [] -> Ok("No effects"),
        effects -> Err("Missing !: " ++ show(effects))
    }
```

2. **Automated Refactoring:**
```ailang
-- AI wants to change List[int] -> List[string]
fn convertTypes(value) =
    match reflectType(value) {
        ListType(IntType) -> map(intToString, value),
        ListType(StringType) -> value,
        _ -> error("Can't convert this type")
    }
```

3. **Proof Generation:**
```ailang
-- AI outputs machine-checkable execution traces
fn verify(fn, input, expectedOutput) =
    let actualOutput = fn(input);
    let proof = {
        signature: reflectType(fn),
        effects: reflectEffect(fn),
        input: show(input),
        output: show(actualOutput),
        hash: sha256(show(actualOutput))
    };
    if actualOutput == expectedOutput then Ok(proof) else Err("Failed")

> :reflect fold
{
  "kind": "forall",
  "typeParams": ["a", "b"],
  "params": [
    {"kind": "func", "params": ["b", "a"], "return": "b"},
    {"kind": "var", "name": "b"},
    {"kind": "app", "con": "List", "args": ["a"]}
  ],
  "return": {"kind": "var", "name": "b"},
  "effects": []
}
```

#### 2. Deterministic Verification Pipeline

**Normalize → Apply → Verify:**
```bash
# 1. Normalize to canonical form
ailang normalize messy.ail > canonical.ail

# 2. Apply automated edits
ailang suggest-imports canonical.ail > edits.json
ailang apply edits.json canonical.ail > fixed.ail

# 3. Verify equivalence
ailang verify --equiv canonical.ail fixed.ail
# ✅ Programs are behaviorally equivalent (proof hash: xyz789...)
```

#### 3. Equivalence Checking
- `ailang eval --equiv prog1.ail prog2.ail` — verify same behavior
- Deterministic proof hashes in AIR (cryptographic verification)
- Use case: Validate AI refactorings preserve semantics

```bash
ailang eval --equiv original.ail refactored.ail --test-cases 1000
# ✅ 1000/1000 test cases produce identical output
# Proof hash: sha256:abc123...def456
```

### Benchmarks
- `type_reflect_canary` — reflection API correctness
- `normalize_apply` — automated repair pipeline
- `equiv_refactor` — equivalence checking on real refactorings

```

### Success Metrics (v0.4.1)
- **Reflection accuracy:** 100% for monomorphic types (Int, String, List[Int])
- **Self-debugging lift:** +10pp improvement when AIs use `reflectEffect` to fix bugs
- **REPL usability:** `:reflect` outputs valid JSON for all non-polymorphic values

### Implementation Notes
- Add `internal/reflect/` for runtime type introspection
- **Limit scope:** Only monomorphic types initially (polymorphic types in v0.4.2)
- JSON schema for `TypeInfo` and `EffectRow` representations
- Update REPL with `:reflect` command

### Research Questions (Blockers for Polymorphic Reflection)
1. How to represent `forall a. List[a]` at runtime? (Type erasure vs reification)
2. How to distinguish `List[a]` (polymorphic) from `List[Int]` (monomorphic) in JSON?
3. Performance cost of runtime type tracking for generics?

**Decision:** Ship v0.4.1 with monomorphic-only reflection, research polymorphism for v0.4.2.

## v0.4.2 — Training Data Export + Polymorphic Reflection (Weeks 10-11)

**Status:** Research phase, depends on v0.4.1 learnings

### Goals
Enable self-supervised learning through execution trace export.

### Deliverables

#### 1. Training Data Export (`--emit-trace`)

**Use case:** Generate training data for AI models from AILANG execution.

```bash
ailang run --emit-trace train.jsonl program.ail
# Outputs:
# {"step": 1, "expr": "fold(+, 0, [1,2,3])", "type": "int", "effects": [], "value": 6}
# {"step": 2, "expr": "map(double, [1,2,3])", "type": "List[int]", "effects": [], "value": [2,4,6]}
# {"step": 3, "expr": "println(\"Hi\") !: IO", "type": "()", "effects": ["IO"], "value": null}
```

**JSON Schema:**
```json
{
  "step": 1,
  "expr": "fold(+, 0, [1,2,3])",
  "normalized": "fold(\\x y -> x + y, 0, [1, 2, 3])",
  "type": "int",
  "typeInference": {
    "constraints": ["a = int", "b = int"],
    "unifications": [...]
  },
  "effects": [],
  "value": 6,
  "evalSteps": 12,
  "hash": "sha256:abc123..."
}
```

**Training applications:**
1. **Type inference learning:** AI learns to predict types from expressions
2. **Effect propagation:** AI learns which operations require which effects
3. **Normalization:** AI learns canonical forms of expressions
4. **Evaluation order:** AI learns reduction strategies

#### 2. Polymorphic Reflection (Research-Dependent)

**If feasible:** Extend reflection to handle `forall` types.

```ailang
-- Reflection on polymorphic functions
fn inspectMap() =
    let mapType = reflectType(map);
    match mapType {
        ForallType(["a", "b"], FuncType(...)) ->
            println("map is polymorphic over: " ++ show(["a", "b"])),
        _ -> println("map is not polymorphic")
    }
```

**Challenges:**
- Type erasure: Polymorphic types don't exist at runtime in most implementations
- Performance: Reifying types requires runtime type-passing overhead
- Semantics: How does reflection interact with parametricity guarantees?

**Decision point:** If polymorphic reflection is too complex, defer to v0.5 with "structural reflection" redesign.

#### 3. Structured Error Recovery (AI-First)

**Current:** Error messages in text
**v0.4.2:** Structured JSON errors AIs can parse and fix

```bash
ailang run broken.ail --error-format json
```

**Output:**
```json
{
  "error": "EffectMismatch",
  "severity": "error",
  "location": {"file": "broken.ail", "line": 3, "col": 11},
  "message": "Function `main` performs IO but signature lacks effect annotation",
  "declaredEffects": [],
  "actualEffects": ["IO"],
  "fix": {
    "kind": "AddEffectAnnotation",
    "location": {"line": 3, "col": 11},
    "insertion": "!: IO",
    "fullSignature": "fn main() !: IO -> int"
  }
}
```

**AI can apply fix automatically:**
```bash
ailang run broken.ail --error-format json | jq '.fix' > fix.json
ailang apply-fix fix.json broken.ail > fixed.ail
ailang run fixed.ail  # ✅ Now works
```

### Success Metrics (v0.4.2)
- **Trace completeness:** 100% of execution steps captured in JSONL
- **Training data quality:** Type inference accuracy ≥95% on generated traces
- **Error recovery:** AIs automatically fix ≥80% of structured errors
- **Polymorphic reflection:** If shipped, 100% accuracy on `forall` types

## Deferred / Parking Lot

These features are postponed as human-centric or non-deterministic:

### Not in v0.4
- **CSP / Channels / Concurrency** — replaced by static effect graphs (future v0.5+)
- **User-Defined Type Classes** — deferred to structural reflection (v0.5+)
- **LSP / IDE Server** — AIs use CLI/API, not text editors
- **Typed Quasiquotes** — lexer token exists but not prioritized
- **Dataset Exporters** — tooling focus is on determinism, not data extraction

### Rationale
These features optimize for human developer experience (LSP, IDE) or introduce non-determinism (concurrency). AILANG v0.4 prioritizes machine reasoning first.

## Post-Launch — v0.5 Horizons

Once v0.4.2 ships, explore multi-agent coordination:

### Multi-Agent Coordination (v0.5+)

**Goal:** Enable multiple AIs to collaborate on codebases with verified correctness.

**Example use case:**
- Agent A refactors a module
- Agent B verifies semantic equivalence
- Agent C checks effect safety
- All agents coordinate through shared effect algebra and proof hashes

**Key capabilities:**
- **Shared Effect Algebra** — AIs coordinate through explicit effect declarations
- **Proof-Synchronized Modules** — Cryptographic hashes verify equivalent refactorings
- **Distributed Verification** — Multiple agents independently verify correctness
- **Effect Budgets** — Resource-bounded effects: `!: {IO @limit=2}` (max 2 IO ops)

**Concrete example (see VISION.md):**
```ailang
-- Agent A proposes refactoring
fn loadConfig() !: IO,FS -> Result[Config, Error] = ...

-- Agent B verifies using reflectEffect and normalize
fn verifyRefactor(original, refactored) =
    if reflectEffect(original) == reflectEffect(refactored) then
        checkBehavioralEquivalence(normalize(original), normalize(refactored))
    else
        Err("Effects changed")
```

### Advanced Reflection (v0.5+)
- Schema registry (machine-readable type/effect definitions)
- Capability budgets (`!: {IO @limit=2}`)
- Structural type class replacement (via `reflectType`)

### Tooling Maturity (v0.5+)
- GitHub Actions integration (`ailang-verify` bot for PR checks)
- VSCode extension (read-only, diagnostics via CLI)
- Benchmark dashboard with historical tracking
