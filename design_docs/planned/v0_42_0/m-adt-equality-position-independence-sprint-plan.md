# Sprint Plan: M-ADT-EQUALITY-POSITION-INDEPENDENCE

**Design doc**: [m-adt-equality-position-independence.md](../m-adt-equality-position-independence.md)  
**GitHub issue**: #713  
**Sprint ID**: `M-ADT-EQUALITY-POSITION-INDEPENDENCE`  
**Planned against**: v0.42.0 (`cb6fc0f0`), 2026-09-23  
**Estimate**: 3 working days, ~690 LOC (implementation, tests, example, and docs)  
**Risk**: high — instance registration and contract inference are language-semantics paths.

## Goal

Make equality on monomorphic ADTs structural and automatic, and make contract predicates obey the
same static typing rules as function bodies. Remove every `std/prelude` import recommendation from
type diagnostics because the module and the recommended bare-import syntax do not exist.

## HEAD Reconciliation

The approved design was measured on v0.38.5; HEAD is v0.42.0 and changes the implementation plan:

- `internal/pipeline/pipeline_module_compile.go` now infers contract expressions to populate
  `CoreTI`, but explicitly discards inference errors. The sprint must promote that best-effort pass
  into a semantic gate, require predicate type `bool`, and retain parameter/`result` bindings.
- M-EQ-DERIVE-CONTAINERS added structural instance synthesis, markers, field validation, and
  residual-constraint checks. This sprint must reuse `registerDerivedEq`,
  `AddDerivedEqForADT`, and `RegisterDerivedEq`; it must not add a third equality mechanism.
- `eqInstanceHint` no longer recommends `std/prelude`, but `Num` and the generic fallback in
  `actionableInstanceHint` still do. Acceptance criterion 5 therefore remains live beyond Eq.
- Source-level user instances are not implemented: `parseInstanceDeclaration` is a stub and the
  v0.42.0 Eq design explicitly relies on that fact. The approved design's criterion requiring a
  non-structural `instance Eq[T]` in both source positions cannot be exercised end-to-end without a
  separate type-class feature. This sprint preserves explicit-instance precedence in unit tests and
  does not invent instance syntax. Source-level custom-instance behavior remains a follow-up gate.

Recent velocity is not measurable from the last seven days because HEAD is a single 46k-line
release fold. Estimates are therefore bottom-up with roughly 25% integration buffer rather than
derived from that misleading commit.

## Milestones

### M0 — Executable baseline and semantic seam tests (~120 LOC, 0.5 day)

**Files**: `internal/pipeline/adt_equality_position_test.go` (new), temporary fixtures generated by
the Go test, and test helpers in the same file.

- Pin issue #713 at HEAD: a monomorphic ADT comparison fails in a body while the same comparison
  in `ensures` currently escapes the discarded contract error.
- Add red tests for ill-typed and non-boolean `requires`/`ensures`, including parameter and
  `result` bindings, so making contract errors fatal cannot accidentally reject valid contracts.
- Add red/green matrix coverage for body, `requires`, and `ensures` positions.

**Acceptance**:

- The test demonstrates the pre-change position discrepancy and fails for the intended reason.
- Valid primitive contracts remain green; invalid predicates are not masked by runtime fallback.
- `make test-core` establishes a green baseline outside the new red tests.

### M1 — Deterministic automatic Eq for monomorphic ADTs (~230 LOC, 1 day)

**Files**: `internal/elaborate/core.go`, `internal/elaborate/file_funcs.go`,
`internal/pipeline/derived_eq.go`, `internal/types/instances.go`, and focused tests beside those
packages.

- Track every monomorphic algebraic declaration separately from explicit `deriving (Eq)` types.
- Generalize the existing sorted registration path so each monomorphic ADT receives the existing
  `DerivedADTEquality` instance and dictionary marker by default.
- Register defaults only when no explicit instance occupies the canonical key; keep
  `deriving (Eq)` accepted as an explicit, idempotent affirmation.
- Leave polymorphic ADTs on the current path: no automatic instance, and unconstrained
  `deriving (Eq)` retains its existing error.
- Pin deterministic registration order and unit-level explicit-instance precedence. Do not add
  parser syntax for user instances.

**Acceptance**:

- `Color` without `deriving (Eq)` supports `==` and `!=` in ordinary expressions.
- Monomorphic constructors with fields use the existing structural comparator and dictionary
  marker; runtime results do not change.
- A pre-registered instance is not overwritten by the compiler default.
- Polymorphic negative cases and all M-EQ-DERIVE-CONTAINERS tests remain green.

### M2 — Contract predicates become a fatal, boolean type-check boundary (~240 LOC, 1 day)

**Files**: `internal/pipeline/pipeline_module_compile.go`, a small extracted helper such as
`internal/pipeline/contract_typecheck.go` if needed to keep the compile coordinator readable,
`internal/pipeline/adt_equality_position_test.go`, and `internal/pipeline/contract_pipeline_test.go`.

- Replace best-effort contract inference with a deterministic helper that constructs the contract
  environment from module bindings, function parameters, and the declared return type as `result`.
- Solve constraints and surface errors with function name, contract kind, and source location.
- Unify every predicate with `bool`; do not merely populate `CoreTI`.
- Fill operator methods only after successful inference, before existing lowering/dictionary phases.
- Cover `requires`, `ensures`, and invariant handling explicitly; ensure a failed contract cannot
  mutate shared inference state for later declarations.

**Acceptance**:

- The same ADT equality expression receives the same verdict in bodies and contracts.
- Ill-typed, non-boolean, and missing-instance contract predicates fail `ailang check`.
- Valid contracts using parameters and `result` still lower and execute.
- Pipeline error output points to the contract rather than failing later in evaluation.

### M3 — Actionable diagnostics, runnable example, and full gates (~100 LOC, 0.5 day)

**Files**: `internal/types/instances.go`, `internal/types/instances_test.go`,
`examples/adt_equality.ail` (new), prompt/docs only if their equality tables are now stale, and
`CHANGELOG.md` or the current release changelog.

- Remove `std/prelude` and bare-import advice from Num and generic instance hints; describe only
  executable fixes at HEAD.
- Add a source-scan regression test covering `internal/types` and `internal/errors` diagnostics.
- Before creating the `.ail` example, run `ailang prompt`; then verify it with `ailang check` and
  execute it through both evaluator and bytecode modes when supported.
- Document automatic structural equality, the polymorphic limit, and redundant-but-valid
  `deriving (Eq)`.

**Acceptance**:

- No diagnostic in the scoped packages recommends `import std/prelude` or another bare import.
- The runnable example compares equal and unequal enum/payload values without deriving Eq.
- `examples/deriving_eq.ail`, structural-equality tests, evaluator/bytecode parity, and
  determinism checks remain green.
- `make fmt`, `make test-core`, `make test`, `make lint`, and `make check-boundaries` pass.

## Dependencies and Ordering

`M0 → M1 → M2 → M3`. M1 and M2 are both required for position independence: automatic instances
alone leave contract errors suppressed, while fatal contract inference alone would turn the
previously accepted postcondition into a rejection.

No external dependency blocks implementation. The source-level custom-instance acceptance case is
not part of the executable language at HEAD and must not expand this sprint into parser/type-class
syntax work.

## Success Metrics

- Issue #713's body and postcondition forms both type-check and execute with identical structural

- Contract predicates are statically checked as `bool`, with all class constraints enforced.
- Automatic ADT instance registration is stable across repeated runs/module ordering.
- At least one runnable `.ail` example and focused tests for all positive and negative paths.
- No regression in M-DX19 or M-EQ-DERIVE-CONTAINERS behavior.
