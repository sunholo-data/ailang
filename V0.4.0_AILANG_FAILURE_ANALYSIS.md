## Executive Summary

AILANG achieved **49% success rate** in v0.4.0 baseline, with **144 failures** across 284 runs. The primary issues are:

1. **Models writing wrong language syntax** (56 failures, 39%)
2. **Parse errors from syntax mistakes** (33 failures, 23%)
3. **Logic errors** (22 failures, 15%)
4. **Runtime errors** (13 failures, 9%)

**Key Finding**: The v0.4.0 prompt (which v0.4.1 now fixes) had:
- ✅ Correct HTTP POST example
- ❌ No JSON decode documentation (models hallucinated)
- ❌ No explicit anti-patterns for `http.post()`, `json.encode()`
- ❌ No simplicity guidance (models overcomplicated solutions)

## Error Pattern Analysis

### 1. WRONG_LANG Errors (56 failures, 39%)

**Top affected benchmarks**:
- `deterministic_list_transform` (6/6 models failed)
- `list_comprehension` (6/6 failed)
- `no_runtime_crashes_option` (5/6 failed)
- `tree_transformation_pipeline` (5/6 failed)
- `api_call_json` (4/6 failed)

**Common hallucinations**:
```python
# ❌ List comprehensions (don't exist)
[x * 2 for x in list]

# ❌ Python-style list methods
list.append(x)
list.map(lambda x: x * 2)

# ❌ HTTP APIs
http.post(url, json=body)
json.encode(data)
JSON.parse(str)

# ❌ Imperative loops
for i in range(10):
    print(i)

# ❌ Assignment statements
result = []
result.append(x)
```

**Root Causes**:
1. Models have strong priors from Python/JavaScript
2. Prompt doesn't explicitly forbid these patterns
3. No negative examples ("DON'T use X")

**v0.4.1 Fixes**:
- ✅ Added explicit anti-patterns: NO `http.post()`, NO `json.encode()`
- ✅ Critical Limitations section lists forbidden syntax
- ✅ Common Mistakes section shows wrong vs correct

---

### 2. PAR_001 Parse Errors (33 failures, 23%)

**Top affected benchmarks**:
- `multi_module_imports` (6/6 failed)
- `effect_pure_separation` (5/6 failed)
- `pipeline` (3/6 failed)

**Common syntax errors**:
```ailang
-- ❌ Wrong list pattern syntax
match xs {
  x::rest => ...  -- Should be: ::(x, rest) or Cons(x, rest)
}

-- ❌ Wrong function type annotations
export func foo(x: int -> int) -> int  -- Should use lambda: (int -> int) is wrong

-- ❌ Missing semicolons in blocks
{
  println("a")
  println("b")  -- Missing semicolon!
}

-- ❌ Record syntax errors
let r = {field: value}  -- Sometimes models use Python-style

-- ❌ Import syntax errors
import "std/io" (println)  -- Should be: import std/io (println)
```

**Root Causes**:
1. Models confusing ML-style syntax with other languages
2. List cons syntax has multiple valid forms (`::(h,t)` vs `Cons(h,t)`)
3. Prompt examples don't show common pitfalls

**v0.4.1 Improvements**:
- ✅ More explicit syntax rules in Critical Limitations
- ✅ Common Mistakes section shows errors side-by-side with fixes
- 🔄 Still needs: more negative examples for list patterns

---

### 3. Logic Errors (22 failures, 15%)

**Top affected benchmarks**:
- `record_update` (6 benchmarks)
- `numeric_modulo` (6 benchmarks)

**Common logic mistakes**:
```ailang
-- ❌ Incorrect record update
let updated = {person.age: 31}  -- Wrong syntax
-- ✅ Correct: let updated = {person | age: 31}

-- ❌ Wrong modulo behavior expectations
5 % 3  -- Returns 2, but models expect different behavior

-- ❌ Incorrect Option handling
match opt {
  Some(x) => x,
  None => 0  -- Type mismatch if x is not int
}
```

**Root Causes**:
1. Subtle semantic differences from other languages
2. Models not understanding AILANG-specific behavior
3. Prompt doesn't emphasize key semantic differences

---

### 4. Runtime Errors (13 failures, 9%)

**Top affected benchmarks**:
- Various (no clear pattern)

**Common runtime issues**:
```ailang
-- ❌ Missing capability grants
export func main() -> () ! {IO} {
  println("hello")  -- Needs IO capability at runtime

-- ❌ Division by zero (not caught at compile time)

-- ❌ Pattern match failures (non-exhaustive)

  Some(v) => v  -- Missing None case
}
```

**Root Causes**:
1. Effect system not always catching capability issues
2. Runtime checks not comprehensive
3. Models not understanding effect propagation

## Recommendations for v0.4.2+

Based on this analysis, future prompt improvements should:

### High Priority (Expected +10-15% success rate)

1. **Add more negative examples**:
   - List comprehensions: Show why they don't exist
   - List patterns: Show correct `::(h,t)` vs wrong `x::rest`
   - Import syntax: Show correct `import std/` vs wrong `import "std/"`

2. **Emphasize semantic differences**:
   - Record update syntax: `{r | field: val}`
   - Modulo behavior: Explain how it works in AILANG
   - Effect propagation: More examples of calling effectful functions

3. **Simplify examples**:
   - Current examples sometimes too complex
   - Show minimal working code first
   - Add "what NOT to add" guidance

### Medium Priority (Expected +5-10% success rate)

4. **Better list operation guidance**:
   - Map/filter/fold patterns more prominent
   - Emphasize "use recursion, NOT loops"
   - Show common list traversal patterns

5. **Effect system clarity**:
   - More examples of effect composition
   - Clearer rules for effect propagation
   - Examples of pure vs effectful separation

6. **Module system examples**:
   - Import/export patterns
   - Multi-module programs
   - Common import mistakes

### Low Priority (Expected +2-5% success rate)

7. **Edge case documentation**:
   - Float comparison pitfalls
   - Pattern matching exhaustiveness
   - Type inference limits

8. **Performance patterns**:
   - Tail recursion examples
   - When to use accumulators
   - Efficient list operations
