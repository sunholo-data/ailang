## [Unreleased] - M-BRAIN-VECTORS: Vector-Native Brain with Embedding Storage

### Added
- **Schema v2 Migration (M1)** — Non-destructive v1→v2 migration adds `embedding BLOB`, `embedding_dim INTEGER`, `embed_model TEXT` columns to brain_frames. IEEE 754 float32 LE encode/decode with exact round-trip precision. `PutVector()` for embedding-only frames. `SearchByEmbedding()` brute-force cosine scan with deterministic ordering. `EmbeddingStats()` for coverage reporting. (~190 LOC)
- **Embedder Wiring (M2)** — `WithEmbedder(e)` CacheOption wires `messaging.Embedder` into SQLiteSharedCache. `PutFrame()` auto-embeds content when embedder present (errors silently ignored — graceful fallback). `BackfillEmbeddings()` for existing frames missing vectors. CLI: `ailang cache put --embed`, `ailang cache embed` backfill command. (~180 LOC)
- **Three-Tier Search (M3)** — `SearchThreeTier()`: cosine (with +0.1 boost) > SimHash > text, merged and deduplicated by key. CLI `--cosine` forces embedding search, `--simhash` forces fast path. `ailang cache put-vector` reads JSON from stdin for machine-to-machine vectors. Stats shows embedding coverage %. Export/import round-trips embeddings via base64 BLOB. (~220 LOC)

### Architecture
- Pluggable embedder: Ollama (local), Gemini Embedding, OpenAI — all satisfy `effects.Embedder` interface
- Three-tier search: cosine similarity (best, requires embeddings) > SimHash (fast, always available) > text LIKE (fallback)
- Vector-only frames enable machine-to-machine communication without text
- Base64 embedding in JSONL export preserves vectors across backup/restore
- Design doc: `design_docs/planned/v0_9_3/m-brain-vectors.md`

- **M-ASYNC-IO Phase 1: Multi-Source Event Multiplexing** (`internal/effects/`, `internal/builtins/`, `std/stream.ail`, ~850 LOC)
  - **EventSource interface** (`stream_source.go`): Abstraction for any readable event source with `Name()`, `Priority()`, `Events()`, `Close()` methods. `connSource` adapter wraps existing `StreamConnection.eventBuffer` channel.
  - **Deterministic multiplexer** (`stream_mux.go`): `selectEventsLoop` implements priority-ordered dispatch over N event sources:
    - Phase 1: Non-blocking priority-ordered check — highest priority wins (deterministic)
    - Phase 2: Block via `reflect.Select` when no events ready (nondeterministic arrival, traced)
    - Round-robin within same-priority bands prevents starvation
    - Idle timeout + max duration ceiling timers
  - **Stdin line reader** (`stream_stdin.go`): `stdinSource` spawns a goroutine reading lines via `bufio.Scanner`, producing `SourceText` events with source tagging
  - **3 new Stream operations** (`stream_async_ops.go`):

### Fixed
- **M-MODULE-SCOPE: Non-exported function name collision across modules** (`internal/runtime/runtime.go`, `internal/eval/eval_evaluator.go`, ~20 LOC)
  - **Bug**: Non-exported (internal) functions with the same name in different modules silently collide. Last-loaded module's version shadows all previous definitions. E.g., `docx_parser.joinParagraphTexts` gets overwritten by `pptx_parser.joinParagraphTexts`, causing DOCX table cells to return empty strings.
  - **Root cause**: `ModuleRuntime.evaluateModule()` used a single shared evaluator environment for ALL modules. `extractBindings()` called `rt.evaluator.Env().Set(name, val)` for both exported AND internal functions — flat namespace collision.
  - **Fix**: Per-module child environment isolation. Each module evaluates in a `NewChildEnvironment()`. Closures capture the child env (correct scoping). Exports are promoted to parent env for cross-module import resolution. Internal names stay isolated in their module's child env.
  - **New**: `CoreEvaluator.SetEnv()` method for environment save/restore
  - 3 regression tests: two-module collision, three-module collision, closure-after-load stability
  - Design doc: `design_docs/implemented/v0_9_0/m-module-scope.md`
