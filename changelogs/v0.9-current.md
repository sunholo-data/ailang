# AILANG Changelog: Current (Cloud Integration, Pub/Sub)

> Archived from CHANGELOG.md. See [CHANGELOG.md](../CHANGELOG.md) for latest and links to all archives.

## [Unreleased]

### Added
- **M-BRAIN-CONTEXT: Contextual brain injection during active sessions** —
  New `brain_context.sh` PreToolUse hook injects relevant brain knowledge when
  files are read during Claude Code sessions, not just at session start. Surfaces
  past resolutions, design decisions, and file context aligned with what you're
  actually working on. Three noise-prevention mechanisms: directory-level cooldown
  (5 min default), session token budget (2000 tokens, soft warning), and relevance
  threshold filtering (score >= 0.25). Configurable via `AILANG_BRAIN_COOLDOWN_SECS`,
  `AILANG_BRAIN_BUDGET_TOKENS`, `AILANG_BRAIN_MIN_SCORE` env vars. Graceful
  degradation — exits silently if ailang unavailable or brain empty. (~80 LOC)
- **M-STDLIB-CRYPTO-JWT: RSA signature verification and JWT support** —
  New `rsaVerifyPKCS1v15(message, signature, publicKeyPEM)` builtin in `std/crypto`
  verifies RSA-SHA256 signatures against PEM-encoded public keys or X.509 certificates
  (Firebase key format). New `fromBase64URL` in `std/bytes` decodes JWT's base64url
  encoding (RFC 4648 §5, no padding). New `std/jwt` module provides pure AILANG functions:
  `decodeJWT` (parse without verification), `verifyRS256` (decode + RSA verify),
  `verifyWithKid` (key selection by kid header — Firebase/OAuth pattern), and claims
  helpers (`isExpired`, `checkIssuer`, `checkAudience`). All functions are pure — key
  fetching is the caller's responsibility via `std/net`. (~350 LOC implementation,
  ~250 LOC tests)

- **M-SERVE-API-ENDPOINT-FILTERING: Endpoint filtering and @nowrap JSON auto-unwrap** —
  New `--routes-only` flag for `serve-api` limits HTTP endpoints to `@route`-annotated
  functions only, hiding internal exports from the API surface. New `@noexpose` annotation
  marks individual exported functions as hidden from HTTP (they remain importable by other
  modules). Both mechanisms filter OpenAPI spec generation, A2A Agent Card skills, and
  the startup banner. Also fixes `@nowrap` double-encoding: functions returning valid JSON
  strings via `encode(jo([...]))` now write raw JSON instead of re-encoding through
  `json.Encoder` (producing `{"status":"healthy"}` instead of `"{\"status\":\"healthy\"}"`.
  Auto-unwrap only triggers for JSON objects and arrays, not bare strings/numbers/booleans.
  (~170 LOC implementation, ~100 LOC tests)

### Improved
- **M-SERVE-API-ZERO-VALUE-PADDING: Zero-value padding for missing named parameters** —
  Missing named parameters in serve-api requests now receive type-appropriate zero-values
  (`""` for string, `0` for int, `false` for bool) instead of unit, which crashed on type
  operations like `length()`. Functions can now validate inputs with `if apiKey == "" then ...`
  and return structured errors instead of framework-level crashes. Positional `{"args": [...]}`
  with fewer elements than expected is also padded. OpenAPI spec now includes `x-ailang-param-types`.
  Per-parameter types extracted from AST at module load time. (~150 LOC)

### Fixed
- **M-VALIDATOR-PATTERN-BINDINGS: Fix validator rejecting pattern match bindings** —
  The `check --package` validator's `collectPatternVars` function did not collect variable
  bindings from `ListPattern.Tail`, causing cons pattern bindings like `rest` in
  `x :: rest =>` to be falsely reported as undefined references. This blocked publishing
  any package using list recursion patterns. Fixed by adding tail traversal to the
  ListPattern case. (~3 LOC fix, regression from M-PKG-INTERREF)
- **M-PKG-INTERREF: Package inter-function reference fix** — Fixed resolver context leak
  where on-demand module evaluation didn't accumulate Let/LetRec bindings in the evaluator
  environment. This caused "undefined variable" errors when an exported function in a
  dependency package called non-exported helper functions. The resolver now accumulates
  each binding in the evaluator env so sequential declarations can reference earlier ones.
  Added static Core AST scope check to `check --package` as defense-in-depth: walks
  top-level declarations verifying that `core.Var` references resolve to in-scope bindings
  from earlier Let/LetRec chains. (~120 LOC)
- **M-ROUTE-COLLISION: Route collision guard & optional A2A** — `registerCustomRoutes()` now
  skips `@route` annotations that collide with built-in paths (health, meta, A2A, MCP) instead
  of panicking on Go 1.22+ ServeMux duplicate pattern registration. A2A protocol endpoints
  (`/.well-known/agent.json`, `/a2a/`) are now opt-in via the `--a2a` flag, mirroring the
  existing `--mcp-http` pattern. This fixes a production crash in docparse Cloud Run deploys
  where a stale `@route("GET", "/.well-known/agent.json")` annotation collided with the
  built-in A2A handler.

### Added
- **M-AI-IMAGE: AI image generation via std/ai** — Two new functions in `std/ai` for generating
  images via AI models. `callImage(prompt, output_path, options)` generates an image and saves it
  to disk (requires `{AI, FS}` effects). `callImageBase64(prompt, options)` returns the image as a
  JSON string with base64-encoded data and mime_type (requires `{AI}` only). Options is a JSON
  string supporting `aspect_ratio` and `mime_type` fields. Gemini provider (`gemini-2.5-flash-image`)
  implements image generation via `ResponseModalities: ["IMAGE"]`. Other providers (OpenAI, Anthropic,
  Ollama) return clear "not supported" errors. Includes stub handler for deterministic testing.
  (~430 LOC: provider types, Gemini extraction, effects, builtins, stdlib, example)
- **M-SERVE-API-AGENT-ENHANCEMENTS: Named parameter binding & @nowrap custom headers** —
  serve-api now supports named JSON parameter binding: agents can send `{"path": "file.docx",
  "output_format": "blocks"}` instead of positional `{"args": ["file.docx", "blocks"]}`. JSON
  keys are matched to function parameter names with automatic snake_case→camelCase conversion.
  Positional `{"args": [...]}` format remains fully backward compatible. Additionally, `@nowrap`
  routes can now set custom HTTP response headers via a `_headers` field in the return record —
  the field is extracted as headers and excluded from the JSON body. Parameter names are exposed
  in the OpenAPI spec via `x-ailang-param-names` and request body descriptions.
  (~360 LOC: handler, routes, server, openapi, tests, docs)
- **M-STDLIB-UUID4: `uuid4()` in std/rand** — New builtin generates RFC 4122 v4 UUID strings
  using `crypto/rand`. Available as `rand.uuid4()` with the `Rand` effect. Useful for generating
  unique API keys, request IDs, and correlation tokens without verbose hex-char approaches.
- **M-ROUTE-NOWRAP: `@nowrap` annotation for unwrapped @route responses** — `@route` handlers
  annotated with `@nowrap` return their result as raw JSON without the `FunctionCallResponse`
  envelope (`{result, module, func, elapsed_ms}`). Enables protocol-compliant responses for
  A2A agent cards, OpenID discovery docs, and any REST endpoint where consumers expect a
  specific JSON schema. Composes with `@raw` for full request/response control. Timing is
  still available via `X-Elapsed-Ms` response header.
- **M-DX-ROUTE-CTX: `@raw` annotation for HTTP request context** — `@route` handlers can now
  receive full HTTP request context (headers, raw body, method, path, query) by adding the `@raw`
  annotation. The handler receives a single `HttpRequest` record argument instead of parsed args.
  Use case: webhook handlers that need signature headers (Stripe, GitHub, Slack). Non-`@raw` routes
  are completely unchanged. (~320 LOC: parser, apiserver, tests, example, docs)
- **M-DEBUG-ERASURE: Debug is now a true ghost effect** — Debug no longer cascades through
  function signatures. Functions can call `Debug.log()` and `Debug.check()` without declaring
  `! {Debug}` — the effect is invisible to callers. Additionally, `--release` flag now erases
  Debug calls to `()` (unit) and removes Debug from effect rows. Ghost effect transparency is
  implemented via `eraseGhostEffects()` in the effect validator; release erasure via `DebugEraser`
  pipeline pass. Both `ailang run --release` and `ailang compile --release` work.
- **Debug ghost effect: fully invisible DX** — Three remaining friction points removed:
  (1) Package `[effects].max` no longer needs to list Debug — ghost effects bypass ceiling checks.
  (2) `--caps Debug` no longer required at runtime — Debug is auto-granted in every EffContext.
  (3) Debug output now collected and printed to stderr after execution (was silently dropped).
  serve-api flushes Debug logs per request via `log.Printf`. All three changes make Debug
  truly invisible — packages just `import pkg/sunholo/logging/logger` and it works.
- **M-PKG-EXPLORER: Package Explorer Website** — Browse all published AILANG packages at
  `ailang.sunholo.com/docs/packages/`. Features: per-vendor/per-package static pages mirroring
  module import paths (`/docs/packages/sunholo/auth`), interactive explorer with search/filter/stats,
  dependency graph visualization with effect-colored nodes, version timeline with provenance chains,
  and ecosystem stats charts. Hybrid static+dynamic architecture: build-time sync generates MDX pages,
  runtime React components hydrate with live data from registry-validator API.
  - Registry validator: new read-only `/api/packages`, `/api/packages/:vendor/:name`, `/api/stats`
    endpoints with in-memory cache (5-min TTL, invalidated on publish) and CORS
  - Build pipeline: `sync-registry.sh` generates per-vendor/per-package MDX pages and sidebar items
  - React components: PackageDetail, VersionTimeline, ProvenanceChain, PackageExplorer,
    DependencyGraph, EcosystemStats, VendorIndex — all with dark/light theme support
  - Data hooks: stale-while-revalidate with localStorage caching and graceful API-down fallback
- **serve-api: GET query parameter support** — GET requests now accepted for function calls.
  Query parameters parsed as positional (`?args=1&args=2`) or named (`?name=Alice`) arguments.
  Existing `@route("GET", ...)` annotations now receive arguments they previously lost.
- **`ailang install @latest`** — Bare `ailang install sunholo/auth` and `ailang install sunholo/auth@latest`
  resolve the latest version from the registry index and write the exact version to `ailang.toml`.
  Semver ranges (`^`, `~`, `>=`) are explicitly rejected — AILANG requires exact versions in manifests.
- **Manifest version guardrail** — `ailang.toml` validation now rejects non-exact dependency versions
  (`latest`, `^0.1.0`, etc.) with actionable error messages pointing to `ailang install @latest`.

### Fixed
- **M-DX-XPKG-RESOLVE: Cross-package stdlib function resolution** (~120 LOC, 4 unit tests + integration test)
  - Functions from stdlib packages (e.g., `asString` from `std/json`) that internally construct ADT
    values (e.g., `Some(s)`) failed when called cross-package — the evaluator used the CALLER's
    resolver instead of the DEFINING module's resolver, so `$adt` constructor lookups couldn't find
    `Option.Some`/`Option.None`. Fix: `FunctionValue` now captures the defining module's `Resolver`
    at closure creation time. At call sites, a `FallbackResolver` tries the caller's resolver first
    (preserving builtins and effect context), then falls back to the function's defining resolver
    (for constructors and module-specific lookups). Three call paths patched: direct application,
    auto-curry, and `applyFunction`.
- **Resolver version conflict detection** — `ailang lock` now fails with a structured `VersionConflictError`
  when a transitive dependency requires a different version of a package than the root manifest pins.
  Previously, the resolver silently used whichever version was encountered first (Go map iteration order),
  which could downgrade direct dependencies. Error includes conflicting versions, which package introduced
  the conflict, and actionable suggestions (republish or change root pin). Dependency iteration is now
  sorted by name for deterministic resolution order.
- **Portable lock file** — `ailang.lock` no longer stores absolute cache paths for registry and git
  packages. Paths are resolved at runtime via `CachedPackagePath()` and `GitCache.CacheDir()`.
  Lock files can now be copied into Docker containers and CI environments without re-resolving.
  Old lock files with stored paths continue to work (backward compatible).

## [v0.9.12] - 2026-03-23

### Added
- **M-DX-RELIMPORT: Relative imports for intra-package modules**
  - `import ./plan (Plan)` for sibling modules within the same package
  - `import ./sub/bar (doThing)` for child directory modules
  - Three-way import distinction: `./` (local), `pkg/` (external), `std/` (stdlib)
  - Resolves in module namespace, not filesystem paths: `./plan` in module `a/b/c` → `a/b/plan`
  - Normalized to canonical paths before elaboration — interfaces/hashes use canonical only
  - Backward compatible: `pkg/` self-imports continue to work
- **Package self-reference loader**: Packages can import their own modules via `pkg/` prefix
  (the loader detects self-references against the current package manifest)

### Fixed
- **M-TYPE-ALIAS: Cross-Package Record Type Alias Unification** (~100 LOC, 9 tests)
  - Type aliases now propagate when importing functions/constructors, not just type names.
    Previously, `import pkg_a/types (applyDelta)` would import `applyDelta` but not the
    `Usage` type alias from that module, causing "cannot unify type constructor Usage with
    TRecord" errors.
  - Module interfaces now embed transitive type aliases referenced in exported function
    signatures. If Package B exports `getUsage() -> Result[Usage, string]` and `Usage` is
    defined in Package A, Package B's interface includes the `Usage` alias so downstream
    consumers can resolve it.
  - Eliminated need for explicit type annotations as workaround for cross-package record types.
  - New tests: `TestCollectTConNames`, `TestCrossPackageTypeAliasUnification`,
    `TestTransitiveTypeAliasPropagation`

### Fixed
- **M-MODULE-SCOPE: Non-exported function name collision across modules** (`internal/runtime/runtime.go`, `internal/eval/eval_evaluator.go`, ~20 LOC)
  - **Bug**: Non-exported (internal) functions with the same name in different modules silently collide. Last-loaded module's version shadows all previous definitions. E.g., `docx_parser.joinParagraphTexts` gets overwritten by `pptx_parser.joinParagraphTexts`, causing DOCX table cells to return empty strings.
  - **Root cause**: `ModuleRuntime.evaluateModule()` used a single shared evaluator environment for ALL modules. `extractBindings()` called `rt.evaluator.Env().Set(name, val)` for both exported AND internal functions — flat namespace collision.
  - **Fix**: Per-module child environment isolation. Each module evaluates in a `NewChildEnvironment()`. Closures capture the child env (correct scoping). Exports are promoted to parent env for cross-module import resolution. Internal names stay isolated in their module's child env.
  - **New**: `CoreEvaluator.SetEnv()` method for environment save/restore
  - 3 regression tests: two-module collision, three-module collision, closure-after-load stability
  - Design doc: `design_docs/implemented/v0_9_0/m-module-scope.md`
