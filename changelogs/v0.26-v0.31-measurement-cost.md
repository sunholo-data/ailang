### Changed

- **BREAKING:** `ailang test` now exits 1 for mixed suites whose
  `no_generator` or `unsupported` properties ran zero cases; pass
  `--allow-skips` to retain the former permissive exit behavior. JSON reports
  additive `vacuous_skips` and per-property `skip_kind` fields, and JSON mode
  now writes pure JSON to stdout. Property parameters spelled `[T]` or
  `list[T]` now use the reachable list generator. In the in-repo contracts
  corpus this changes the exit status of `inbox_injection_v2.ail`,
  `inbox_v2_app.ail`, `park.ail`, and `record_discovery_verify.ail` from 0 to 1.

  Two consequences worth calling out, because neither follows from the above:

  - **Some suites get *less* red, not more.** Making `[T]` generators reachable
    means properties that never ran now execute — and a property that runs can
    then be discarded as out-of-contract, which is forgiven. So
    `list_recursive_verify.ail` can move from exit 1 to exit **0**. A property
    surviving only 1–2 of 100 generated cases before the rest are discarded is
    near-unvalidated yet reported as passing; that residual gap is tracked as
    follow-up **F1** and is *not* closed here. Newly-running properties may also
    surface genuine contract violations that were previously invisible (observed
    in `list_verify.ail`).
  - **The per-file list above is not reproducible run-to-run.** Property
    generation is seeded from the wall clock, so the same file on the same binary
    can yield a different exit code between runs (#535). The `vacuous_skips`
    classification added here is stable; `failed_tests` counts, and therefore
    some exit codes, are not. Treat the corpus list as illustrative rather than
    as a contract until #535 is fixed.

- **Breaking for out-of-repo shell callers:** `ai-check` now exits 1 when its
  emitted JSON reports `verify.errors > 0`; complete JSON is still written
  before the exit decision. Skips remain exit 0.

### Fixed — our Anthropic prompt-cache hit rate was structurally zero (M-ANTHROPIC-CACHE-HIT-RATE)

Anthropic told us our organization's prompt-cache hit rate was very low. It was very low because
the code path carrying essentially all of our Anthropic traffic **could not request a cache at
all**: `internal/ai/anthropic/client.go` contained zero references to `CacheBreakpoint`.
M-AI-PROMPT-CACHING (v0.18.4) wired `Step`; every 0-shot eval, classifier call, and `ai.generate`
goes through `Generate`.

Three things were wrong, and each hid the next:

| | Problem |
|---|---|
| Capability | `Generate` had no `cache_control` support whatsoever |
| Placement | The only implemented breakpoint was `system`, but our reusable content is a ~16K-token teaching prompt in the **user** turn, sat behind a ~70-token system prompt — below every model's minimum cacheable prefix |
| Visibility | Cache tokens were modelled on `ai.Response` but never persisted; **zero of 28,139** banked result files carried them, so the miss was invisible in our own telemetry |

What changed:

- **`ai.Request.CachedPrefix`** — a provider-neutral carrier for the stable head of a user turn.
  The model always sees `CachedPrefix + UserPrompt`; only the encoding differs. On Anthropic with a
  `user_prefix` breakpoint it becomes a two-block content array with `cache_control` on block 0
  only (a marker on the volatile block would write an entry per request and never read one).
  Everywhere else it concatenates, byte-identical to v0.30.0.
- **Caching is ON by default** for the eval harness on Anthropic. Opt-in is exactly why the rate
  was near zero — the v0.18.4 mechanism shipped and no Go caller ever set it.
- **Silent no-ops now warn.** Anthropic accepts a too-short `cache_control` marker, returns 200,
  and quietly declines to cache. A model-tier minimum table (512/1024/2048/4096 — *not* monotonic
  across generations) drives a one-shot warning naming the model and the shortfall.
- **Cache tokens are persisted** into banked eval metrics, additive and `omitempty` so pre-v0.31.0
  baselines still parse.

Two decisions worth recording. The teaching prompt was **not** moved to the system role, though
that would cache equally well: it changes model inputs and would invalidate every v0.30.0 baseline
in the same commit as a cost change. Splitting in place keeps the bytes identical. And the
feedback-gate classifier is measured and deliberately **not** cached — ~439 tokens against
`claude-haiku-4-5`'s 4096-token minimum, so a breakpoint there would be the exact silent no-op
this work removes; a test fails if the prompt ever outgrows the minimum.

Not yet proven: that Anthropic actually creates and reads the entries. That needs a live billed
call and no API key was available in this window. The check is written and gated as
`TestLiveGeneratePromptCache` (`AILANG_LIVE_ANTHROPIC_CACHE=1`).

Design doc: `design_docs/planned/v0_31_0/m-anthropic-cache-hit-rate.md`

### Added — the measurement contract: banked data must earn its place (M-EVAL-MEASUREMENT-CONTRACT)

The eval pipeline could not distinguish **"the subject was measured and did badly"** from
**"we failed to measure the subject."** Both produce a low number, and both were banked as
findings. Four incidents in six weeks, one shape:

| Incident | Recorded as |
|---|---|
| motoko died before step 0 for six days (`1282767ca` broke its module load) | 72 benchmark "failures" |
| a shell bug coerced an empty pass count to `0` | `on_pass: 0, delta_pp: -73.8` — a real 0% measurement |
| ten cloud motoko models silently ran the `dogfood` profile | rows advertising microRAG + DP7 they never loaded |
| the fmt A/B ran against a subject at ~96% | a comparison structurally unable to show the effect |

Five checks now stand between a run and a trend line:

- **Pre-flight canary** (`CanaryCheck`, optional executor interface). `HealthCheck` proves a CLI
  exists; the canary proves the subject *works* — motoko's `--version` is handled at the
  TypeScript argv level and exits before any AILANG module loads, which is how it passed 72 times
  while dead. A failing model is dropped **before the run matrix is built**, so it cannot bank a
  row. `--no-canary` overrides.
- **Validity flag** on every banked result (`canary_failed`, `zero_files`, `zero_pass_all`,
  `config_mismatch`, `harness_error`, `infra_outage`). Analysis excludes invalid **by default**;
  `LoadResultsIncludingInvalid` reaches quarantined data, which is annotated, never deleted.
  A missing `validity` field means valid, so no pre-v0.31.0 history is erased.
- **Paired analysis + McNemar** (`ailang eval-paired`). Aggregate rate deltas cannot resolve
  anything at n=84 (unpaired SE ≈ 6.8pp ⇒ only effects >~13pp reach significance). Replaying the
  real 2026-07-27 A/B: aggregate unchanged at +13.1, pairing yields b=18, c=7 → χ²=4.0,
  **p=0.0455**. No p-value below 10 discordant pairs; unpaired rows surfaced, never dropped.
- **Resolved-config assertion**. motoko now broadcasts the profile it actually loaded; a
  contradiction with the `models.yml` claim quarantines the row as `config_mismatch`.
- **Headroom warning**. A control arm at or above 90% cannot resolve a small effect. Advisory,
  never blocking.

Guide: [docs/docs/guides/evaluation/measurement-contract.md](../docs/docs/guides/evaluation/measurement-contract.md).

### Fixed — dedup key was dropping half of every multi-trial run

The re-run dedup keyed on `(model, id, lang, seed, mode)`, but both trials of a benchmark share
all five — so a `--trials N` run collapsed to its newest trial per slot. Every multi-trial rate
was computed from a fraction of the data collected:

- `eval_results/rotation/os-rolling/v0.30.0`: **494 → 861 rows** (+367)
- one arm of the weekly A/B: **42 → 84 rows** (+42)

⚠️ **Dashboard numbers will move.** The new ones are computed from 861 observations instead of
494. Re-runs still dedup exactly as before (same trial, newest wins), and legacy rows predate the
`trial` field so their behaviour is unchanged — both pinned by test.

Found while implementing paired analysis, where the symptom was louder than a wrong rate: the
surviving trial could differ between arms, so the join produced `delta=9.5 / unpaired=46` instead
of the correct `delta=13.1 / unpaired=0`.

### Fixed — effect validation no longer erases mode parameters across local calls (M-EFFECT-REPLAY-SUBSUMPTION M0+M1)

⚠️ **This makes the effect checker STRICTER.** Code that type-checked before may now be
rejected — that is the point. Three fixtures that previously passed (`c3`, `c7`, `c8`) now
correctly fail. The matching *relaxation* (letting a declared `seeded`/`crypto` mode satisfy a
bare/os requirement) is M2 and has not landed yet, so `! {Rand[mode=seeded]}` still cannot call
the bare `std/rand` wrappers.

Design doc: [m-effect-replay-subsumption.md](../design_docs/planned/v1_0_0/m-effect-replay-subsumption.md)

- **Effect modes were silently erased for calls to locally declared functions.**
  `ValidateEffects` built its declaration map with `ast.EffectNames`, which returns effect
  *names* only, so a local call's requirement was reconstructed mode-blind and normalised to
  `mode=os`. Enforcement was therefore one-directional: a bare/os caller silently accepted a
  `seeded` or `crypto` callee, while the reverse was rejected. Declarations now carry full
  elaborated `*types.Row` values through validation, and elaboration errors are **returned
  rather than swallowed** into a default row.
- **Conflicting modes can no longer collapse to whichever was seen first.**
  `UnionEffectRows` deliberately prefers its left parameter map on conflict. That was harmless
  only while params were erased; preserving them made it a soundness hazard — a body calling
  both a `seeded` and an `os` helper would collapse to one mode, and if `os` survived, an `os`
  declaration would wrongly *accept* the `seeded` callee, reopening the very hole this change
  closes. Validation now collects requirements through a conflict-preserving union that keeps
  both values as a stable sorted set, so neither traversal order can silently win.
  Guarded by `TestConflictingLocalModesAreOrderIndependent`,
  `TestConflictingImportedAndLocalModesAreOrderIndependent` and
  `TestRequirementUnionPreservesConflictingModesDeterministically`, each covering both
  declaration directions and both call orders. `UnionEffectRows` itself is unchanged.
- **Row-variable tails still validate.** `! {IO | e}`-style declarations across `std/list`,
  `std/stream` and `std/smoke` are explicitly guarded, since preserved rows now carry a real
  `Tail` where the old path produced a bogus label.
- Function-value effect-row **unification remains invariant** — this is a validate-path change
  only. `unifyRows`, `effectParamsCompatible`, `effectiveParamsOf`, `DefaultModeFor`,
  `internal/replay` and `internal/eval` are byte-unchanged.

Known gap carried to M2: a rejection caused by conflicting modes exits 1 correctly but does not
yet name the offending mode, and the conflict set can surface as `mode=os|seeded` in a
"Suggested fix" line, which is not valid AILANG source. Structured mode diagnostics are M2's
deliverable.

### Changed — eval suite: equal token headroom + labelled thinking state (M-EVAL-TOKEN-HEADROOM)

⚠️ **Baseline discontinuity.** `max_output_tokens` moved by up to 8× on some rows. Eval
numbers produced after this commit are **not comparable** to earlier baselines. Pre-v0.30.0
results additionally carry no `reason_tokens` and cannot be re-judged for truncation — only
re-run. Do not redraw a trend line across this boundary without saying so.

Design doc: [m-eval-token-headroom.md](../design_docs/planned/v0_31_0/m-eval-token-headroom.md)

- **P1 — `finish_reason` on the standard path** (previous entry below): a run truncated at
  `max_tokens` now banks `finish_reason: "length"` instead of looking like a capability failure.
- **P2 — `default_thinking` on every model** (`on` / `off` / `always_on` / `none` / `unknown`).
  The harness sends no `thinking` control, so each model runs at its *vendor* default, and
  those disagree (Opus 5 / Sonnet 5 think; Opus 4.8 does not; Fable 5 cannot be stopped;
  gemini-3-5-flash-lite has none). 29 rows carry a citable value; **81 are `unknown`** — a
  deliberate admission rather than a guess, since a wrong label silently corrupts an
  efficiency comparison. Enforced by `TestModels_DefaultThinkingIsExplicit`.
- **P3 — headroom equalised to 65536** for cloud entries, or a documented lower ceiling.
  The suite previously ranged **8192 → 128000**; unequal headroom is a silent, *directional*
  confound (a thinking model on a small budget reads as a weak model — the GLM-5.2 failure).
  53 entries changed. Ceiling-limited exceptions: Anthropic held at its 64000 family cap
  (non-streaming Messages API), and `or-deepseek-v3` / `or-qwen-2-5-72b` at 16384 (verified
  via the OpenRouter endpoints API as their max across *all* upstreams). Local ollama rows
  are exempt — VRAM-bound, not policy. Enforced by `TestModels_CloudHeadroomEqualised`.
- **Why equalising matters beyond fairness**: it converts "ran out of tokens" from a harness
  artifact into real token-efficiency signal about the model. That only works if truncation
  is visible, which is why P1 gates P3.
- ⚠️ `claude-fable-5` dropped 128000 → 64000. It is an always-thinking model, so this is the
  row most likely to start reporting `finish_reason: "length"`. That would be a genuine
  efficiency finding under equal headroom — but check it before reading any Fable score change
  as capability.

### Fixed — Anthropic thinking control is now model-generation aware

Anthropic **removed** the fixed-budget extended-thinking knob
(`thinking: {type:"enabled", budget_tokens:N}`) starting with Claude Opus 4.7;
sending it to a 4.7-or-later model is a hard **HTTP 400**, not a degraded run.
The provider client emitted that one shape for every Anthropic model, so the
reasoning-effort knob (M-AI-REASONING-EFFORT) would have failed every request on
Opus 4.7 / 4.8 / Opus 5 / Sonnet 5 / Fable 5.

Not user-visible today: `reasoningCapabilities` ships empty, so `checkCapability`
already rejects every reasoning control before dispatch, and no models.yml entry
sets one. This lands the correct wire shape **before** the M7 live-smoke step
populates that table and opens the path.

- **New generation table** (`internal/ai/reasoning_anthropic.go`):
  `AnthropicThinkingStyleFor(model)` classifies a model as adaptive-style
  (Opus 4.7+) or budget-style (Opus 4.6 and older), tolerating `-YYYYMMDD`
  snapshot ids. Unlisted models return `!ok` — callers fail loudly rather than
  guessing a shape, matching the capability table's no-optimistic-pass-through rule.
- **Wire shape per generation** (`thinkingConfigFor`, used by both `Generate` and
  `buildStepRequest`): adaptive models get
  `{"thinking":{"type":"adaptive"},"output_config":{"effort":"low|medium|high"}}`;
  budget models keep `{"thinking":{"type":"enabled","budget_tokens":N}}` unchanged.
  Effort `off` emits an **explicit** `{"type":"disabled"}` on adaptive models —
  omission there means thinking stays **on** by default (Opus 5 / Sonnet 5), the
  opposite of what was asked. Fable 5 / Mythos 5 think unconditionally, so `off`
  is rejected with a clear message instead of a 400.
- **Actionable rejection** (`ResolveReasoning`): an explicit positive
  `thinking_budget_tokens` on an adaptive model now fails naming the removed knob,
  ahead of the MaxTokens check that would otherwise blame the wrong parameter.
  A budget of `0` stays exempt — that is disablement, which is expressible.
- **Invariant guard**: `TestAnthropicThinkingStyle_CoversCapabilityTable` fails if
  a model is ever registered as reasoning-capable without a classified generation
  (the half-populated-table failure mode). Wire bodies are pinned per generation
  by a table-driven test asserting `budget_tokens` never reaches a 4.7+ model.
- Requests with **no** reasoning control are unchanged and byte-identical, on both
  generations.

### Added — Cost-Per-Verified-Success KPI (M-COST-PER-SUCCESS-KPI, M1–M3)

The v1.0 headline value KPI: **dollars of benchmark spend per verified success**,
built on the already-shipped cost-classification substrate (`ClassifyStageCost`,
`CostRollup.TotalKnownCost()`) — no reimplementation of cost math.

- **M1 — capture + compute** (`internal/observatory/cost_per_verified_success.go`):
  a single `isVerifiedSuccess` predicate and a strict rollup that sums the
  **reported+estimated** known cost (never the divergent legacy raw-SQL total) over a
  cohort's banked `eval_assessment` rows, including failed-attempt spend. The 5
  `verify_*` fields are propagated into **both** `EvalAssessment` constructors
  (agent + standard paths, `cmd/ailang/eval_benchmark.go`); `EvalQueryOptions` gains
  a `SourceRefPrefix`/`CreatedAfter`/`CreatedBefore` cohort filter. No DB migration.
- **M2 — expose + publish**: `ailang chains stats --cost-per-verified-success
  --baseline <id> [--json] [--strict]`, `GET /api/chains/stats?cost_per_verified_success=true`,
  and an additive `latest.json headlineKpis.costPerVerifiedSuccess` — all serialize the
  **same** `CostPerVerifiedSuccessResult` struct field-for-field.
- **M3 — dashboard**: a headline KPI card atop `ValueDashboard` with a visible
  Fallback/stale badge when the static copy is served, and explicit
  available / zero-denominator / incomplete / absent states.
- **Fail-loud, no silent fallback**: any unknown-cost stage, zero denominator, or
  empty cohort yields `available=false` — never a fabricated `$0`, infinity, or stale
  value. `--strict` exits non-zero on unavailability.
- **M4a — cohort freeze mechanism** (the *write* side). M1–M3 shipped the read side,
  but it was **live-unreachable**: no writer could emit a cohort-prefixed
  `chains.source_ref`, so the KPI returned `{"available":false,"reason":"empty_cohort"}`
  by construction.
  - **`ailang eval-suite --baseline <id>`** banks a run under an immutable cohort ref,
    writing `source_ref` as `<id>/<taskID>/<mode>[/<cond>]` — which the M1
    `SourceRefPrefix` filter matches, while `taskID` stays *embedded* so trace/task
    correlation survives the freeze. **The default (no `--baseline`) `source_ref` is
    byte-identical to before**, proven by a test rather than by inspection.
    `taskID`/`assignmentID`/`OTEL_RESOURCE_ATTRIBUTES`/`createEvalTask` are untouched:
    the baseline is a chain **cohort label**, not a correlation id.
  - **`--baseline` requires `--verify`** — a hard error raised before the rig lock, the
    API-key check, or any spend. A frozen cohort with no verification evidence can only
    ever produce `zero_denominator`, so refusing costs nothing and saves a metered run.
  - **Baseline-id charset pinned** to `^[A-Za-z0-9][A-Za-z0-9.-]*$`, validated by
    **one** validator shared by the freeze side and the query side. The id becomes an
    *unescaped* SQL `LIKE` pattern (no `ESCAPE` clause) where SQLite treats `_` as a
    single-character wildcard, so `v1_0` would silently also match `v1x0/…` and widen
    the KPI denominator with no error.
  - **`cohort_manifest.json`** in the run's output dir (+ a stable `cohort_hash`),
    closed out with `run_window.completed_at` at finalize. Every identity field is
    **derived** — `models[]` comes from `models.yml` via `expandModelSuite` →
    `GetAgentSuite()`; **nothing in Go names a model**. So a `models.yml` edit yields
    new members *and a different `cohort_hash`*: cohort drift is visible in the artifact
    instead of silent, and a re-freeze publishes as a **new** baseline id. The hash
    covers the cohort (sorted models/benchmarks/languages/conditions + mode, seed,
    prompt version, trials) and excludes run identity (timestamps, `git_commit`,
    `chain_id`), so re-freezing an unchanged cohort is recognisably the same cohort.
  - **Agent-mode contract verification now actually runs.** The only agent-mode
    `RunAICheck` call sat inside the legacy `RunAgentBenchmark()`, which had **no
    caller** (the live path is `RunAgentBenchmarkWithExecutor`). No agent run could ever
    bank `verify_verified > 0`, so `isVerifiedSuccess` was permanently false and the KPI
    would have returned `zero_denominator` *forever* — the freeze mechanism would have

### Added — Static "Ok contains a default/empty value" detection (M-CHECK-STRICT-FALLBACKS, `STRICT_FALLBACK_001`)

Static enforcement of the **NO SILENT FALLBACKS** principle. A `Result`-returning
function whose `Ok` branch carries an empty/zero value (`Ok("")`, `Ok([])`,
`Ok({})`, an all-zero record, a zero-valued constructor, or a known-empty builder
like `std/json.jo([])`) silently lies about success — the caller's `Ok(v) =>` arm
fires with zero data instead of falling through to `Err(e) =>`. This exact shape
shipped in `firestore/client@0.7.1` and returned all-zero data to customers with no
error signal.

- **Detector** (`internal/pipeline/strict_fallbacks.go`): runs over the elaborated
  Core **after name resolution**, mirroring `warn_split_args.go`. It keys on the
  resolved `$adt.make_Result_Ok` constructor identity, threads an `env` of enclosing
  ANF `let` bindings to resolve constructor args back through ANF (`Ok([])` →
  `let t = [] in make_Result_Ok(t)`), and classifies the resolved value. A curated
  `knownEmptyBuilders` registry keyed by module-qualified `core.GlobalRef`
  (`std/json.jo`, extensible like `swapTraps`) catches builder-empties **soundly** —
  a user-defined local `jo` is a plain `core.Var` and is never flagged.
- **Two channels**: **WARNING** under `ailang check` (exit 0, advisory in dev);
  **HARD ERROR** under `ailang check --package` (exit 1, the publish boundary) via a
  new `checkStrictFallbacks` gate mirroring `checkInterFunctionRefs`.
- **Opt-out**: `@allow_empty_ok("rationale")` annotation suppresses the diagnostic
  on a function where an empty-`Ok` is legitimate. The rationale string is
  **required** — missing/empty rationale is a parse error; it is the audit record.
- Bare `Ok(0)` / `Ok(false)` are NOT flagged (legitimate scalar success values);
  mixed records with a real field are NOT flagged; patterns in non-`Result`
  functions are NOT flagged.
- Ships `examples/strict_fallbacks_demo.ail`, `docs/docs/guides/strict-fallbacks.md`,
  and end-to-end tests driving the real `pipeline.Run` / `ailang check --package`
  binary. AILANG's own stdlib passes the audit with zero unannotated violations.

### Added — Cost-attribution rollup for `ailang chains` (M-MISSION-COST-CHAINS, M1)

`ailang chains` becomes the mission's cost tracker. A token-bearing stage that
never self-reported a cost previously rolled up as a misleading `$0.0000` "free"

- **unknown**: `tokens > 0`, `cost == 0`, model unresolvable → surfaced separately,

  banks) also surface as unknown, never as negative dollars.
- **quota**: `tokens == 0` — subscription/quota lanes, `$0`-by-design, NEVER
  estimated.

recovered per stage from `eval_assessment.model` then a child span's model

### Fixed — Effect budgets are per-function again, not cumulative across the call chain (M-BUDGET-SCOPING-BUG)

`@limit`/`@min` effect budgets were enforced **cumulatively over the whole
dynamic call chain**: a callee annotated `! {IO @limit=3}` failed if its caller
had already spent the budget, even when the callee performed only 2 of its own IO
operations. This contradicted the documented "at most N operations *for this
function*" meaning and left `examples/effect_budget_demo.ail` runtime-broken.

Budgets are now **hierarchical per-invocation frames**:

- Each call to an annotated function pushes its own frame; `@limit=N` bounds that
  invocation's own effects only. Recursion pushes an independent frame per call.
- Unannotated functions push no frame; their effects charge whatever annotated
  ancestor frames are active (budgets compose through unannotated intermediates).
- **Bubbling charge**: an effect charges the innermost frame and every active
  ancestor frame, so delegated effects still count toward an annotated caller
  (delegation cannot launder effects), while an annotated callee is also bounded
  by its own frame.
- **`@limit`** is checked **pre-op** against every active frame; on violation the
  op is rejected without mutating any frame and the error names the first
  violating frame innermost-to-outermost (tightest active limit wins).
- **`@min`** is checked at frame pop on **normal exit only**; on error/exceptional
  exit it is **suppressed** so the original error propagates unmasked.
- Frame pop is unwind-safe (`defer`-guarded at both evaluator call-sites), so a
  callee error can no longer leak a stale frame onto a sibling call.
- Also fixed two latent bugs this exposed: effect ops were charged **twice** (the
  runtime builtin wrapper *and* the builtin Impl/`effects.Call` both charged) —
  now charged exactly once; and **recursive** functions never carried their
  `@limit`/`@min` annotations (the `LetRec` `buildClosure` path did not populate
  them), so recursion escaped budget enforcement entirely.

Removed the obsolete cumulative machinery (`BudgetContext.Merge`/`Reset`/
`ChargeSemanticOnly`, `EffContext.WithBudgetLimits`/`PopScopeAndChargeCaller`/
`SetMinBudgets`/`CheckMinimums`) and its tests. `examples/effect_budget_demo.ail`
now runs to completion under `--caps IO` and is no longer run-skipped.

### Fixed — Effect rows preserved across pure nested calls (#386) (2026-07-22)

**P0 soundness regression.** Effect inference silently erased `IO` when an
effectful call received an argument containing a pure application (e.g.
`println(show(x))` or `println(intToStr(x))` inside an effectful `mapE`
callback), then a later `foldlE` failed with `incompatible closed rows: r1 has
extra labels [], r2 has extra labels [IO]`. Fixed under M-EFFECT-ROW-SHOW-INTERP
(mechanism ratified by the human architect):

- **Application-local effect resolution** (`inferApp`): each application solves
  the equality constraints its subtree added with the same unifier as
  `SolveConstraints`, then substitutes its argument effect rows *before*
  combining them, so a nested pure application (`show(x)`) resolves to `{}` and
  is no longer prematurely collapsed. The original constraints are left in place
  (not deleted), so the whole-program/let-boundary solve still propagates every
  unification to outer nodes. No `EffectJoin` type/constraint is introduced and
  `internal/types/row_unification.go` is unchanged.
- **Tail-preserving effect union** (`combineEffects`): stops dropping an
  unresolved effect-row tail to closed `{}`; a shared or single tail is preserved,
  stray non-effect (record) tails are dropped, and budgets/params/provenance
  survive the union.
- **Effect-validation walker** (`ValidateEffects`): now traverses `let`/`letrec`
  bodies (ANF/block lets carry a nested pure call's effect in the body) and
  enforces an inline lambda's declared effect row against its body's actual
  effects, so an effectful lambda annotated with a too-narrow row (e.g.
  `! {FS}`) passed as a combinator argument is rejected.
- **Row-variable generalization** (`generalizeWithConstraints` + `iface` builder):
  free effect-row variables are collected across the whole type and generalized
  under the HM environment side condition, and a row-polymorphic combinator's
  shared source row variable is restored at the interface boundary, so each use
  of `mapE`/`filterE`/`foldlE`/`flatMapE`/`forEachE` gets fresh row variables.
  The outer-effect-row restoration (`iface/builder.go`) now fires whenever an
  annotation contains **at least one** row variable — a pure `! {e}` **or** a
  mixed `! {Stream, e}` (`hasRowVarEffects`, replacing the narrower
  `isPureRowVarEffects`) — preserving the concrete label(s) as row entries while
  quantifying the shared row var, so a stream combinator whose outer effect names
  a concrete effect alongside `e` still flows an effectful handler through.
- **`std/stream`** (`selectEvents`/`onEvent`/`withStream`/`withSSE`) and
  **`std/ai/streaming.onEvent`**: their `handler` callbacks are now
  row-polymorphic (`(StreamEvent) -> bool ! {e}`, propagating `! {Stream, e}`),
  so an effectful handler can be passed (they previously required a pure
  callback). `std/list.ail` is unchanged.

`println(show(x))`/`println(intToStr(x))` now infer `{IO}` (never `{}`), and
unannotated helpers performing IO are correctly rejected with `Missing effects:
IO`. Four #386 examples returned to `working`: `effectful_list.ail`,
`effectful_list_t7_chain_combinators.ail`, `stream_multi_source.ail`,
`stream_process_source.ail` (`mcp_tools.ail` stays quarantined — separate
`Option[string]` issue).

### Added — `ailang fmt`: stable multi-line let-chain comment boundaries (M-AILANG-FMT-INLINE-INTERIOR)

`ailang fmt` Phase 2 previously fails-closed (exit 2, no output) whenever a comment
landed strictly inside a multi-line `let … in` chain, because the printer collapsed
the chain onto one inline line (`let x = v in let y = w in tail`) so a between-binding
comment had no stable boundary. That was the largest coherent refusal class:
**28 of 59 corpus refusals**.

This sprint adds a **printer-local conditional multi-line let-chain emitter** (design
Decision 1, option (a); parser/AST untouched):

- `internal/format/letchain.go` — a shared maximal-chain flattener (`flattenLetChain`)
  used by both attachment and emission, treating any `*ast.Let` with a non-nil `Body`
  as a chain root (including length-2 `let x = v in tail`).
- `internal/format/attach.go` — registers one child list owned by the root `*ast.Let`
  with explicit non-overlapping child spans (binding end = `subtreeEnd(binding.Value)`;
  the `in` has no AST position so it rides the separator). Only maximal chains register
  (no overlapping suffixes). A braced block whose sole expression is a let-chain no
  longer registers a competing one-child list.
- `internal/format/expr.go` + `decl.go` + `format.go` — `letIn` emits multi-line ONLY
  when the root let owns a comment attachment (`hasAnyAttachment`), interleaving the
  comments at their boundaries and writing `in` before a trailing comment so a `--`
  cannot swallow it. Comment-free and unattached input keep the exact old inline bytes.

Invariants preserved: `fmt(fmt(x)) == fmt(x)` (layout chosen from reconstructed
attachment ownership, never source line count), never-lossy (marker count preserved),
comment-free byte identity, and the strict-interior fail-closed guard for every
unsupported interior (unchanged — Decision 2).

**Result** (corpus gate, `go test ./internal/format/ -run TestCorpusCommentGate`):
comment-unattached refusals **59 → 32** (15.28% → 8.29%), the **let-chain-interior
refusal class is eliminated (0)**, with `marker-fail=0`, `PHASE2-rt-regression=0`, and
`preexisting-Phase1-rt-bug=0`. 27 of the 28 let-chain files now format losslessly; the
28th (`records.ail`) carries an additional deferred footer comment and stays fail-closed
on that comment (no-enclosing-list class, out of scope). The corpus refusal counter is
split into truthful construct classes (let-chain-interior / non-let-equation-body /
inline-tests-list / no-enclosing-list / other-interior).

### Added — `ailang fmt`: canonical AILANG source formatter (M-AILANG-FMT, Phase 1)

A new `ailang fmt [--write] [--check] <files...>` subcommand collapses AILANG's
equivalent statement-sequence spellings (equation `;`, braced `;`, braced newline)
into one stable canonical form. It is a presentation-only convenience, not a
correctness gate: `Parse(fmt(x))` is structurally identical to `Parse(x)` for every
accepted file.

- **New `internal/format` package** — an exhaustive AST-to-source printer over every
  concrete declaration, expression, type, pattern, effect, test, and property node.
  Public API: `Source(program, Options) ([]byte, error)` and `HasComments(source)
  (bool, error)`. Unknown / nil-required / `ast.Error` nodes and malformed literals
  fail loudly — there is **no** debug `String()` fallback. Parentheses are
  reconstructed from parent precedence (the AST has no `ParenExpr` node); redundant
  source parentheses are dropped. Cons `::` is re-emitted infix (it has no
  prefix/call re-parse). A single `;` is inserted only where a following block
  statement begins with a non-starter token (e.g. a bare `()` or tuple) that the
  parser would otherwise glue onto the previous statement — keeping the common case
  semicolon-free while preserving round-trip.
- **Canonical form** — braced newline-per-statement blocks with a bare final
  expression, single-expression equation bodies as `= expr`, explicit `let ... in`
  preserved, two-space indent, LF, one final newline, one blank line between
  top-level declarations, and original AST order (no reordering of imports, symbols,
  cases, fields, or declarations).
- **CLI** (`cmd/ailang/fmt.go`) — stdout (exactly one file), `--write` (1+ files),
  `--check` (1+ files), `--write`⊕`--check` mutual exclusion. `--write` validates
  every input in memory (comment preflight + parse + print + round-trip) before
  touching any file, then replaces each changed file atomically (same-directory temp

  strings, char literals, regex literals, and quasiquote templates. Lossless comment
  preservation is a separately-scheduled Phase 2.
- **Release-gate tests** — idempotence (`fmt(fmt(x)) == fmt(x)`) and structural
  round-trip (`Parse(fmt(x)) == Parse(x)`, go-cmp ignoring pos/span) over every
  comment-free `examples/**/*.ail` (21 files) plus generated cases; the three
  separator spellings format identically; explicit `let ... in` stays explicit.

### Fixed — `make fuzz-parser` CI flake: spurious `context deadline exceeded` on the fuzztime boundary (mission iter 50)

Dev CI went red on a **data-only** commit (`3556e9377`) with `FuzzParseExpr: context deadline
exceeded` — no parser code had changed in 7 days and the previous 11 runs were green. Root cause:
when `-fuzztime=2s` expires while a slow, deeply-nested input is still executing on a loaded CI
runner (4 workers vs 16 locally), Go's fuzzing coordinator cancels the worker context and reports
the cancellation as a test FAILURE even though no crasher was found. `make fuzz-parser` now
discriminates a real crasher (`Failing input written to testdata/fuzz/…` → fail immediately) from
the transient boundary timeout (`context deadline exceeded` with no crasher → retry once). A
genuine slow-parse regression that *always* times out still fails on the second attempt, so
crash-detection and perf-regression coverage are preserved.

### Fixed — `design-quorum` reasoning-model reviews truncated silently at the 4096-token cap (mission iter 43)

A reasoning reviewer (Gemini 3.x — "2× reasoning") whose thinking tokens count against
`maxOutputTokens` could exhaust the quorum's `reviewMaxTokens = 4096` cap mid-verdict, returning
a valid-but-cut-off JSON body. `ParseReviewResult` rejected it as "malformed JSON" and the
reviewer was silently dropped, degrading the two-provider quorum to N−1 (observed live mission
iter 42: `gemini-3-1-pro` `finishReason=MAX_TOKENS` on a substantive objection). Intermittent —
it fired cleanly whenever the review happened to be terse.

- **Root-cause fix:** `reviewMaxTokens` raised 4096 → 16384, leaving genuine thinking headroom
  above the ~1–2K structured verdict. Output is billed per actual token (a short verdict stays in
  cents) and the pre-flight budget cap uses a fixed `expectedOutputTokens` estimate, so the
  ceiling change does not alter budget gating (`internal/mission/quorum/call.go`).
- **Fail loudly (Principle 2):** a residual `finish_reason == "length"` truncation now surfaces as
  an explicit `"reviewer output truncated at N tokens … raise reviewMaxTokens"` error instead of an
  opaque parse failure (`internal/mission/quorum/run.go`).
- **Provider signal wired:** the Gemini `Generate` path was discarding `finishReason`; it now
  populates the normalized `ai.Response.FinishReason` (`MAX_TOKENS → length`, `STOP → stop`, safety
  reasons → `content_filter`) so all Gemini callers can see truncation
  (`internal/ai/gemini/generate.go`). Regression tests: `TestNormalizeGeminiFinishReason`,
  `TestRunReviewerWith_TruncatedOutputFailsLoudly`.

### Fixed — `design-quorum` cross-provider schema: OpenAI reviewers were silently dropped (mission iter 41)

The mission pick-time `design-quorum` gate ran with only ONE reviewer present on every
invocation, silently degrading a two-provider quorum to a single-provider veto. Root cause:
`internal/mission/quorum/reviewer.go`'s `reviewSchema` listed `proposed_fix` in `properties`
but deliberately omitted it from `required` (to keep it "optional"). OpenAI's strict
`json_schema` response-format mode **requires every property to appear in `required`** and
400s otherwise (`'required' ... must include every key in properties`), so every OpenAI
reviewer (e.g. `gpt5-6-sol`) was recorded as `unreachable` while only the laxer Gemini
reviewer ran.

- **Fix:** `proposed_fix` is now listed in `required` as a plain `string`. It stays optional
  by CONVENTION — a reviewer with no fix returns `""`, which `ValidateReviewResult` never
  inspects, so it validates byte-identically to the old omitted case; the parser also tolerates
  a missing/`null` value defensively.
- **Cross-provider constraint discovered + guarded:** a nullable `["string","null"]` union
  satisfies OpenAI strict mode but is rejected by Vertex/Gemini (`Proto field is not repeating,
  cannot start list`). A single plain `string` in `required` is the one form BOTH providers
  accept. Live-verified: both `gpt5-6-sol` and `gemini-3-1-pro` now `present`.
- **Regression guards:** `TestReviewSchema_OpenAIStrictInvariant` (every property must be in
  `required`; no union types) + `TestParseReviewResult_NullProposedFixPreservesContract`. The
  stale `TestReviewSchema_ProposedFixNotRequired` (which encoded the broken contract) was removed.

### Added — Inject a sprint diff bundle into a sandboxed gemini evaluator (M-GEMINI-EVALUATOR-DIFF-BRIDGE, M1–M3)

A policy-layer bridge (`internal/eval_harness/gemini_evaluator_bridge.go`) so a sandboxed

- **M1 — `BuildDiffBundle`.** Enumerates the changed-file set via
  `git status --porcelain -z` (modified + staged + **UNTRACKED** — new files are
  load-bearing: a sprint frequently CREATES files and `git diff` alone misses them),
  emits the tracked unified diff (`git diff` + `git diff --cached`, ALWAYS included /
  never dropped) plus `+++ NEW FILE:` views of untracked files, then appends full
  changed-file contents under a configurable **256 KiB** ceiling. Drop order:

  drop order).

  `json` verdict) + the design doc / plan / criteria + the bundle; a truncated bundle

  `quorum.ReviewResult`). `ParseGeminiVerdict`/`ValidateGeminiVerdict` hard-error on a
  malformed verdict (missing fence, non-JSON, score out of `[0,100]`, `pass==true` with
  blockers, degraded without a reason) — never a lenient/coerced pass. Fence parsing is
  shared via a new exported thin wrapper `LastFencedBlock` DELEGATING to the existing
  unexported `lastFencedBlock` (no rename of the extract-out call site).

  a stub — NO live Vertex call in the suite; the default `DefaultGeminiRunner` shells
  `ailang exec gemini --json`). The caller ENFORCES degradation: on bundle truncation OR a
  backend error it stamps `VerificationDegraded=true` with a reason, and a model/stub
  `pass:true` under degradation can NEVER stand as a real pass (CLAUDE.md "no silent
  fallbacks"). A backend error yields a degraded NON-PASS verdict carrying the error text,
  never a fabricated pass.

Ships the CAPABILITY only — routing gemini as the evaluator lives in
`m-mission-agentic-provider-routing.md` (out of scope) and the mission default stays
sonnet-5. Tests: `gemini_evaluator_bridge_test.go` (12 new, each references a symbol

### Fixed — `ailang verify` no longer crashes Z3 on cross-function callees over parametric ADTs (M-SMT-CALLEE-SORT-GATE)

A contracted function whose cross-function callee returns (or takes) a parametric ADT
over a primitive — e.g. `convertTo(...) -> Option[float]` — made `ailang verify` emit a
hard Z3 error (`unknown sort 'Option'`, `unknown constant convertTo (Real String)`,
exit status 1) instead of the promised graceful skip. Root cause: the fragment gate only
inspected `$builtin`/stdlib call *names*, never the signature *types* of a user callee, so
the callee leaked an undeclared sort into the SMT script. Reported via feedback (grader
`gradeNumeric` path).

**Primary fix (M1)** — a caller-side gate (`firstUnencodableCalleeType` in
[cmd/ailang/verify.go](../cmd/ailang/verify.go)) walks the cross-function call graph and,
before encoding, rejects any caller whose callee signature uses an unencodable *AST* type:
a parametric ADT application (`Option[float]`, `Result[e,a]`), a bare type variable, or an
undeclared bare name. The check is AST-based on purpose — the flattened SMT sort string
`"Option"` loses the `[float]` argument, and an imported parametric ADT is registered in
`adtTypes` yet can't be monomorphized, so a sort-string check wrongly passes it. Monomorphic
enums, records, lists, and primitives still verify unchanged. The function now reports
`SKIPPED` with a structured `UNENCODABLE_TYPE` reason naming the callee and offending type.

**Defense-in-depth (M2)** — `validateDeclarations` in
[internal/smt/codegen.go](../internal/smt/codegen.go) now also scans callee `(define-fun …)`
*signatures* (params + return, never the body) for undeclared sorts, returning
`ErrUnresolvableTypes` (→ graceful skip) so any leak that slips the caller gate still can't
reach Z3.

**Leak-site guard (M3, systemic)** — a follow-up report showed two more shapes still
hard-ERRORed with `unknown constant`: a callee returning a **record** (`canon(...) -> Rec`)
and a user function called inside a **contract predicate** (`ensures { legal(result) }`). Both
share one root cause: *any* user function referenced (in the body OR a requires/ensures
predicate) that `ResolveCallees` doesn't turn into a define-fun/contract-substitution falls
through `encodeApp` to `encodeConstructorApp` and emits a raw uninterpreted symbol. The fix
detects this at the leak site: `encodeApp` now knows the set of user function names
(`activeUserFunctions`) and, on an unresolved call to one, returns `ErrUnresolvableTypes` (→
graceful skip) instead of leaking. This single guard covers every drop path and both body +
contract positions; real ADT constructor applications are unaffected. Verified: `useCanon`
(record callee) and `pick` (`legal` in `ensures`) now SKIP; `useDbl` (int callee) and
`classify` (enum-in-ensures) still VERIFY.

Note this closes the *crash* for all known shapes — no contracted function hard-errors on an
unencodable cross-function callee anymore. It does not *extend* the fragment: actually
verifying record/enum-returning callees, user functions in contract predicates, or
`Option`/`Result`-over-primitive callees is future work (parametric-ADT monomorphization +
contract-callee inlining). New example
[`examples/runnable/contracts/unencodable_callee_skip.ail`](../examples/runnable/contracts/unencodable_callee_skip.ail),
unit + e2e tests (record-callee & contract-predicate-callee skip-not-error, leak-guard unit),
design doc `design_docs/planned/v0_30_0/m-smt-callee-sort-gate.md`.

### Added — Option/Result are prelude in entry modules, no import needed (M-PRELUDE-OPTION-RESULT)

`Option`/`Some`/`None` and `Result`/`Ok`/`Err` — the types AND their data
constructors — now resolve **without** `import std/option` / `import std/result`
in **entry modules** (a module with an exported `main`), at both `ailang check`
and `ailang run`. You can construct and pattern-match them directly:

```ailang
module m
export func main() -> () ! {IO} {
  match Some(42) { Some(x) => println(show(x)), None => println("none") }  -- no import
}
```

Previously this failed with `undefined variable: Some` — ~6% of recent
AI-authored compile failures were exactly this missing import. Models write
idiomatically-correct AILANG (Option/Result are in the standard prelude of
Haskell, Rust, OCaml, F#, Swift) and reasonably omit the import; this removes the
friction structurally rather than re-teaching every model.

**How:** entry modules implicitly import `std/option` + `std/result` at the
**loader** — the single call-site both the compile pipeline (`mod.File.Imports`)
and the runtime (`LoadedModule.Imports`) consume — so compile and runtime stay in
lockstep with **zero** changes to the type checker, elaborator, or runtime
resolver core. The injection reuses the existing constructor-import machinery
(selective import → `M-CTOR-AUTO` → `resolveConstructorImport` →
`findConstructorMatches`).

**Shadowing / precedence (lowest):** implicit imports are prepended and deduped.
A user's explicit `import std/option (…)` is left untouched; a local
`type Option[a] = Some(a) | None` or `type Result = Pending | Done` (different
constructors, same name) — or any local constructor whose name collides —
**shadows** the prelude cleanly (the colliding module is simply not injected), so
there is no ambiguous-constructor error at compile or runtime.

**Entry-only:** library modules (no exported `main`) are untouched and still
require explicit imports, keeping library code self-documenting. Helper functions
(`map`, `getOrElse`, …) still need an explicit import (only the type +
constructors are prelude). No `cacheKeyVersion` bump — no persisted `Iface`
struct changed; entry-module cache keys shift naturally because their dependency
set now includes the two implicit deps. Example: `examples/prelude_option_result.ail`.

### Added — parameterized type aliases substitute their arguments (M-XMOD-ALIAS-POLY)

A type alias may now take type parameters and be **used at a concrete
instantiation**: `type Box[a] = { items: [a] }` used as `Box[int]` type-checks
as `{ items: [int] }`. Previously the applied form reached unification as an
un-expanded `TApp{TCon("Box"), [int]}` and failed with
`cannot unify old record type with *types.TApp`. Now working, single-module and
cross-module, for every alias body shape:

- **record** — `type Box[a] = { items: [a] }` → `Box[int]`
- **bare param** — `type Ident[a] = a` → `Ident[int]`
- **tuple** — `type Pair[a, b] = (a, b)` → `Pair[int, string]`
- **function** — `type Fn[a, b] = (a) -> b` → `Fn[int, int]`
- **nested** — `Box[Box[int]]`

**How:** aliases now carry their parameter names (`AliasParams`) alongside the
body at every layer (elaborator, `iface.Iface`, type-checker, unifier), threaded
cross-module through the interface (JSON cache round-trip) and the import
resolver. `expandAlias` gained a `*TApp` branch that instantiates an applied
alias by substituting `param→arg` through the body (via the existing
`Type.Substitute` method, which recurses through record/tuple/function bodies)
and continues the fixpoint loop, so alias chains still resolve.

**Non-regression (critical):** expansion is keyed **strictly on alias-env
membership**, so genuine parameterized ADTs (`Option[a]`, `Result[a, b]`, a user
`type Tree[a] = …`) — whose head constructor is registered as a constructor, not
an alias — are **never** instantiated and stay nominal. Locked by tests.

**Arity mismatch** (`Box[int, string]` on a 1-param alias, or a nullary alias
applied with args) now fails with a coded, directional diagnostic
`TC_ALIAS_ARITY_001` (styled on `TC_ARITY_001`) instead of a generic unification
error. Adding a parameterized alias is **digest-neutral** (no dependent-package
cascade), locked by the digest test. `cacheKeyVersion` bumped `v2 → v3`
(on-disk `Iface` gained `AliasParams`). Example: `examples/type_alias_poly.ail`.

### Fixed — lambda `{field, ...}` open-record patterns now propagate row polymorphism (M-LAMBDA-OPEN-RECORD-PATTERN)

`\obj. match obj { {name, ...} => name }` previously inferred a **closed** parameter
`{name: τ}` instead of the **open** `{name: τ | r}` the user asked for with `...`, so a
caller passing a record with extra fields was rejected — even though top-level
`let … in match` already worked, and the error's own Hint told the user to write
`{name, ...}`, which they already had. Fixed across three coordinated sites:

- **`core.RecordPattern` gains a `Rest bool`** (was erased at the AST→Core boundary);
  the elaborator now propagates `p.Rest`.
- **`checkPattern` honors `Rest`** for an *unresolved* scrutinee (a lambda parameter):
  an open pattern builds a `{fields | freshRow}` constraint; a closed `{name}` builds a
  `Row: nil` (closed) constraint so it STILL rejects extra fields. A *resolved* record
  scrutinee keeps subset-matching semantics unchanged.
- **Record unification does row-polymorphic subsumption** (`unifyOpenRecords`): the old
  `TRecord ~ TRecord` path rejected any field-count difference *before* consulting row
  variables, so an open `{name | r}` param vs a `{name, id}` caller failed a length check
  and never reached row unification. Now, when either side is genuinely open (row tail
  unbound — a helper disambiguates the overloaded `TRecord.Row`, since even closed literals
  carry a `*Row{Tail:nil}`), common fields unify and each side's extra fields flow into the
  other side's extension row. The strict length check is kept ONLY for closed~closed.

Soundness preserved (regression matrix, 7 tests in
`internal/pipeline/lambda_open_record_test.go`): open+extra PASS, open+matching PASS,
closed+matching PASS, **closed+extra FAIL**, IIFE+extra PASS, **open+missing-field FAIL**,
and the misleading hint no longer fires on the fixed reproducer. `examples/runnable/record_patterns.ail`
restored to use `{name, ...}` in a lambda with an extra-field caller.

### Added — coded, directional arity diagnostic `TC_ARITY_001` (M-ARITY-STYLE)

- Calling a function with the wrong number of arguments now emits a **coded,
  directional, style-aware** diagnostic instead of the bare
  `function arity mismatch: 2 vs 1`. The message carries the greppable code
  `TC_ARITY_001`, states how many arguments the function expects vs how many were
  provided, and adds a `Suggestion:` line naming the fix:
  ```
  TC_ARITY_001: function expects 2 argument(s), but 1 provided
    Suggestion: AILANG has no partial application — call with all 2 arguments, or wrap in a lambda `\a b. f(a, b)`.
  ```
  - **Under-supply / partial application** (`add(1)` or `let inc = add(1)` on an
    arity-2 `add`) names AILANG's no-partial-application rule.
  - **Over-supply** (`add(1, 2, 3)`) tells you to remove the extra argument(s).
- **Diagnostic-only** — no arity semantics change. Strict arity and
  no-partial-application are preserved; no program that compiled before stops
  compiling, and curried↔tupled unification still works. The code + hint are
  inline in the message (mirroring the `TC_REC_00X` convention) because the
  unification error is plain-`%w`-wrapped and never recovered via `errors.As`.
- Documented in [docs/docs/reference/errors/index.md](../docs/docs/reference/errors/index.md).
  Golden tests: `internal/types/arity_diagnostic_test.go`.

### Added — compile-time warning for reversed `split` arguments (M-DX-SPLIT-ARG)

- The compiler now emits a **non-blocking** warning when it detects the reversed
  `split` footgun: `split("/", name)` where the first arg is a short (1–3 rune)
  string literal and the second arg is not a literal. `split(s, delimiter)` is
  **data-first**, so `split("/", name)` silently splits the literal `"/"` by the
  contents of `name` and returns the 1-element list `["/"]` instead of the parts.
- The warning names the exact call site and suggests the fix:
  ```
  warning: split(s, delimiter) takes the string first, delimiter second.
    --> app.ail:8:20
    = hint: did you mean split(name, "/")?
    = note: split("/", name) splits "/" by name, which likely returns ["/"]
  ```
- Both `ailang run` and `ailang check` surface it (and `check` now renders pipeline
  warnings, which it previously dropped). The program **still compiles and runs** —
  this turns a silent wrong result into a visible diagnostic (A11 Structured Failure).
- **Why models get this wrong**: `join(delimiter, xs)` is separator-first while
  `split(s, delimiter)` is data-first — inverse operations with **opposite** arg
  orders — and both args are `string`, so the type system can't catch a swap.
  Observed twice in AI-generated AILANG code.
- **Extensible**: the detector is a `swapTraps` table keyed by imported symbol
  (`internal/pipeline/warn_split_args.go`); only `std/string.split` is armed today.
  A user-defined local `split` never triggers (module-guarded on the resolved
  `std/string.split` reference).
- New runnable example **`examples/runnable/split_argument_order.ail`** demonstrates
  the wrong-vs-right call end-to-end (the reversed call yields 1 part, the correct
  call yields 3) with the join-vs-split ordering teaching in its header.
- Implements the split heuristic without a runtime or type-system change; see
  `design_docs/planned/v0_29_0/m-dx-split-argument-warning.md`.

### Added — `std/json.asBoolLoose`: boundary-tolerant boolean decode (M-DX-JSON-BOOL)

- New helper **`asBoolLoose(j: Json) -> Option[bool]`** for the *system-boundary*
  case where an external API may hand a boolean back as either a JSON boolean or a
  stringified `"true"`/`"false"`. It accepts `JBool(b)` **or** `JString "true"/"false"`;
  anything else is `None` — a **structured failure, never a silent default** (CP2).
- **Why**: booleans must be encoded with `jb(b)` (→ JSON `true`), *not* `js("true")`
  (→ JSON `"true"`). The two are different JSON values, and `asBool` only accepts the
  real boolean, so a value written the wrong way — or normalised by an API like
  Firestore's `booleanValue` — reads back as `None` and is silently treated as false.
  `asBoolLoose` is the liberal-in-what-you-accept decoder for exactly that boundary;
  keep using `asBool` for values you control.
- New runnable example **`examples/runnable/json_bool_encoding.ail`** demonstrates the
  `jb` vs `js` footgun and the `asBool`/`asBoolLoose` distinction end-to-end.
- Regression test `internal/repl/json_asboolloose_test.go` reproduces the Firestore
  `{"field":{"booleanValue": …}}` round-trip for both boolean and stringified shapes.
- **Scope note**: this landed the in-repo half of M-DX-JSON-BOOL. The original
  package-level encoder bug (`sunholo/firestore/fields` using `js("true")`) lives in
  the separate `ailang-packages` repo and is parked for a coordinator task there.

### Fixed — foreign-constructor error now lists transitively-known constructors (M-MATCH-XCHECK-ERROR-QUALITY)

- When a `match` arm uses the wrong ADT's constructor, the error already named
  both ADTs and the offending constructor. But the `<scrutinee ADT>'s constructors
  are:` suggestion line was **empty** whenever the scrutinee's ADT was known only
  *transitively* — e.g. `std/json.asNumber` returns `Option[float]`, but a module
  that imports only `std/result` (not `std/option`) matched it with `Ok`/`Err`.
  The typechecker knew the scrutinee was `Option` yet couldn't enumerate `Some`/
  `None` because they weren't in the direct-import constructor map.
- Fix (design doc Option A): a **diagnostic-only** constructor→ADT registry sourced
  from every transitively-loaded module interface, consulted **only** for the error
  message when the direct/local map has no entry for that ADT. The offending case
  now reads `Option's constructors are: None, Some` with a matching `did you mean
  one of: None, Some?` hint. The registry never brings constructors into scope — a
  module that hasn't imported `std/option` still cannot call `Some(x)`; the message
  is purely a suggestion. Cosmetic/UX only; correctness was already sound.

### Added — `std/regex`: linear-time (RE2) regular expressions (M-STDLIB-REGEX)

- New stdlib module **`std/regex`** backed by Go's `regexp` package (the RE2
  engine): matching is **guaranteed linear-time with no backtracking**. The
  classic catastrophic pattern `(a+)+$` against a long non-matching input — which
  makes PCRE/Python/JS blow up exponentially — returns in microseconds. This
  closes the regex half of the v1.0 orchestration bar (clause 4).
- Two-stage API (like `std/json`'s `decode -> Result`): `compile(pattern) ->
  Result[Regex, string]` is the **only** fallible entry point; once you hold a
  `Regex`, the match functions are total — `isMatch`, `findFirst`
  (`Option[RegexMatch]`), `findAll` (`[RegexMatch]`), `replaceAll` (Go `$1`/
  `${name}` replacement syntax), `split`. All `pure` (`! {}`), usable in contracts.
- **RE2 subset is the documented contract**: no backreferences, no lookaround —
  these are what RE2 drops to guarantee linearity. `compile` returns `Err(message)`
  for them (and for any invalid pattern), **never a panic** (CP2). See LIMITATIONS.
- Capture groups: `RegexMatch` exposes the whole-match span + per-group spans +
  text; `groups[0]` is the whole match, `groups[i]` is capture group `i`;
  non-participating optional groups report `start = -1`. **Match spans are RUNE
  indices**, consistent with `std/string` (Go's byte offsets are converted).
- Compile is memoized Go-side (mutex-guarded cache keyed by pattern string) — pure
  memoization, invisible to AILANG semantics, deterministic. Axiom net +8
  (A1/A5/A9: linear-time removes the ReDoS footgun and keeps cost analyzable).
- Examples: `examples/regex_basics.ail`, `examples/regex_capture.ail`,
  `examples/regex_log_orchestration.ail` (the orchestration use case — parse +
  route structured log/LLM lines).

### Added — `std/net`: RFC-3986 URL parsing (`parseUrl` / `parseQuery`) (M-STDLIB-URL-PARSE)

- `std/net` gains two **pure** URL-parsing functions backed by Go's `net/url`
  (the reference RFC-3986 parser) — the *inverse complement* of the existing
  `urlEncode`/`urlEncodeForm`. This closes the **URL-parse half** of the v1.0
  orchestration bar (clause 4); the regex half shipped alongside (above).
- `parseUrl(s) -> Result[Url, string]` splits a URL into a flat record
  `Url = {scheme, host, port, path, query, fragment : string}`. `port` is `""`
  when absent (Go `url.Port()` semantics — no `-1`/`0` sentinel); `host` is the
  hostname only (no port, **no brackets for IPv6**: `http://[::1]:80/` →
  `host="::1"`); `path`/`fragment` are percent-decoded; `query` is the raw
  substring after `?` (still encoded — feed to `parseQuery`). Malformed input
  (invalid `%`-escape, control char, bad port) returns `Err(message)`, **never a
  panic** (CP2) — one fallible boundary, the record fields are then total.
- `parseQuery(s) -> [{name, value}]` decodes a query string into
  order-preserving `{name,value}` pairs (values percent-**DECODED**) — the inverse
  of `urlEncodeForm`. Deliberately **not** Go's `url.ParseQuery` (a sorted map):
  it parses the raw string to **preserve source order and duplicate keys**
  (`a=1&a=2` → two entries). A bare key (`flag`) → `{name:"flag", value:""}`;
  the empty string → `[]`. Total — never fails.
- Both `pure` (`! {}`, `IsPure: true`) — **no `Net` capability** despite living in
  `std/net` (parsing reaches no network); usable in contracts and pure code.
  `parseQuery(urlEncodeForm(pairs))` round-trips (modulo `urlEncodeForm`'s
  alphabetical key sort). Axiom net **+8**.
- Examples: `examples/url_parse_basics.ail` (parse + all six fields),
  `examples/url_route_dispatch.ail` (the orchestration use case — route on host,
  dispatch on path, branch on a query param).
- Design: [`m-stdlib-url-parse.md`](../design_docs/planned/v0_30_0/m-stdlib-url-parse.md).

### Added — Forgiving statement separators: newline-as-soft-separator in blocks (M-SYNTAX-AI-FORGIVING R2)

- A **newline** before a statement-starter (`let` / `letrec` / `if` / `match` /
  identifier) now separates statements inside a `{ }` block, not only `;` — the
  form small models naturally write. This relaxes the **PAR020** "missing ;"
  failure class to the genuinely ambiguous same-line case *without changing the
  model*.
- Additive and **backward-compatible**: a newline-separated block parses to the
  same `ast.Block` the `;`-separated block does. The rule is line-aware
  (`peek.Line > cur.Line`, the M-GAP2 precedent) AND requires a statement-starter,
  so multi-line *expressions* (`{ 1\n+ 2 }`, operator continuations) are never
  split. Record literals / record-updates use commas and are detected up front, so
  the newline rule never reaches a record body.
- **Systemic fix**: patched all block statement-loops — `parseFunctionBody`,
  `parseBlockOrExpression`, and both loops in `parseRecordLiteral` (the LBRACE-
  prefix path that `if/then` blocks and `\`-lambda bodies take). **PAR020** is
  preserved for the genuine same-line no-`;` case at both guard sites.
- Enforced by the same corpus AST-diff fuzz gate (`AILANG_CORPUS_FUZZ=1`): every
  currently-valid `benchmarks/**/*.ail` + `examples/**/*.ail` file (389 of 400)
  produces a byte-identical AST under R2. Follow-up: a canonical formatter is
  deferred to [`m-ailang-fmt.md`](../design_docs/planned/v0_29_0/m-ailang-fmt.md).
- Design: [`m-syntax-ai-forgiving.md`](../design_docs/implemented/v0_30_0/m-syntax-ai-forgiving.md).

### Added — Forgiving statement separators: `;`-sequences in `=` bodies (M-SYNTAX-AI-FORGIVING R1)

- The parser now accepts a `;`-separated statement sequence directly in an
  equation-form (`=`) function body — `func f() = s1; s2; e` — the form small
  models naturally write. This eliminates the **PAR017** parse-failure class
  (~32% of small-model failures, directional) *without changing the model*.
- Additive and **backward-compatible**: a multi-statement `=`-body parses to the
  same `ast.Block` a braced `{ ... }` body produces, so elaboration and typing are
  unchanged; a single-expression `=`-body is unchanged. The sequence stops at a
  top-level declaration boundary (`export | type | import | extern | @ | pure |
  func IDENT | EOF`), while an anonymous-function expression `func ( ... )` in the
  body is never cut (M-TAINT guard).
- Implementation: `parseEquationBody()` + `peekIsDeclBoundary()` in
  `internal/parser/parser_func.go`. Backward-compatibility is enforced by a corpus
  AST-diff fuzz gate (`internal/parser/corpus_astdiff_test.go`, run with
  `AILANG_CORPUS_FUZZ=1`): every currently-valid `benchmarks/**/*.ail` +
  `examples/**/*.ail` file (389 valid of 399) produces a byte-identical AST under
  the new parser. Example: `examples/runnable/syntax_ai_forgiving.ail`.
- Design: [`m-syntax-ai-forgiving.md`](../design_docs/implemented/v0_30_0/m-syntax-ai-forgiving.md).

### Fixed — Windows CI: riglock dead-holder steal used Unix-only PID probe

### Fixed — module-less file silent-success footgun (`MOD014`) (M-MODLESS-FAIL-LOUD)

- A `.ail` file with top-level function declarations (`export func main …`) but
  **no `module` declaration** used to type-check clean, print `✓ Running`, and
  **exit 0 with no output** — the entry never ran, because a module-less file
  exports nothing and the runner fell through to a non-module print of unit. The
  worst possible signal for an AI author, and it silently sank any model-generated
  solution that omitted the module line (empty-stdout failures with no cause).
  This is exactly the "NO SILENT FALLBACKS — FAIL LOUDLY" anti-pattern.
- `validateModulePath` (the shared check/run/eval/test chokepoint) now emits
  **`MOD014`** when a module-less file has top-level `Funcs`:
  `Error MOD014: no 'module' declaration — this file has top-level declarations
  but no module, so nothing is exported and the entry never runs. Fix: add
  'module <canonical/path>' as the first line of the file`. Both `ailang run` and
  `ailang check` fail loudly (exit ≠ 0).
- Gated on top-level `Funcs` **only**: a bare-expression file (`1 + 1` → `2`) has
  no `Funcs` and still evaluates. (`MOD011` was already the module-path-collision
  code, so this uses the next fresh `MOD014`.)
- Remediated the one affected corpus file (`examples/runnable/block_demo.ail`,
  now `module examples/runnable/block_demo`). Added a footgun-coverage fixture
  (`internal/diag/footguns.md` + `footgun_fixtures_test.go`).

### Fixed — unresolved uppercase identifier in pattern position was a silent catch-all (#323)

Originally filed as "imported `std/list.nth` returns None inside recursive functions" — root cause
was neither `nth` nor recursion. In `elaboratePattern` (`internal/elaborate/patterns.go`), a bare
identifier not found in the elaborator's constructor table silently fell back to a **variable
pattern**, which matches everything. So in any module that didn't import Option's constructors
(e.g. only `import std/list (nth)`), `match nth(xs, i) { None => ..., Some(v) => ... }` bound the
`Some(7)` value to a variable named "None" and always took the first arm — while Some-first arm
order happened to work, making the bug look recursion/nth-shaped. Fix: an uppercase identifier in
pattern position now ALWAYS elaborates as a nullary constructor pattern (constructors are enforced
UpperCamelCase at declaration, so uppercase-as-variable is never legitimate), matching how
constructor patterns *with* arguments already behaved; and a bare KNOWN non-nullary constructor
(e.g. `Some` without arguments) is now a compile error carrying the fix instead of a silent
catch-all. Regression coverage: elaborate unit tests, `examples/option_pattern_import_free.ail`
(run by verify-examples), and `benchmarks/frontier_refs/bytecode_vm_trace.ail` (None-first +
unimported Option + recursion, byte-exact expected output). Tier-distribution drift tests
re-centered for the 8 new stretch benchmarks (stretch 14 → 22).

### Added — linux/arm64 (aarch64) release binary

The release pipeline had **never** built a Linux ARM64 binary — the build matrix in `.github/workflows/release.yml` only produced `linux/amd64`, `darwin/amd64`, `darwin/arm64`, and `windows/amd64`. But the official installer (`docs/static/install.sh`) already maps `aarch64|arm64 → arm64` and constructs the URL `linux.arm64.ailang.tar.gz`, so every aarch64 Linux user (AWS Graviton, ARM VMs, Raspberry Pi, Apple-Silicon Linux guests) hit a `404` on install — the installer promised an asset the release never produced. Added a `linux/arm64` matrix entry (cross-compiled from `ubuntu-latest`, pure Go / no cgo → statically-linked ELF, version-stamped and cosign-signed identically to every other artifact). The changelog download block now lists both Linux architectures. v0.26.0 could not be backfilled because GitHub immutable releases cryptographically lock a published release's assets (HTTP 422 on upload); this is the first release to ship the binary. Reported by an external tester on aarch64 Linux.

### Fixed — A hung motoko could silently wedge the whole eval rig for hours (M-MOTOKO-RIG-WEDGE-FIX)

The motoko executor's main run (`internal/executor/motoko/motoko.go`) called `cmd.Run()` on the *incoming* ctx, which carries no per-benchmark deadline — unlike claude/codex/opencode/pi, motoko had **no timeout enforcement on its main run** (only the 5s `--version` probe). So a hung motoko subprocess blocked `cmd.Run()` forever, which also hung the eval-suite goroutine waiting on it. Because motoko's env-server binds the **fixed `ENV_PORT=8080`**, the hung run's env-server then squatted 8080, and every *later* motoko spawn — the rotation's own remaining trials and any concurrent eval — crashed with the cryptic "terminated without emitting run_summary" (it couldn't bind its env-server → 0-event JSONL). Observed 2026-06-29: one hung rotation trial wedged the rig for **10 hours, 0 results banked**, and crashed an unrelated gate A/B 5/5; ollama and the model were healthy the whole time. Fix (AILANG-side defense in depth; the proper upstream fix is an ephemeral env-server port): (1) **bound the run** with `timeoutSeconds` + a hard 3h fallback ceiling so `cmd.Run()` can never block forever; (2) **`Setpgid` + a group-kill `Cancel`** (new `procgroup_{unix,windows}.go`, mirroring `eval_harness/process_*.go`) so the timeout reaps the env-server child instead of orphaning it on 8080; (3) **pre-flight `clearStalePort8080()`** kills an orphaned `bun src/tui` still holding 8080 before spawning (at `--parallel 1` any holder is a leftover), turning a silent 5/5 cascade into self-healing. New `procgroup_unix_test.go` proves ctx-timeout → group kill → child reaped + bounded run.

### Fixed — Eval harness graded an isolated re-stubbed file, not the model's workspace (M-EVAL-RELIABLE-GRADING)

Agent-mode grading re-seeded `input_files` into a *fresh* workspace — re-stubbing the very module the agent was told to implement — and ran `benchmark/solution.ail` in isolation. So a correct multi-file solution could only pass by **ignoring the task** and inlining everything into `solution.ail`; the score measured "did the model guess the solution.ail convention," not "did it implement the task." Proven by `docx_reimplement`: a local model implemented `docx_parser.ail`, verified `ailang run --entry main main.ail` produced **byte-for-byte golden output**, and still scored FAIL ("entrypoint 'main' not found" on the discarded `solution.ail`); `markdown_reimplement` passed only by luck (it happened to inline). Fix (opt-in, additive): `BenchmarkSpec.GradeEntrypoint` + `SolutionFiles` — `validateSolution` now grades the agent's **preserved** workspace by re-seeding every input_file *except* `solution_files` (restoring the harness-owned probe + fixed deps, keeping the agent's implementation) and running the probe against it; failures are attributable to the model (compile error or wrong output), never a missing-entrypoint artifact. Benchmarks without `grade_entrypoint` (the 74 single-file suite) take the unchanged legacy path. End-to-end: `docx_reimplement` + `markdown_reimplement` now grade **2/2 PASS** on motoko-local (docx was a measurement-artifact FAIL). New `grade_workspace_test.go` (correct impl PASS / wrong impl FAIL) + benchmark self-check. See [m-eval-reliable-grading](../design_docs/planned/m-eval-reliable-grading.md).

### Added — Multi-file reimplement benchmarks + executor `agent_env` (M-EVAL-REIMPLEMENT-BENCH)

`markdown_reimplement` and `docx_reimplement`: multi-file benchmarks where the agent reimplements a stubbed parser module against seeded dependencies, exercising `MOTOKO_AST_AUTOREAD` (compact dependency interfaces — the M-IFACE-COMPACT-ADT-FIELDS path) on a long, real task. Required `BenchmarkSpec.AgentEnv` (per-benchmark env exported to the agent subprocess, `${WORKSPACE}` expansion) routed through the **executor** path (`executor.Task.ExtraEnv` → `BuildEnvironment`, applying to every executor uniformly). The original injection sat in the dead legacy `RunHeadlessSessionStreaming` path, so `MOTOKO_AST_AUTOREAD` silently never reached executor agents (motoko/opencode/pi) and AST-autoread stayed off — diagnosed via a file-probe (the eval harness swallows agent stderr) and fixed; validated end-to-end (`proc.MOTOKO_AST_AUTOREAD="1"`, dependency reads return the 2138-char compact iface vs 6500-char full source).

## [v0.26.0] - 2026-06-26

### Added — Hex, binary, and octal integer literals

AILANG integer literals now accept radix prefixes — `0xFF`/`0XFF` (hexadecimal), `0b1010`/`0B1010` (binary), `0o17`/`0O17` (octal) — in addition to decimal. The lexer (`readNumber`) recognizes the prefix and reads the radix digits as a single `INT` token; the parser converts via Go's base-0 auto-detection, with **decimal kept on base 10** so a leading-zero decimal (e.g. `0123`) stays `123` and is never silently reinterpreted as octal. Surfaced as a root cause by the motoko docx harness: a local model reimplementing a DOCX parser needed Unicode private-use codepoints (`0xE000`–`0xF8FF`) and wrote `0xE000` (valid in nearly every other language), which previously failed with `PAR020` — the model then fell into a `sed`/`python`-via-BashExec edit loop trying to convert hex to decimal until the step budget exhausted. Supporting what models naturally write removes the wall. New `examples/integer_literals.ail`, lexer test (`TestHexBinOctalLiterals`), and parser test (`TestParseIntLiteralValue`, incl. the leading-zero-decimal regression).

### Fixed — `iface --compact` now carries ADT constructor fields (M-IFACE-COMPACT-ADT-FIELDS)

`ailang iface --compact` — the token-efficient interface motoko's `MOTOKO_AST_AUTOREAD` serves when an agent reads a *dependency* `.ail` module — rendered sum-type constructors as bare names (`type Block = HeadingBlock | TextBlock`) and leaked the Go-internal `<*types.TRecord>` for record return types. An agent implementing a parser whose job is to *construct* ADT variants couldn't learn the constructor shapes from the interface and fell back to `cat`-ing the full source (observed: 11 cat-fallbacks in a docx eval run), defeating the compaction. Now: the iface `ConstructorInfo` carries `FieldTypes` (threaded from the elaborator through `convertToIfaceConstructors`); `formatTypeCanonical` renders records structurally (`{label: type, ...}`, cycle-safe via a depth guard) or by nominal name; and the normalized-JSON constructor entries are full signatures — so the compact interface shows `HeadingBlock({level: int, text: string})` and `simpleCell : (string)->TableCell` instead of bare names and `<*types.TRecord>`. Interface digests for ADT/record-bearing modules change accordingly (constructor field types are part of the public interface). New tests in `internal/iface/compact_adt_fields_test.go`. See [m-iface-compact-adt-fields](../design_docs/planned/m-iface-compact-adt-fields.md).

### Fixed — duplicate approval notifications under Pub/Sub at-least-once (M-SECRET-EFFECT)

The coordinator's `/pubsub/push` approval bridge forwarded *every* delivery to ntfy, so Pub/Sub's at-least-once redelivery (push subscriptions can't use exactly-once) produced duplicate phone notifications for the same approval. The bridge now suppresses duplicates by Pub/Sub message ID (atomic mark-before-forward, un-mark on send failure so genuine retries still push; 1-hour TTL, lazy prune). The request and its confirmation are distinct publishes (distinct IDs) and are unaffected.

### Changed (breaking) — `secret(ref, purpose)`: approval requests now carry a reason (M-SECRET-EFFECT)

`secret()` now takes a required second argument, a human-readable **purpose**, surfaced in the phone approval request so the operator knows *why* a secret is being requested — `secret("op://Prod/stripe/api-key", "charge order #1234")`. Previously `secret(ref)` defaulted the purpose to the reference itself, so the notification showed the `op://` ref twice with no context. Breaking: the stdlib signature is now `secret(ref: string, purpose: string) -> string<secret> ! {Secret}` (and the `_secret_read` builtin is 2-arg); existing single-arg calls must add a purpose. The remote-approval notification was also reworked to a clear multi-line body (requested-by / secret / purpose / task / decision-window). Examples, the builtin-types golden, and tests updated. See [docs/guides/secret-approvals.md](../docs/docs/guides/secret-approvals.md).

### Security — Static IFC enforcement: `<secret>` leaks are now compile errors (M-SECRET-EFFECT M5/M6)

M-TAINT-TYPES (v0.16.0) shipped the information-flow label lattice and parsing but never enforced it — `CheckSinkRefinement`/`CheckDeclassify` had **zero callers**, so a `<secret>` value could reach a `{not secret}` sink with no error (verified empirically: a deliberate leak passed `ailang check` clean). M5 closes that gap with `CheckModuleIFC` (`internal/types/ifc_check.go`), a self-contained post-typecheck analysis over the surface AST that enforces two rules over the label lattice: **(A) sink refinement** — a value labelled `<ℓ>` may not reach a `T{not ℓ}` parameter; **(B) declassification** — a function may not hide body taint behind a cleaner explicit return label without `! {Declassify}`. Sources are explicit `<ℓ>` annotations plus the `secret()` builtin; unannotated functions are label-transparent (join of arg labels), so ordinary code needs no annotations. The pass emits standard `TypeCheckError`s (`SinkRefinementError`, `DeclassifyRequiredError`) and **never injects `TLabelled` types into CoreTI/codegen** — labels stay confined to the type layer, so there is zero runtime cost and no regression surface in the HM core or backend. `secret()`'s stdlib signature now honestly declares `-> string<secret>`. Scope: intraprocedural sink enforcement with source-label propagation within a module (cross-module sink flow remains Z3-contract-backed, deferred to M-TAINT-TYPES Phase 2); `inbox_injection_v2.ail` is unchanged (no `{not ℓ}` typed sinks there). New worked examples `examples/runnable/secrets/{gated_secret,leak_attempt}.ail` (the safe declassify pattern vs. the rejected leak), 14 unit tests (deterministic at `-count=20`), guide updated ([ifc-labels.mdx](../docs/docs/guides/ifc-labels.mdx)). Deferred from M6: the `approved(ref)` Z3 contract predicate (approval is inherently a runtime property; tracked as Phase 2). See [design_docs/planned/v0_26_0/m-secret-effect-remote-approval.md](../design_docs/planned/v0_26_0/m-secret-effect-remote-approval.md).

### Changed — Eval grading: boolean-case + numeric-format parity (M-EVAL-OUTPUT-NORMALIZE)

Sibling of M-EVAL-JSON-COMPARE. The v0.25.0 baseline revealed that **32 of 83 Python stdout failures (39%) across all 11 models** were pure `True`/`False` vs expected `true`/`false` casing — Python emits native booleans, benchmarks expect AILANG/JSON-style lowercase — plus a tail of numeric formatting (`7.50` vs `7.5`, `16.0` vs `16`). `CompareOutput` gained a third, **safe-by-construction** branch (after the exact and JSON paths): a **per-line** normalized comparison that case-folds standalone booleans, canonicalizes decimal trailing-zeros/integer-float, and removes whitespace adjacent to structural punctuation (`[1, 2, 3]`==`[1,2,3]`). It can only turn a *fail into a pass* when the normalized forms are exactly equal — a different line count (verbose/extra output) or a wrong value/structure (a Python set `{1,2}` is **not** equated to a list `[1,2]`) still fails, so genuine misses keep failing. Verified by `TestCompareOutput_Normalization` (positives + safety negatives). New `tools/eval-regrade` re-applies the grader to a stored baseline's `stdout`/`expected_stdout` with **monotonic** semantics (recovers false-negatives, never removes a stored pass) — re-grading the v0.25.0 baseline recovered **44** results, moving field Python **85.5%→92.1%** (AILANG ~93%, essentially even), with zero genuine downgrades. The re-grade also surfaced **1** pre-existing runtime-grader leniency (a verbose repair output stored as a pass) flagged for separate investigation. See [design_docs/planned/m-eval-output-normalization.md](../design_docs/planned/m-eval-output-normalization.md).

### Added — ELO ratings: persistence, mode-separation, selective rerun + saturation report (M-EVAL-RATING-EFFICIENCY)

The eval rig now derives benchmark *difficulty* and model *capability* from ELO ratings instead of hand-assigned tiers, and spends compute where it buys information. **ELO engine** (`internal/eval_harness/ratings.go`): `FitFromTrials` fits converged, deterministic ratings over a baseline (a PASS = the model beating the benchmark). **Persistence** (`internal/observatory` v16 migration): `benchmark_ratings`/`model_ratings`/`trial_history` tables, **mode-separated** (`mode` in the primary key) because standard and agent are different difficulty regimes — agent saturates, so a combined fit falsely ranks agent harnesses top. **`eval-suite --benchmarks-by-confidence <db>`** picks the most informative, non-saturated benchmarks for the run mode (drops the Trivial band, ranks the rest by proximity to the field's median rating) — a "did this morning's fix help?" check becomes a handful of benchmarks, not a full rotation. **`eval-trend tier-saturation`** renders a per-mode saturation report with demotion candidates + recommendation. On the regraded v0.25.0 baseline: standard model ELO has **claude-fable-5 #1 (2154)**; standard is 24% saturated (still discriminating) while **agent is 68% saturated** (→ add harder benchmarks, M-EVAL-FRONTIER-TIER). `tools/eval-elo --persist` seeds the DB. Emitting these into `latest.json` for the website is the dashboard-redesign sprint (M-EVAL-DASHBOARD-REDESIGN). See [design_docs/planned/v0_24_0/m-eval-rating-efficiency.md](../design_docs/planned/v0_24_0/m-eval-rating-efficiency.md).
