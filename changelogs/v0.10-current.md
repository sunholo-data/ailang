# AILANG Changelog: Current (Bytecode VM & Runtime)

> Archived from CHANGELOG.md. See [CHANGELOG.md](../CHANGELOG.md) for latest and links to all archives.

## [Unreleased]

### Fixed
- **bytecode: fix register allocation bugs (13 EvalOnly → 0)** —
  Two bugs fixed: (1) Image validator incorrectly treated OpGetField's C operand
  (a sorted field index) as a register number, rejecting 9 prototypes whose field
  index exceeded NumRegs. Fix: separate OpGetField from the register-checking group
  in `image.go:validateInstruction`. (2) Switch case bindings and nested let
  bindings permanently consumed registers via `allocPinned` even after their scope
  ended. Fix: scope-aware register recycling — `scopeStack.pop()` now returns
  scoped registers to the allocator's free list, and `allocContig` scans the free
  list for adjacent slots before bumping. EvalOnly reduced from 89 → 76 / 1228
  prototypes (-15%). Parity: 129 MATCH, no regressions.
  Sprint: `M-BYTECODE-REGALLOC-FIX`.
- **bytecode: fix lambda body name resolution in multi-module images** —
  `compileLambda` was not propagating `currentModule` to the inner
  `funcCompiler`, causing all same-module function references inside lambda
  bodies to fail with "unbound variable" / "call to unbound name". One-line
  fix: `inner.currentModule = fc.currentModule`. Reduces docparse EvalOnly
  from 157 → 92 / 1204 prototypes (-41%). Remaining 92 are effectful
  builtins (73), register overflow (11), unknown ADT (2), and std/net
  unbound (2). Parity: 129 MATCH, no regressions.
  Sprint: `M-BYTECODE-LAMBDA-RESOLUTION`.

### Added
- **bytecode: wire 3 JSON builtins to VM** — `__json_encode`, `__json_decode`,
  and `__json_repair` now dispatch natively in the bytecode VM. JSON encode
  walks the `Json` ADT tree recursively building strings. JSON decode uses Go's
  streaming `encoding/json` parser to construct `Result[Json, string]` ADT
  values. JSON repair fixes truncated JSON by closing unclosed brackets/strings.
  21 unit tests with `-count=20` determinism checks. EvalOnly reduced from
  92 → 89 / 1204 prototypes (-3). Sprint: `M-BYTECODE-PURE-EFFECTS`.
- **bytecode: wire 6 HOF builtins to VM** — `list_map`, `list_filter`,
  `list_foldl`, `str_foldChars`, `str_foldSlices`, and `str_mapSlicesJoin`
  now dispatch via new `OpBuiltinCallHOF` opcode with `VM.CallClosure`
  callback infrastructure. Added `ClosureCaller` interface, `HOFBuiltinFunc`
  type, and `HOFBuiltinTable` in both compiler and VM. Each HOF builtin
  iterates its collection natively and invokes the user callback via
  `CallClosure`, which handles both compiled closures and EvalOnly fallback.
  22 unit tests cover all 6 builtins including edge cases (empty lists,
  single elements, nested closures). EvalOnly reduced from 163 → 157 / 1130
  prototypes. The modest reduction (vs ~90 target) is because most remaining
  EvalOnly ops are from unbound-variable lambda bodies and unknown-ADT
  switches — separate compiler limitations, not HOF-related. Parity: 129
  MATCH, no regressions. Sprint: `M-BYTECODE-HOF-BUILTINS`.
- **bytecode: wire 55 pure stdlib builtins to VM** — String ops (26: split,
  join, trim, find, slice, replace, startsWith, endsWith, upper, lower, len,
  compare, eq, chars, words, charAt, charCode, decodeQP, startsWithIC,
  splitAny, replaceMany, escapeXml, intToStr, floatToStr, stringToInt,
  stringToFloat), math (23: all trig, floor/ceil/round, abs, PI, E, pow, log,
  sqrt, mod, floatToInt, int↔float aliases), and list set ops (6: nth, member,
  dedup, difference, intersect, union) now dispatch via `OpBuiltinCall`.
  Reduces docparse EvalOnly from 220 → 163 / 1130 prototypes (-26%).
  `stringToInt`/`stringToFloat` are the first builtins to create ADT (Option)
  values natively in the VM. HOF builtins (map/filter/foldl) and effectful
  builtins remain EvalOnly. Parity: 129 MATCH, no regressions.
  Sprint: `M-BYTECODE-STDLIB-BUILTINS`.

## [v0.10.15] - 2026-04-09

### Added
- **bytecode: wire Phase 2E pure builtins** — `_not_Bool`, `_intToFloat`,
  `__list_length`, and `_concat_List` now dispatch via `OpBuiltinCall`
  instead of bridging to the evaluator. Reduces docparse EvalOnly from
  247 to 220 / 1129 prototypes. Remaining EvalOnly are effectful builtins
  (IO, FS, XML, string ops) that require capability-aware dispatch.
  Sprint: `M-BYTECODE-PHASE2E`.

### Fixed
- **bytecode: constructor-pattern head in cons pattern** — Match arms of
  the form `TextBlock(t) :: rest => t.style` caused `unbound variable "t"`
  at compile time. Two bugs in `internal/gen/lower/match.go`: (1)
  `lowerPatternCond` for `ListPattern` only checked list length, not the
  constructor tag on head elements — fixed by AND-combining a tag equality
  check for each `ConstructorPattern` element; (2) `lowerPatternBindings`
  for `ListPattern` only handled `VarPattern` elements, silently skipping
  constructor sub-patterns — fixed by binding head to a temp and
  field-accessing each var sub-arg. Regression test:
  `TestLowerMatchStmt_ConsConstructorHead`. Eliminates the last
  sprint-scoped EvalOnly errors in `ailang-parse` docparse.
  Sprint: `M-BYTECODE-MULTIMODULE` M5.

### Added
- **`scripts/bench_ailang_parse.sh`** — Wall-clock benchmark script
  comparing evaluator vs bytecode VM on the runnable example corpus.
  Supports `--iters`, `--only`, `--min-ms` flags. Reports per-file and
  aggregate speedup with a ≥3× gate check.

### Changed
- **serve-api: typed router error envelope** — Router-level 404 responses
  now carry a structured `error_detail` envelope with a stable `code`
  field (`ROUTE_NOT_FOUND`, `MODULE_NOT_LOADED`, `FUNCTION_NOT_FOUND`,
  `METHOD_NOT_ALLOWED`) alongside the existing flat `error` string. When
  a request path doesn't match any registered `@route` on a route-driven
  server, the response now returns `ROUTE_NOT_FOUND` with a "Did you
  mean ...?" suggestion and a bounded `available_routes` list, instead
  of the misleading `module "X" not loaded` error that sent AI agents
  debugging the wrong layer. Legacy `/api/{module}/{func}` dispatch on
  no-`@route` servers still returns `MODULE_NOT_LOADED` with the
  historical message text for backward compatibility. The flat `error`
  field always mirrors `error_detail.message` so existing clients that
  parse the top-level `error` string continue to work unchanged.
  Reported by docparse (inbox `msg_20260409_070210_566f6da6`).
  Implements `M-SERVEAPI-ROUTE-NOT-FOUND`.

## [v0.10.14] - 2026-04-08

### Fixed (SECURITY, P0)
- **`std/rand` no longer deterministic across cold starts** — `init()`
  in `internal/builtins/rand.go` seeded `math/rand` with
  `rand.NewSource(0)`, so every fresh process produced the *same*
  sequence from `rand_int`/`rand_float`/`rand_bool` unless the program
  explicitly called `_rand_seed`. This was a real security bug, not a
  theoretical one: docparse on Cloud Run minted the **identical** 32-char
  API key `dp_fc4af748e9e0a03496c86bdae37091f6` on at least four
  independent cold starts across two GCP projects (`ailang-multivac-dev`
  and `ailang-multivac`), causing Firestore upserts to silently overwrite
  one user's API key with another's. The "first key after cold start"
  was also predictable to anyone able to trigger a cold start. Fix:
  `init()` now seeds from `crypto/rand` via the new `cryptoSeed()`
  helper, which panics on entropy failure rather than falling back to
  a predictable value (per the no-silent-fallbacks rule). Determinism
  for games/tests is preserved — callers must opt in via `SetRandSeed`
  or `std/rand._rand_seed`. Regression test:
  `TestCryptoSeed_NonDeterministic` in `internal/builtins/rand_test.go`.
  Reported by docparse (inbox `msg_20260408_165307_ca9998b6`).

## [v0.10.13] - 2026-04-08

### Fixed
- **serve-api: empty POST body now zero-pads named params instead of
  leaking eval errors** — When a client POSTed to a `@route` handler
  with no body (or no `Content-Type`), `parseArgsWithNames` short-
  circuited to `parseArgs` and returned `nil, nil`, skipping the
  zero-value padding that the `{}` / unmatched-keys path already had.
  Result: single-string handlers received `UnitValue` (crashing
  `_crypto_sha256hex` etc. with `expected String, got *eval.UnitValue`),
  and multi-arg handlers got `function expects N arguments, got 0` —
  both surfaced as raw internal errors to the network. Now an empty
  body with declared params behaves identically to `POST {}`: each
  param gets its type's zero value (`""`, `0`, `false`, `[]`, `{}`),
  so user code runs its normal validation path and the response is the
  handler's own error envelope. Reported by docparse on prod
  (inbox `msg_20260408_104901_78aa2a4f`); fixed in
  `internal/apiserver/handler.go::parseArgsWithNames` with regression
  tests in `named_args_test.go`.

## [v0.10.12] - 2026-04-08

### Changed
- **M-SERVEAPI-UNIFY: serve-api loader refactor — single registration site,
  PhysicalPath identity, no dep-discovery loop** — Replaces the v0.10.7 →
  v0.10.11 cascade's root cause with a structural fix instead of a third
  patch on the dep-discovery loop. The cascade was a *projection drift*
  bug: HTTP routes, OpenAPI spec, MCP tools, and function dispatch each
  derived their own key/filter from the same loader output, and the four
  derivations could disagree. v0.10.11 unified the two derivations inside
  `loadFile`; v0.10.12 retires the entire dep-discovery loop and makes
  drift structurally impossible.

  **New architecture:**
  - `s.modules` is now keyed by `PhysicalPath` (the symlink-resolved
    absolute file path) — the module's *identity*, not a derived string.
  - `registerModule` (`internal/apiserver/module_entry.go`) is the SOLE
    write site for `s.modules`. It computes `PhysicalPath`, `CanonicalID`,
    `DeclaredPath`, and `RelPath` ONCE, and writes them all to the
    `ModuleInfo` struct. Consumers read the projection they need from
    the fields — they never re-derive from source data.
  - `LoadProject` (`internal/apiserver/load_project.go`) is the new
    project-wide loader: one pipeline pass per file, idempotent
    registration via `registerModule`, eager-load by `CanonicalID`. It
    replaces the old per-file `loadFile` + dep-discovery loop. The
    legacy `loadFile` is now a thin wrapper for the single-file form
    (watcher reload, individual file args).
  - The `loadDirectory` walker is deleted entirely (subsumed by
    `LoadProject`).
  - The dep-discovery loop in `loadFile` (~170 lines, source of every
    cascade bug from v0.10.7 onward) is deleted.

  **Consumers migrated** to read `info.Path` (RelPath projection) via
  the new `findModuleByRelPath` helper instead of indexing `s.modules`
  by a derived string: `handler.go` (function dispatch), `meta.go`
  (`/api/_meta/modules/{path}`), `a2a.go` (skill IDs and `tasks/send`),
  `openapi.go` (URL generation), `mcp.go` (tool name generation and
  `engine.Call` dispatch).

  **Tests:**
  - `cold_start_test.go` rewritten for the PhysicalPath-keyed map. The
    four cold-start invariants now assert: each `PhysicalPath` appears
    exactly once, keys ARE absolute file paths (the new identity),
    `Registered:` log line emitted exactly once per module
    (idempotency), all expected RelPaths present.
  - `module_entry_test.go` (new): asserts `registerModule` is the sole
    write site (every entry has populated `PhysicalPath` /
    `CanonicalID` / `Path`, and the map key equals the entry's
    `PhysicalPath`); the under-basePath filter rejects files outside
    the project root; `normalizedBasePath` is correctly Abs +
    `EvalSymlinks` + trailing separator.
  - `TestLoadProject_DocparseShape` (new in `cold_start_test.go`): the
    permanent CI guard against the cascade class. A docparse-shaped
    fixture with three local route-bearing files plus a `pkg/vendor/`
    directory containing a route-bearing file asserts: exact local
    module count, no `pkg/` files leaked into `s.modules`, and
    idempotency on a second `LoadModules` pass.

  **Net change:** `server.go` shrank from 842 → 671 lines (-171).
  Architecturally: 4 projection key derivations → 1; 2 write sites → 1;
  3 specialized filters → 1 under-basePath check; ~600 LOC of cascade
  patches and dep-discovery glue → ~270 LOC of `registerModule` +
  `LoadProject`.

  Design docs:
  [m-serveapi-unify.md](../design_docs/planned/v0_11_0/m-serveapi-unify.md),
  [m-serveapi-unify-sprint-plan.md](../design_docs/planned/v0_11_0/m-serveapi-unify-sprint-plan.md).
  Files: `internal/apiserver/server.go`,
  `internal/apiserver/load_project.go` (new),
  `internal/apiserver/module_entry.go` (new),
  `internal/apiserver/module_entry_test.go` (new),
  `internal/apiserver/cold_start_test.go`,
  `internal/apiserver/handler.go`, `internal/apiserver/meta.go`,
  `internal/apiserver/a2a.go`, `internal/apiserver/openapi.go`,
  `internal/apiserver/mcp.go`.

## [v0.10.11] - 2026-04-08

### Fixed
- **Cold-start regression: dep-discovery double-registration (v0.10.10
  follow-up)** — v0.10.10 populated `ast.File.Path` to fix the MOD011 dedup,
  which inadvertently reanimated dormant code in
  `internal/apiserver/server.go::loadFile`'s dep-discovery loop. That loop
  used a different key derivation (`strings.TrimPrefix` over the pipeline
  canonical ID) than the main `loadFile` path (`filepath.Rel(s.basePath,
  absPath)`), so the same local file was registered under TWO keys in
  `s.modules` whenever a project had multiple `@route` files importing
  each other. The eager-load step then called `engine.Load` twice per
  module — doubling cold-start time and breaking Cloud Run probes for
  docparse (cold start went from ~22s on v0.10.7 to ~90s on v0.10.10).
  Three surgical fixes in the dep-discovery loop:
  1. **Unify key derivation** with the main path via
     `filepath.Rel(s.basePath, absFile)` so both paths produce identical
     `s.modules` keys.
  2. **Existence check moved BEFORE** the four `extract*` calls — repeat
     visits across the multi-file `LoadModules` pass are now O(map lookup)
     instead of O(parse + 4 AST traversals).
  3. **Skip the entry-point file** explicitly so dep-discovery doesn't
     redundantly process the file the main path already handles.

  Also normalizes `s.basePath` (absolute + `EvalSymlinks`) at server
  construction so the prefix check matches loader-resolved file paths
  consistently on macOS, where TMPDIR routes through `/var/folders` →
  `/private/var/folders`. Without this, the prefix check silently dropped
  local files in temp directories.

  Regression tests in `internal/apiserver/cold_start_test.go` cover four
  invariants: no duplicate registration, key consistency (forward-slash
  relative paths only), no redundant dep-discovery work (each module
  logged at most once), and entry-point skipping. Postmortem:
  [m-mcp-cascade-postmortem-and-fixes.md](../design_docs/planned/v0_11_0/m-mcp-cascade-postmortem-and-fixes.md).
  Files: `internal/apiserver/server.go`,
  `internal/apiserver/cold_start_test.go` (new).

## [v0.10.10] - 2026-04-07

### Fixed
- **MOD011: dedupe by resolved file path (regression fix for v0.10.9)** — The
  v0.10.9 MOD011 check false-fired on every package module that uses
  `module_prefix`, because the same physical file was being loaded under two
  canonical IDs (e.g. `pkg/sunholo/ailang_parse/services/csv_parser` AND
  `docparse/services/csv_parser`, both pointing at the same on-disk file).
  The detector now dedupes by `filepath.EvalSymlinks(Abs(mod.File.Path))`
  before comparing declared module paths, so aliasing is no longer flagged —
  only two *genuinely different* files claiming the same module header
  trigger the error. Also populates `ast.File.Path` in the loader so the
  detector (and future consumers) can see the resolved disk path instead of
  the empty string set by the parser. Files:
  `internal/loader/loader.go`, `internal/pipeline/pipeline_module.go`,
  `internal/pipeline/module_collision_test.go`.

## [v0.10.9] - 2026-04-07

### Fixed
- **MOD011: Module path collision detection (silent dispatch footgun)** — When
  two different source files declared the same `module X` header (e.g. a local
  `docparse/services/mcp_tools.ail` and a `module_prefix`-aliased package file
  at `pkg/sunholo/ailang_parse/services/mcp_tools.ail` both declaring
  `module docparse/services/mcp_tools`), runtime dispatch via
  `callFunction("docparse/services/mcp_tools", "mcpParse", ...)` was ambiguous
  — whichever module won the loader cache silently shadowed the other. v0.10.8
  fixed route *registration* in this case, but function *dispatch* still went
  to the wrong module, causing features like `AUTH_REQUIRED` checks to appear
  to "not fire" when they were actually firing on the wrong function. The
  pipeline now detects collisions at load time and returns `Error MOD011`
  listing both source files, consistent with AILANG's "no silent fallbacks"
  principle. Detection happens once per pipeline run, right after
  `modLoader.LoadAll`. Files: `internal/pipeline/pipeline_module.go`,
  `internal/pipeline/module_collision_test.go`.

## [v0.10.8] - 2026-04-07

### Fixed
- **serve-api: package routes leaked through `module_prefix` aliasing** — When a
  project imported a single symbol from a package module that declared its own
  `module_prefix` colliding with the local project namespace (e.g. docparse
  importing `pkg/sunholo/ailang_parse/services/mcp_tools` under the aliased
  path `docparse/services/mcp_tools`), the package's `@route` annotations
  still leaked into the project's route table. The v0.10.6/v0.10.7 filter used
  `strings.HasPrefix(modPath, "pkg/")` + `os.Stat(localFile)`, both of which
  could be fooled by alias collisions. The filter now uses the module's actual
  source file path (`loaded.File.Path`) and only registers routes when the
  file lives under `s.basePath` on disk. Set `DEBUG_APISERVER_ROUTES=1` to log
  which modules are filtered out. Fixes a case where docparse's local
  `mcpParse` wrapper was shadowed by the package's own `mcpParse` at
  `POST /mcp/v1/parse`. Files: `internal/apiserver/server.go`.

## [v0.10.7] - 2026-04-07

### Added
- **MCP-compliant tool names + `@mcp_name` annotation** — All MCP tool names now
  match the strict regex `^[a-zA-Z0-9_-]{1,64}$` enforced by Claude Desktop and
  most current MCP clients (no dots, no slashes, max 64 chars). Previously,
  AILANG generated dot-separated names like `docparse.services.mcp_tools.mcpParse`
  that Claude Desktop rejected outright.
  - **New `@mcp_name("toolName")` annotation** lets authors set the exact MCP
    tool name surfaced to clients (e.g. `@mcp_name("parse")` on `mcpParse`).
    Invalid names are logged at startup and the affected tool is skipped.
  - **Auto-generated names** follow a layered fallback: (1) bare function name
    when globally unique among exposed exports (e.g. `mcpParse`), (2)
    `<lastModuleSegment>_<funcName>` for collisions (e.g. `services_parseCsv`),
    (3) deterministic SHA1 hash suffix when truncated to 64 chars.
  - All non-override outputs are guaranteed to satisfy the MCP regex by
    construction. New `validateMCPName()` defensively checks every emitted name.
  - Files: `internal/parser/parser_decl.go`, `internal/apiserver/server.go`,
    `internal/apiserver/routes.go`, `internal/apiserver/mcp_schema.go`,
    `internal/apiserver/mcp.go`, plus tests + `docs/docs/guides/serve-api.md`
    + devtools prompts.

## [v0.10.6] - 2026-04-06

### Fixed
- **MCP --routes-only: exclude external package routes** — When a project imports
  a package that has its own `@route` annotations (via `module_prefix` aliasing),
  those package routes were leaking into the importing project's MCP tools/list and
  REST endpoints. Now only the project's own local `.ail` files contribute routes;
  external package modules are preloaded for execution but their `@route` annotations

## [v0.10.5] - 2026-04-06

### Fixed
- **MCP --routes-only canonical path dedup** — Modules loaded via `loadDirectory`
  were registered twice: once under the declared path (`docparse/services/mcp_tools`)
  and again under the canonical filesystem path (`Users/.../docparse/services/mcp_tools`).
  On Cloud Run this produced `app.*` prefixed duplicate tools in MCP `tools/list`.
  Fix normalizes canonical paths by stripping basePath before checking the module map.
  Also removed redundant MCP doc-comment exception (`isExposed()` is now the sole filter).

## [v0.10.4] - 2026-04-04

### Added
- **M-MCP-QUALITY: MCP server quality + @route header access** —
  Six fixes making AILANG packages work as proper MCP tool providers for AI agents.
  - MCP `tools/list` now respects `--routes-only` and `@noexpose` (was exposing all 159 exports)
  - Tool names are machine-portable (`docparse.services.parseCsv` not `Users.mark.dev...`)
  - Descriptions use doc comments (`-- comment above func`); type signatures as fallback
  - `inputSchema` uses named parameters with JSON Schema types (was generic `{args:[...]}`)
  - `makeToolHandler` accepts both named params and legacy `{"args":[...]}` format
  - Undocumented non-route helpers auto-excluded from MCP when `--routes-only`
  - `@route` handlers can declare `_headers: Json` parameter to receive HTTP request headers
    (enables multipart file upload + auth header access without switching to `@raw`)
  - New `ExportInfo.DocComment` field extracted from source `--` comment lines
  - Deterministic dedup: modules loaded via both direct and pkg/ paths produce one
    MCP tool (not two), preferring the entry with a doc comment description
  - Example: `examples/runnable/mcp_tools.ail`
  (~450 LOC across implementation + tests)

- **M-PHASE2A-BENCH: Evaluator vs native Go performance benchmarks** —
  Phase 2A gate for bytecode VM decision. 7 workloads (fib30, list map/filter 5K,
  tree pattern match, curried closures, string pipeline, game step, cross-boundary)
  benchmarked with startup excluded. Results: evaluator is 400-441,000x slower than
  native Go across all workloads. Decision: **build bytecode VM** (all workloads exceed
  10x threshold). Benchmarks retained as permanent regression tests.
  Run with: `make bench-phase2a`
  (~550 LOC benchmark harness + 7 AILANG programs + decision report)

- **M-STD-STRING-PERF: O(n) string processing primitives** —
  Six new builtins for high-performance string processing, unblocking real-world
  email/HTML parsing that previously hung at 1.8GB with O(n²) accumulator patterns.
  - `decodeQuotedPrintable(s)`: Native Go RFC 2045 §6.7 decoder — single-pass O(n)
    using `strings.Builder`. 37KB email decodes in ~80μs (was hanging indefinitely).
  - `replaceMany(s, pairs)`: Multi-pattern replacement via `strings.NewReplacer`
    (Aho-Corasick). 23-pattern HTML entity decoding on 50KB in ~150μs.
  - `foldSlices(s, delim, acc, f)`: Fold over split segments without list allocation.
    Iterates via `strings.Index`, calls callback per segment.
  - `mapSlicesJoin(s, delim, f)`: Split-transform-join in O(n) using `strings.Builder`.
    3000 segments in ~100μs. Recommended for split→transform→concat workflows.
  - `startsWithIgnoreCase(s, prefix)`: Case-insensitive prefix check using
    `strings.EqualFold` on prefix slice. Useful for header parsing.
  - ASCII fast-path for `substring`/`find`: Skips `[]rune` conversion when input is
    pure ASCII (99% of email/HTML). 24x faster for 50KB strings (15μs vs 356μs).
  New file: `internal/builtins/string_encoding.go` (QP decoder).
  All builtins registered in `std/string` module with full metadata, determinism
  verification (`-count=20`), and benchmarks.
  (~560 LOC implementation + tests + benchmarks)

## [v0.10.3] - 2026-04-03

### Fixed
- **Fix multipart file upload field name mismatch** —
  `serve-api` multipart uploads silently dropped files when the curl field name
  didn't match the AILANG param name (e.g. `curl -F 'file=@doc.docx'` with param
  `filepath: string`). Now uses 3-pass matching: (1) exact name match, (2) positional
  fallback for unmatched files to unmatched string/bytes params, (3) zero-value pad.
  Extracted `readMultipartFile` helper to deduplicate file reading. 4 new tests.

## [v0.10.2] - 2026-04-03

### Fixed
- **M-DX-SERVE-API-ERROR-STATUS: Map Result.Err to proper HTTP status codes** —
  serve-api now returns HTTP 400 (not 200) when an AILANG function returns `Err(...)`.
  Custom status codes via `Err({_status: 404, message: "not found"})`. `_status` is
  extracted for the HTTP response and stripped from the body (same convention as `@raw`).
  `Ok(value)` responses are unwrapped automatically — clients receive the inner value
  directly instead of `{"__tag": "Ok", ...}`. Works with both wrapped and `@nowrap` paths.
- **Fix serve-api type coercion and improve DX error messages** —
  Better error messages when serve-api encounters type mismatches. Improved developer
  experience for debugging API endpoint issues.
- **Reject underscores in ParseFloat across all user-facing paths** —
  Underscores in numeric literals (e.g., `1_000`) were incorrectly accepted by the
  serve-api args parser as digit separators. ParseFloat now rejects underscores
  consistently across all user-facing code paths.

### Changed
- **Auto-attach binary MD5 and version to bug reports** —
  `ailang bug` now automatically includes the binary MD5 hash and version info,
  making it easier to diagnose version-related issues.
- **Unify registry validator URL config** —
  Registry validator URL now defaults to `registry.ailang.sunholo.com` consistently.

### Fixed
- **M-DX-XPKG-RESOLVE: Cross-package stdlib function resolution** (~120 LOC, 4 unit tests + integration test)
  - Functions from stdlib packages (e.g., `asString` from `std/json`) that internally construct ADT
    values (e.g., `Some(s)`) failed when called cross-package — the evaluator used the CALLER's

    at closure creation time. At call sites, a `FallbackResolver` tries the caller's resolver first
    (preserving builtins and effect context), then falls back to the function's defining resolver
    (for constructors and module-specific lookups). Three call paths patched: direct application,
    auto-curry, and `applyFunction`.
- **Resolver version conflict detection** — `ailang lock` now fails with a structured `VersionConflictError`
  when a transitive dependency requires a different version of a package than the root manifest pins.
  Previously, the resolver silently used whichever version was encountered first (Go map iteration order),
  which could downgrade direct dependencies. Error includes conflicting versions, which package introduced
  the conflict, and actionable suggestions (republish or change root pin). Dependency iteration is now
  sorted by name for deterministic resolution order.
- **Portable lock file** — `ailang.lock` no longer stores absolute cache paths for registry and git
