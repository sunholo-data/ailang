### Information-flow control labels (M-TAINT-TYPES, target v0.16.0)

Adds an information-flow control (IFC) label system to AILANG so functions can express where untrusted data is and is not allowed to flow. The annotation `T<label>` marks a value as carrying a source-level taint; `T{not LABEL}` marks a parameter position as a sink that refuses values labelled with `<LABEL>`. The new `! {Declassify}` effect must be present on any function that intentionally lowers a label. Adapted from Erik Meijer's "Guardians of the Agents" (CACM Jan 2026) — the language-level half of the static-check-before-tool-runs idea, sitting alongside the Z3 contract layer that v0.9.x already provided. Design doc: [m-taint-types.md](design_docs/planned/v0_16_0/m-taint-types.md). Sprint plan: [m-taint-types-sprint-plan.md](design_docs/planned/v0_16_0/m-taint-types-sprint-plan.md).

- **M1: label lattice.** New `internal/types/labels.go` package with `Label` interface and four implementations (`labelBottom`, `labelConst`, `labelVar`, `labelJoin`). The join constructor canonicalises (sorted, deduplicated, flat) so equality is structural and commutative-/associative-/idempotent-clean. `EvalNot(L, ℓ)` evaluates the refinement predicate `{not ℓ}` against label `L` (true iff `ℓ` is not subsumed by `L`). 12 unit tests run with `-count=20` to catch map-iteration nondeterminism in the canonical sort.
- **M2: AST + parser.** New AST nodes `LabelExpr`, `RefinementExpr`, `LabelledType`. Parser gains 2-token lookahead (`peek2Token`) so `{not IDENT}` after a base type is unambiguous from a function body's `{`. `T<label>` and `T{not LABEL}` work in any type position (params, returns, record fields, list/tuple element types). Pretty-printer emits canonical forms. Structured parse errors with hints for non-MVP shapes (`{!email}`, `{¬email}`, `{not a && not b}`, `{label = email}`).
- **M3: type-system label primitives.** New `TLabelled{Inner, L}` wrapper type and helpers `LabelOf`, `StripLabel`, `WithLabel`, `PurePropagateLabel` (APP-PURE: output label = join of input labels), `JoinLabels`, `JoinLabelList`. `WithLabel` strips before re-wrapping to prevent double-nesting.
- **M4: sink-refinement check + DECLASS rule.** `CheckSinkRefinement(argType, refinement)` evaluates `EvalNot(LabelOf(argType), <ℓ>)` and returns a structured `SinkError` if the argument's label flows into a `{not ℓ}` position. `CheckDeclassify(in, out, effectRow)` enforces the DECLASS rule: a function that changes the input/output label must have `Declassify` in its effect row, with identity (same label) treated as a no-op. The `Declassify` effect is registered alongside `IO`, `Net`, `FS`. `*ast.LabelledType` cases added to all 7 `ast.Type` switches (typechecker, iface builder, elaborate, gen/lower, apiserver, verify).
- **M5: single-module demo + Z3 sort handler.** [examples/runnable/contracts/inbox_injection_v2.ail](examples/runnable/contracts/inbox_injection_v2.ail) rewrites the v1 demo using real labels — `string<email>` source, `string<sanitized>` declassified output. `ailang verify` reports `5 functions: 3 verified, 2 violations`. `cmd/ailang/verify.go` gains `*ast.LabelledType` cases in `astTypeToSMTSort` and `convertASTTypeToType` so Z3 sees the underlying sort. All 20 existing contract examples produce identical pre-/post-sprint outcomes.
- **M6: iface JSON serialisation.** Tagged-union JSON for `Label` (`bottom`, `const`, `var`, `join`) plus a `tlabelled` envelope on `Type`. The iface builder restores labels from the original `*ast.FuncDecl` onto its `*types.Scheme` before serialisation — the type checker erases labels for unification, so `applyLabelsFromAST` walks the AST and re-wraps each param/return position. Backwards-compatible: ifaces without label fields decode as plain types with `LabelOf == ⊥`. New `internal/types/label_json.go` + 9 round-trip tests.
- **M7: cross-module demo.** New [inbox_v2_lib.ail](examples/runnable/contracts/inbox_v2_lib.ail) exports a `Mail` record with labelled fields (`body: string<email>`); [inbox_v2_app.ail](examples/runnable/contracts/inbox_v2_app.ail) imports it and shows the same 3-verified / 2-violation split with the label flowing across the module boundary. Required adding `*TLabelled` to the unifier (strip + recurse). M-SMT-CROSS-MODULE-TYPES regression check passes (`cross_module_types{,_lib}.ail` still 4 verified / 1 named SKIP).
- **M8: prompt-injection benchmark.** [benchmarks/prompt_injection/](benchmarks/prompt_injection/) — scenario.md, expected_ailang_safe.ail (3 verified), expected_ailang_injected.ail (1 violation caught), expected_python_naive.py (no static check available), score.sh CSV scorer, README.md. YAML benchmark spec at [benchmarks/prompt_injection.yml](benchmarks/prompt_injection.yml) for `ailang eval-suite` integration.
- **M9: prompt + CHANGELOG + sprint finalisation.** New [prompts/v0.16.0.md](prompts/v0.16.0.md) (active version) teaches `T<label>`, `T{not LABEL}`, the lattice naming convention (lowercase, kebab-case for compounds), the DECLASS rule, and a 30-line worked example.

**Known follow-up:** the SMT encoder cannot currently encode imported function calls (the lib's body is in another Core program). M7 worked around this using cross-module *types* rather than function calls. A separate sprint will teach the encoder to use the callee's iface contract as a black-box specification — tracked as `M-SMT-CROSS-MODULE-FUNCTIONS`.

### Autonomous package cascade — validated + hardened (M-PKG-AUTONOMOUS-CASCADE-SAFE)

Closes the loop on the v0.10.0 [M-PKG-AUTONOMOUS-UPDATES](design_docs/implemented/v0_10_0/m-pkg-autonomous-updates.md) work that built the cascade infrastructure but had never been exercised end-to-end in cloud — partly because cloud dispatch was sending raw message content as the agent prompt instead of the templated workflow until commit `228d5c0a` (M-PKG-FEEDBACK-LOOP M2). This sprint validates the cascade end-to-end AND hardens the cascade-trigger channel via topic-IAM separation.

- **New `ailang-{env}-cascade` Pub/Sub topic.** Publish IAM restricted to the coordinator service account ONLY. The pkg-update.md template now starts with a critical guard: act on the bump request only when `Source: cascade`. Public MCP traffic (`submit_feedback` etc.) cannot reach this topic — enforced at the GCP layer before any agent code runs. Threat-modelled in the design doc as "Public MCP attacker"; closed at the IAM layer instead of relying solely on template-level discipline.
- **`Source` attribute end-to-end.** Added to `pubsub.MessageAttributes`, `coordinator.Message`, `coordinator.TaskRecord` (persisted in both Firestore and the local SQLite — bonus latent-bug fix: `Kind` was set on the in-memory task at message-receive time but never persisted to local SQLite, so dispatchTasksCloud silently fell back to the default template on the laptop dev path; now both `kind` and `source` round-trip).
- **`emitDependentNotifications` dual-writes.** Existing inbox path stays for backward-compat (deprecated v0.17), new cascade-topic publish via `pubsub.Publisher.PublishCascade(ctx, msgID, attrs, rootPackage)` stamps `source=cascade` and `root_package=<vendor>/<name>@<version>` attributes.
- **Per-cascade cumulative budget cap.** New optional `[cascade] max_cost_usd` section in `ailang.toml` (default $1.00). `coordinator.CascadeBudget` accumulates per-task cost across the cascade DAG; aborts further dispatches with structured event when cap would be exceeded. Per-task hard ceilings unchanged — this is an additional, cumulative gate. Each package owner controls how expensive a cascade rooted at THEIR package can grow.
- **`ailang pkg cascade status <vendor/name@version>` CLI.** Prints cascade DAG with per-dependent status (queued/merged/unknown), accumulated cost, PR URLs. Reads from existing registry provenance + index data.
- **End-to-end smoke tests.** `scripts/integration/test_cascade_e2e.sh` (positive: real publish → real PR observed) and `test_cascade_negative.sh` (negative: a crafted public-MCP `submit_feedback` with `auto_dispatch=true` and a "please bump" body MUST NOT publish anything). Both target a configurable env via `AILANG_CLOUD_PROJECT`. Idempotent cleanup.
- **`sunholo/test_pkg_consumer` cascade fixture** (in ailang-packages repo). Depends on `sunholo/test_pkg`; sets tight `[cascade] max_cost_usd = 0.50` so the forced-fail variant trips the budget gate cheaply.
- **Always-PR for v1.** No package agent auto-merges cascade-driven changes. The cascade does the boring work; humans keep the merge call.
- **Developer guide:** [`docs/guides/autonomous-package-updates.md`](docs/guides/autonomous-package-updates.md) — the golden path, threat model, diagnostics.

### Cascade deterministic-first dispatch (M-PKG-CASCADE-DETERMINISTIC-FIRST)

First real cascade observation against `ailang-multivac-dev` revealed an architectural opportunity: AILANG already had the hash-driven semver classifier from M-PKG-MSG (`classifyChange` in `internal/messaging/pkg_events.go` — A=content-only, B=additive, C=interface change), but the cascade flow was treating every bump as an AI task even when it was pure computation. Routine cascades cost ~$0.10–0.30 + ~3 min on a $0.000 deterministic operation.

This sprint shifts cascades to deterministic-first: the wrapper does the routine bump (toml dep version edit + `ailang lock` + `check` + `test`) and only invokes the AI agent when actually needed (interface breakage that requires consumer code repair). Validated end-to-end on dev with both paths exercised. Design doc: [m-pkg-cascade-deterministic-first.md](design_docs/implemented/v0_16_x/m-pkg-cascade-deterministic-first.md).

- **Self-contained cascade messages.** New `pubsub.PublishCascadeWithEnvelope` carries the full hash + change_class + effect-ceiling deltas in the Pub/Sub message data field AND surfaces key fields as attributes (`change_class`, `from_version`, `to_version`, `effects_widened`). The cloud coordinator decodes the envelope and populates 11 new cascade fields on `coordinator.Message` and `coordinator.TaskRecord` (persisted in both Firestore and the local SQLite). Backward-compatible: existing single-attribute cascade publishes still decode via fallback.
- **Wrapper-side deterministic dispatch.** `cmd/ailang/coordinator_cloud.go` now calls `classifyDispatchPath(change_class)` before invoking the AI executor: class A/B → `deterministicCascadeBump` (read consumer's ailang.toml, regex-rewrite the dep pin, `ailang lock`, `ailang check`, `ailang test`, commit). On success: skips AI executor entirely, the wrapper's existing push + `openCascadePullRequest` flow runs. On failure: falls through to AI with the check output for repair.
- **AI escalation context.** Nine new template variables (`{{.RootPackage}}`, `{{.RootChangeClass}}`, `{{.FromVersion}}`, `{{.ToVersion}}`, `{{.FromInterfaceHash}}`, `{{.ToInterfaceHash}}`, `{{.EffectsWidened}}`, `{{.PrevEffectCeiling}}`, `{{.NewEffectCeiling}}`) so when the AI is invoked it sees exactly what changed instead of having to reverse-engineer it from the message body. Plumbed through DispatchParams → Cloud Run Job env vars → `stage_execution.go::buildTemplateDirective`. The `pkg-update.md` template was rewritten action-first (assumes the wrapper attempted the bump first; the agent's job is breakage repair).
- **Conservative C-classifier.** `mapChangeClassToSchema` in `pkg_publish.go` now returns C whenever interface hash differs unless we can prove the change was a pure new-module addition. The previous logic returned B for "module list unchanged" cases, missing function-level removals (the registry sees module-level exports, not function signatures).
- **Cascade PRs auto-tagged.** Wrapper detects the cascade context via `AILANG_CASCADE_ROOT_PACKAGE` env var and opens the PR with `[cascade] bump <root> (<task-id>)` title and `cascade` label. Skips the `injectAgentsMD` step for cascade tasks (kept the cascade PR diff focused on the actual bump).
- **End-to-end smoke verified on dev:**
  - **Class A deterministic success** (PR #12): cascade fired → wrapper detected class A → bumped toml + regenerated lock + check passed → committed → wrapper pushed + opened PR. Total: **7.5 seconds, $0.00, zero AI invocations** (`turns=0, tokens=0+0`).
  - **Class A → check fails → AI escalation** (PR #11): cascade fired → wrapper bumped + locked → `ailang check` failed (consumer wrap.ail had deprecated `++` syntax) → wrapper escalated to AI with full cascade context → AI repaired wrap.ail → PR opened with cascade label.
- **Test+prod deployment deferred.** Cascade infrastructure live in `ailang-multivac-dev` only. `ailang-core-test-release` triggers on tag push (`^v.*`); promotion to test+prod requires a v0.14.3 release tag plus a manual `promote-to-prod` trigger run. Multivac config changes (templates, agent registrations) deploy via `git push origin dev:test/prod` once a release lands.

### Z3 cross-module type verification (M-SMT-CROSS-MODULE-TYPES)

Closes the gap that prevented `ailang verify` from working on real-world multi-module AILANG code. Phase 1 (demand-driven ADT filtering) shipped in v0.9.x; this pass lands Phase 2 (record aliases + inline records), Phase 3 (mutual recursion + parameter prefix), and the Issue 7 follow-up (named SKIP messages). Design doc: [m-smt-cross-module-types.md](design_docs/planned/v0_13_0/m-smt-cross-module-types.md). Sprint plan: [m-smt-cross-module-types-sprint-plan.md](design_docs/planned/v0_13_0/m-smt-cross-module-types-sprint-plan.md).

- **M1: per-function record-alias and inline-record filter.** Extends the v0.9.x ADT-only filter so the verifier passes only the named record aliases (`type Cell = {…}`) and inline records (e.g., `Record_blocks_kind`) that a function actually references via its params, return type, or body — including transitively through inline-record bodies. Eliminates the cascade where one unrelated alias's missing dependency would skip every function in the module. New helper `buildNeededSortSet` walks ADT variants, alias field types, and ExtraDeclaration bodies to compute the closure.
- **M2: mutual recursion via `declare-datatypes` (plural).** When the multi-pass declaration loop ends with sorts that reference each other (e.g., `Block ↔ Record_blocks_kind`), the verifier now runs Tarjan's SCC over the dep graph and emits each cycle as a single `(declare-datatypes ((Sort1 0) (Sort2 0)) (variants1 variants2))` block — Z3's only supported encoding for mutual recursion. Self-recursive singletons stay in the singular `declare-datatype` form (which Z3 also accepts). New file `internal/smt/codegen_mutual.go` (~200 LOC) plus 6 unit tests covering split helpers, plural emission, and SCC detection.
- **M3a: `$p_` parameter prefix.** Parameters are declared as `(declare-const $p_NAME SORT)` and rewritten in body references via the new `activeParamRenames` table. Eliminates Z3's "ambiguous constant reference" error when a parameter shares a name with a record accessor function (e.g., `text` parameter alongside `(text TableCell) -> String`). Bounded-recursion top-level call (`(factorial_5 $p_n)`) and the body's `*core.Var` encoder both honour the prefix.
- **M3b deferred.** Qualified field-accessor names (`RecordType_fieldName`) for cross-record collisions (Issue 6) are not in this sprint — the current docparse codebase has no real Issue 6 case, and the eval.ail breakage that surfaces "applicable" errors is a separate HOF-inlining + let-binding shadowing concern. Tracked as future work.
- **M4: named SKIP messages.** `firstUnencodableBuiltin` walks the body and reports the first unencodable builtin by name — both internal (`_str_trim`, `_str_upper`) and stdlib (`std/list.filter`, `std/string.toLower`). Replaces the generic "Function X uses types not encodable in SMT (list, unsupported string operations)" with actionable diagnostics like "Function X uses an unencodable builtin: std/list.filter". Generic fallback preserved for unencodable shapes (e.g., `core.Array`) without a named builtin.
- **M5: cross-module example + downstream validation.** New `examples/runnable/contracts/cross_module_types{,_lib}.ail` exercises all four capabilities in a verifiable form: 4 functions VERIFIED (record alias from another module, recursive ADT via `Tree`, parameter `text`/`count` colliding with accessor, cross-function call), 1 SKIPPED with a named blocker (`std/string.trim`).
- **Net effect on docparse:** 3/28 → 20+/115 verified functions across the project (~7× more functions reaching Z3). `types/document.ail` alone goes from 0 verified to 5 verified. Existing `format_router.ail` maintains 3/3 (no regression). All 20 existing AILANG contract examples produce identical verify outcomes to pre-sprint baseline.

### Multivac CI speed (M-CI-BUILD-SPEED, ailang-multivac repo)

Cut Cloud Build wall-clock from 16-22 min to 60 sec for YAML/config-only pushes (16-22× faster) and to 6:27 for full source pushes (~3× faster). Real measurements from real builds — see [docs/sprint-retros/m-ci-build-speed.md](docs/sprint-retros/m-ci-build-speed.md).

- **BuildKit registry cache + parallel agent variants (M2+M3).** All 11 agent variants (`agent-base` + `agent` + `agent-go` + `agent-codex` + `agent-codex-go` + `agent-opencode` + `agent-pi` + `agent-gemini` + `agent-gemini-go` + `agent-eval` + `agent-eval-go`) now use `docker buildx build --cache-from --cache-to --push`. Per-image `:cache` tags in Artifact Registry survive between runs. waitFor restructured so the 6 level-1 variants fan out from `build-agent-base` in parallel (vs serial chain via `push-agent-base`). Agent build phase: ~14 min serial → max(any single variant) ≈ 30s when cached.
- **Path-based trigger filters + config-only fast path (M4).** New `cloudbuild-config-only.yaml` and 3 new triggers (`ailang-multivac-config-{dev,test,prod}`) fire only on `config/**` or `terraform/**` changes and skip the entire image rebuild. Existing 4 triggers (`ailang-multivac-{dev,test,prod}`, `ailang-core-dev`) gained `includedFiles`/`ignoredFiles` so a docs-only push runs nothing and a code-only push doesn't fire the unrelated multivac pipeline.
- **Terraform skip-when-clean (M5).** `terraform plan -detailed-exitcode -out=plan.out` writes the exit code to `/workspace/tf-exitcode`. Apply step skips entirely when plan returned 0 (no changes). `deploy-services` always runs — Cloud Run revisions need to roll for new image digests even when terraform has nothing to do (terraform tracks `:latest` tag, not the digest).
- **Eliminated Cloud Run terraform drift.** Added `lifecycle { ignore_changes = [client, client_version] }` to all 14 `google_cloud_run_v2_job` and 6 `google_cloud_run_v2_service` resources. Every `gcloud run {services,jobs} update` (CI deploy step + manual force-refresh) was stamping `client="gcloud"` / `client_version="565.0.0"` on resources, causing terraform to perpetually try to null them out. Plan now stable across consecutive runs in dev/test/prod (was 0/9/0 with ping-pong, now 0/0/0).
- **Eliminated Identity Platform drift.** Removed the explicit `email{ enabled=false, password_required=false }` block from `google_identity_platform_config.default` (provider's read returns null for the block when disabled, so explicit values caused permanent diff). Belt-and-braces `lifecycle { ignore_changes = [sign_in] }` for future provider quirks.
- **Side-fix:** Cloud Build's `images:` declaration is incompatible with `buildx --push` (daemon can't find the locally-built images to push at build end). Dropped from all three `cloudbuild*.yaml` configs.
- **Net effect:** Fix-a-bug-and-ship-to-prod cycle drops from ~75 min (3 hops × 25 min) to ~15 min (3 hops × 5 min, fast paths). Major DX win for the agent-driven dev loop.

### Public MCP rate limit (M-MCP-EDGE-THROTTLE Path A)

The public unauthenticated `submit_feedback` MCP tool was unthrottled — a single client could fan out a flood through the coordinator into Sonnet-driven package agents. Path A ships an in-process per-IP token-bucket limiter; Path B (Cloud Armor + HTTPS LB cutover) and the deeper triage gate are documented separately.

- **`internal/apiserver/ratelimit.go`** — per-IP token bucket; nil = disabled (rpm=0 escape hatch); idle buckets swept after 1h to bound memory under flood. Concurrency-safe; verified under `go test -race`.
- **`X-Forwarded-For` parsing** — uses the rightmost entry, the only one Google's frontend trusts (clients can prepend, GFE always appends the real TCP source as the last hop). `X-Real-Ip` fallback; missing headers bucket as `"unknown"` rather than bypassing the cap.
- **Defaults: 5 rpm, burst 3.** Override via `AILANG_RATELIMIT_RPM` and `AILANG_RATELIMIT_BURST` on the Cloud Run service. Junk values fall back to defaults.
- **Wired only on `submit_feedback`.** Read tools (stdlib introspection, examples, benchmarks, etc) stay uncapped — they're idempotent and cacheable.
- **Wire shape:** rate-limited calls return the structured envelope `{"error": "rate_limited", "detail": "...retry after 60s"}` with `IsError=true`. No Firestore write, no Pub/Sub publish, no agent dispatch — denial happens at the tool boundary.
- **Tests:** 8 cases in `ratelimit_test.go` + `feedback_tool_test.go` cover allow/deny/refill/per-IP isolation/stdio safety/sweep/env-var override/concurrent access. All pass under race detector.
- **Limitations:** state is per Cloud Run instance, so under autoscale the cap is "soft" up to `instances × rpm`. Path B (Cloud Armor) and M-FEEDBACK-TRIAGE-GATE are the strict-enforcement and cost-killer follow-ups respectively.

Design docs: [m-mcp-edge-throttle.md](design_docs/planned/v0_15_0/m-mcp-edge-throttle.md), [m-feedback-triage-gate.md](design_docs/planned/v0_15_0/m-feedback-triage-gate.md).

### Fixed (M-AGENT-MCP, follow-up to M1)
- **`std/json.Json` values now serialize as plain JSON over HTTP/MCP.** Previously, AILANG functions returning `Json` (built via `jo`/`kv`/`js`/etc.) leaked the AILANG ADT envelope `{__type, __tag, fields}` into responses, making outputs ~10x larger and unreadable. `internal/embed.ToGo` now special-cases `TaggedValue` where `TypeName=="Json"` and `ModulePath=="std/json"`, unwrapping each constructor (JNull/JBool/JNumber/JString/JArray/JObject) to its natural Go shape. Other ADTs keep the envelope so callers can still discriminate by tag. Regression test in `internal/embed/embed_test.go::TestToGo_JsonUnwrap`.

## [v0.12.1] - 2026-04-20

> **M-CONCAT-DISAMBIG Phase 1: String interpolation lands.** `"Hello, ${name}!"` now
> desugars to a `concat_String` chain with auto-`show()` wrapping. Zero-regression:
> plain strings (no `${`) still tokenize as a single `STRING`, and escaped `\${` is
> preserved as a literal. Phase 2 (restricting `++` to lists only) ships in v0.13.0.

### Added
- **String interpolation (`M1_LEXER_INTERP`, `M2_PARSER_TYPECHECK_INTERP`)** —
  Double-quoted strings now accept `${expr}` substitution. The lexer emits a
  `STRING_PART` / `INTERP_START` / expr tokens / `INTERP_END` / `STRING_PART`
  sequence; the parser desugars that to a left-associative chain of
  `concat_String(prefix, show(expr))` calls. `show_String` is identity at
  runtime, so string-typed expressions are not double-quoted.

  ```ailang
  let name = "Alice" in
  let age = 30 in
  println("Hello, ${name}! Next year you will be ${age + 1}.")
  -- → Hello, Alice! Next year you will be 31.
  ```

  Supports:
  - Arbitrary expressions inside `${...}` (arithmetic, function calls, let-blocks, records)
  - Nested braces via brace-count tracking (`"${compute({a: 1}.a)}"`)
  - Escaped `\${literal}` → literal `${literal}` (no interpolation)
  - Plain strings with no `${` → single `STRING` token, zero regression

  Evaluator, elaborator, and codegen required zero changes — the desugar tree
  uses only existing AST nodes (`FuncCall`, `Identifier`, `Literal`).

  New examples: `examples/runnable/string_interpolation.ail`,
  `examples/runnable/string_interp_nested.ail`.

  This phase ships ahead of `M-CONCAT-DISAMBIG` Phase 2 (restricting `++` to
  lists). The teaching prompt now recommends `"${expr}"` as the primary
  string-building pattern; `"..." ++ show(x)` still works during the v0.12.x
  deprecation window.

## [v0.12.0] - 2026-04-14

> New stdlib modules (`std/gzip`, `std/tar`), three-tier OTEL tracing (`--trace-tier off|standard|deep`), and major XLSX runtime-hotspot wins (6.6× speedup on `poi_many_merges.xlsx` from `M-PERF6-PHASE4` M1 + M2a).

### Changed
- **Default tracing is now `standard`, not implicit-deep (`M-OBS-TRACE-TRIAGE`)** —
  Every `ailang run` with telemetry enabled used to emit one OTEL span per
  function invocation (avg 8.7 KB attrs each), filling the Observatory DB at
  ~730 MB/day with data no consumer queries. Investigated (252K spans / 1.93 GB
  traced to `eval.function.*` emission; 0 of 221K `eval.*` spans had `task_id`,
  `chain_id`, `tokens_in/out`, or `cost_usd` populated) and confirmed no reader
  queries these by name. Introduced three tracing tiers:

  | Tier | Emits | Default |
  |---|---|---|
  | `off` | nothing (same as `AILANG_NO_TRACE=1`) | |
  | `standard` | `eval.module.*`, top-level `eval.effect.*` (Depth≤1), contracts, budget, errors | ✅ |
  | `deep` | standard + per-call `eval.function.*` + nested `eval.effect.*` | opt-in |

  Controls (CLI wins over env wins over legacy alias):
  - `--trace-tier off|standard|deep` (CLI flag on `ailang run`)
  - `AILANG_TRACE=off|standard|deep` (env var)
  - `AILANG_NO_TRACE=1` (legacy, kept as alias for `off`)
  - `AILANG_TRACE_MAX_SPANS=N` (per-trace budget, default 500). When exceeded,
    emitter produces exactly one `trace.truncated` rollup span with
    `{budget, kept_count, dropped_count, first_dropped_name}` attrs.

  **Migration**: existing eval/benchmark workflows unaffected — they set
  `AILANG_NO_TRACE=1` via `make/eval.mk` already. Devs who relied on implicit
  per-call spans should run with `AILANG_TRACE=deep` or `--trace-tier deep`.

  Files: [internal/trace/options.go](../internal/trace/options.go),
  [internal/trace/otel_emitter.go](../internal/trace/otel_emitter.go),
  [cmd/ailang/main_run.go](../cmd/ailang/main_run.go).

### Performance
- **eval: skip redundant `FallbackResolver` chain growth on cross-module calls (`M-PERF6-PHASE4` M2a)** —
  Profile-guided follow-up to M1. The post-M1 CPU profile on
  [`poi_many_merges.xlsx`](https://github.com/sunholo-data/ailang-parse/blob/main/data/test_files/stress/poi_many_merges.xlsx)
  showed `FallbackResolver.ResolveValue` consuming **64.52% flat** of runtime
  (251s out of 417s). Root cause: each cross-module function application in
  [`eval_operations.go`](../internal/eval/eval_operations.go) wrapped
  `e.resolver` in a new `FallbackResolver` even when the existing chain
  already had a path to the callee's defining resolver — every name lookup
  on a 140K-cell XLSX hot loop walked an unnecessarily deep chain. Fix: a
  new `resolverCovers(chain, target)` helper in
  [`eval_evaluator.go`](../internal/eval/eval_evaluator.go) walks the
  existing chain once; if `target` is reachable as any Primary or Secondary,
  the wrap is skipped. Applied at all three function-application sites
  (auto-curry, full apply, `applyFunction`). **Measured: 417.31s → 64.46s
  on `poi_many_merges.xlsx` — a 6.5× speedup from a 5-line change.** Total
  improvement vs pre-M1 baseline: 425.45s → 64.46s (**6.6×**). The new top
  hotspot is GC scan (`gcDrain` 41% cum) and `listConcatImpl` (13% cum) —
  both at much smaller absolute cost. EPUB benchmarks unchanged: Alice 1.98s
  ≤ 2s target, Moby Dick 2.75s ≤ 3s target. Tests: `make test` (eval pkg)
  ✅, `make verify-examples` 161/161 ✅.

- **eval: universal `Environment.Clone` → `NewChildEnvironment` in function application (`M-PERF6-PHASE4` M1)** —
  Reported by [msg `e234c455`](../design_docs/implemented/v0_12_0/m-perf6-runtime-hotspots.md)
  (ailang-parse XLSX perf). At each of 5 function-application sites in
  [`internal/eval/eval_evaluator.go`](../internal/eval/eval_evaluator.go)
  and [`internal/eval/eval_operations.go`](../internal/eval/eval_operations.go),
  swapped `fn.Env.Clone()` (O(n) copy of the defining environment) for
  `fn.Env.NewChildEnvironment()` (O(1) — empty child scope that delegates
  lookups to the parent chain). Semantically equivalent because AILANG never
  mutates existing bindings in a shared parent env; parameters write only into
  the fresh child scope. The design doc's per-closure `PureCapture` flag was
  dropped as unnecessary — the universal swap is provably safe without it
  (saves ~150 LOC vs original plan). Measured wins on this machine
  (macOS arm64, `AILANG_NO_TRACE=1`): `poi_many_merges.xlsx` 425.45s →
  408.78s (**-3.9%**); DocParse EPUB benchmarks unchanged within noise
  (Alice 1.98s ≤ 2s target, Moby Dick 2.75s ≤ 3s target). Smaller than the
  ~14% projected from a stale 5.27s CPU profile — the real XLSX hotspot at
  408s is outside the evaluator (likely `map(parseXlsxCell, cells)` over
  140K cells in the xlsx_parser itself); follow-up investigation deferred.
  Design: [`design_docs/implemented/v0_12_0/m-perf6-runtime-hotspots.md`](../design_docs/implemented/v0_12_0/m-perf6-runtime-hotspots.md),
  sprint plan: [`design_docs/implemented/v0_12_0/m-perf6-phase4-sprint-plan.md`](../design_docs/implemented/v0_12_0/m-perf6-phase4-sprint-plan.md).

- **types: polymorphic `Ord`/`Eq` lambdas silently monomorphized to `Int` (`M-POLY-ORD` M2)** —

  bugfix to elaboration, type-checking, or op-lowering silently did

  Reported by [msg `ce6e078e`](../design_docs/planned/v0_11_3/m-eval-short-circuit-bool.md):
  guarded string indexing like `i > 0 && charAt(s, i - 1) == "\\"` crashed
  with "index -1 out of bounds for string of length N" at `i == 0`, because
  the RHS of `&&` was evaluated regardless of LHS. Before this fix, `&&`
  and `||` were lowered to strict `core.BinOp` nodes and `applyBinOp`
  evaluated both operands before reducing. Now `normalizeShortCircuit` in
  [`internal/elaborate/expr_simple.go`](../internal/elaborate/expr_simple.go)
  desugars them to `core.If` at elaboration time:
  * `a && b` → `if a then b else false`
  * `a || b` → `if a then true else b`
  All downstream phases (evaluator, bytecode VM, SMT encoder) inherit lazy
  branch semantics from the existing `If` lowering — no additional runtime
  changes required. The LHS is ANF-normalized to atomic form; the RHS is
  normalized lazily inside its branch so side-effects stay unevaluated when
  short-circuited. A `DEBUG_STRICT=1` guard in `applyBinOp` panics if the
  strict branch is reached, making future regressions visible. Five unit
  tests in [`internal/elaborate/short_circuit_test.go`](../internal/elaborate/short_circuit_test.go)
  and runnable regressions at [`examples/short_circuit_and.ail`](../examples/short_circuit_and.ail)
  and [`examples/short_circuit_or.ail`](../examples/short_circuit_or.ail).
