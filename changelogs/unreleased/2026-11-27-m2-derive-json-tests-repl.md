### Fixed

- **Multi-module `deriving (Json)` (`DERIVE-JSON`, RC1 M2)**: a library module with `export type T = ... deriving (Json)` and only `import std/json (Json)` now type-checks — it receives the implicit `std/option` + `std/result` prelude its synthesized decoder needs (no more `type Option expects 1 type argument(s), but got 0`), and the loader exports `encodeT`/`decodeT` before elaboration, so `import ./types (Item, encodeItem, decodeItem)` no longer risks `IMP010`. A module that declares its own `Option`/`Result` (or `Some`/`Ok`…) keeps its names: the codecs get the prelude ADTs under hygienic `$` aliases. Runs on the evaluator and `--strict-bytecode`.
- **Inline `tests [...]` constructor scope (`INLINE-TESTS-SCOPE`)**: the expected side of a test row can name `Some`/`None`/`Ok`/`Err` and constructors the module imports, including aliased ones (`import m (Circle as Round)`); it failed with `undefined variable: Some`. Local constructors still shadow the prelude.
- **WASM / playground / REPL `ModuleRegistry.LoadModule` parity (#2410)**: modules loaded there now go through the CLI's effect check (a `pure func` calling `println` is rejected), match exhaustiveness (`TC_MATCH_002`), contract type-checking (`TC_CONTRACT_001`) and `deriving (Eq)` instance registration (including types from previously loaded modules).
