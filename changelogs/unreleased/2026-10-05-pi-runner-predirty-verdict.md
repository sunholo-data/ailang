### Fixed — pi runner verdict read ok on a pre-dirty worktree (2026-10-05)

`scripts/mission_pi_run.sh` granted `ok` when the post-run `git status --porcelain` was non-empty, so a worktree that was already dirty before pi started read `ok` even if pi did nothing (ticket `pi-runner:verdict-blind-to-commits-and-predirty`, pre-dirty half; the commit-blind half landed in #1329). The runner now takes a content fingerprint of the worktree (porcelain, binary-safe diff against HEAD, per-file hashes of untracked files) right after `BASE_HEAD` and grants `ok` only if the fingerprint changed or commits were made. The verdict JSON gains `predirty_files` and `worktree_changed_since_start`; `worktree_changed_files` stays the post-run porcelain count. A pi run that reverts a pre-existing dirty edit also reads `ok`, because the tree really changed. `scripts/test_mission_pi_run.sh` TEST 1 and TEST 5 had been passing only because of this bug (dirty repo, stub wrote nothing); their stubs now write a file. The suite now also runs in `make test-launchd-drivers`.

The fingerprint hashes untracked entries one at a time, so an entry git cannot hash (dangling symlink, nested git repo, unreadable file) no longer hides the untracked files that sort after it; such an entry contributes a stable stand-in (name plus symlink target or nested HEAD and porcelain) instead of aborting the whole hash.
