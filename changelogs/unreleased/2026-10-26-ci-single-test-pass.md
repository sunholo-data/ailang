### Changed — CI runs the Go test suite once, not twice

The `test` job ran `go test ./...` and then `make test-coverage-gate` re-ran the whole suite with coverage (509s on the 2026-10-26 green dev run, the job's largest step). The main test step now writes the coverage profile itself (`-coverprofile=coverage/raw.out -covermode=set`), and the gate is two steps, `make coverage-from-profile` then `make check-coverage-threshold`: the first trims that profile to the same package set the gate always counted (one `COVERAGE_PKGS_CMD` definition shared with `make test-coverage`) and checks the threshold without running anything. SonarCloud and the badge read the same `coverage/coverage.out` as before. Measured on CI run 40483258889: the `test` job went from 1418s to 1108s, the coverage gate read 56.9% (identical to the last four green dev runs), and the slowest package stayed at 61% of the 416s budget.

Coverage mode moved from `atomic` to `set` (CI and `make test-coverage`): `set` gives the identical statement-coverage percentage and is the cheapest mode. Under the old coverage run `internal/format`'s corpus tests were 2–7x slower on GitHub's runners (56.6s → 401s), which inside the 416s hang budget would read as a hang.
