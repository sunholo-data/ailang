### Changed — mission driver: provider `finish_reason=error` retry is pinned end to end (2026-10-29)

Ticket `pi:provider-error:no-retry` asked for a bounded retry when the provider returns `finish_reason=error`. The driver already retries it: `Provider finish_reason: error` has been in `TRANSIENT_SIG` since #1391. What was missing was a test of the whole path. `test_controller_capacity.sh` now has a case that runs it end to end: pi writes the error to stderr, the driver's `2>&1` sends it into the driver log, the retry loop matches it, the same rung is retried, and the retry resumes the same `--session-id` with the RESUME prompt. This change is test-only and does not change driver behaviour. The lab's ROOT is now canonicalised with `pwd -P`, so the test stays correct where `$TMPDIR` is a symlink.
