### Removed — BREAKING: `extern func` declarations are rejected (EXT004) (2026-11-17, #2390)

An `extern func` declared a function whose body the host supplied in Go generated by
`ailang compile --emit-go`. That emitter was removed (#2389). Neither the evaluator nor the
bytecode VM can run an extern function, so every declaration is now error **`EXT004`**, located at
the `extern` keyword, whether or not anything calls it. This holds on every path that compiles a
program: `check` (and `--json`, also `check --package --json`), `run` with or without `--bytecode` /
`--strict-bytecode`, `test` of a module that has tests, the LSP, and the runtime that serve-api uses.
A module importing one that declares an extern fails, and the error names that module's file. The
fix is to write the function in AILANG as an ordinary `func`, or to call a std function or an effect.

Before this, a declared but uncalled extern passed `check` and ran. A call failed on every engine
with a misleading `undefined variable … please report as #366`.

The parser still accepts the syntax (now also `extern pure func`, which used to be
`PAR_EXTERN_REQUIRES_FUNC`), so the error is the one clear `EXT004` and not a parse cascade. Its shape
checks `EXT001`–`EXT003` (no `_` prefix, no type parameters, explicit return type) existed for the
emitter and are retired. `extern` stays a reserved word.

Measured before the change: no tracked `.ail` file (0 of 969, including all 49 std modules and 18
in-repo packages) declares or calls an extern. Of 5,396 unique banked eval bodies, 1 declares and
calls externs (`extern pure func`), and it never parsed.
