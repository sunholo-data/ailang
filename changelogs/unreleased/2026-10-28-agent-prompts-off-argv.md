### Fixed — Agent evals no longer kill each other through `pkill -f` (2026-10-28)

The claude and codex executors now keep every prompt byte off the child's argv. claude gets its system prompt through `--system-prompt-file` (a 0600 temp file, removed after the run) and its directive on stdin. codex gets `exec ... -` with the prompt on stdin. Before this, every eval agent's command line carried the whole teaching prompt, including `ailang run --entry main ...` and, for Python, `solution.py`. When one agent under test cleaned up its own hung test with `pkill -f "ailang run"` or `pkill -f "solution.py"`, the pattern matched every other agent CLI on the machine: concurrent trials, other `eval-suite` processes, and the launchd rotation's opencode. BSD pkill skips its own ancestors, so the agent that ran it survived. The rest got SIGTERM. claude rows were banked as `api_error` ("exit status 143"), and a killed codex row was graded on its partial solution. On the rig this happened seven times on 2026-10-27/28, and each time the kill landed 0.1–5s after a `pkill` in one eval agent's transcript. The model receives the same bytes as before; only the process table changes. opencode and pi still take the prompt on argv: their CLIs have no stdin prompt, and the only alternative (an attached file) would change what the model sees.
