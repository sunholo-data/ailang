### Fixed — verify: unannotated parameters skip; counterexamples report result values

- **An unannotated parameter is a skip, not a Z3 error** (#2400, M-VERIFY-SOUNDNESS-COVERAGE S5). `pure func inc(x) requires { x >= 0 } ensures { result > x } { x + 1 }` printed `! ERROR inc … unknown constant x`: a parameter with no type annotation has no SMT sort, was dropped from the declarations, and the clauses that mention it reached Z3 anyway. It now reports `SKIPPED inc — Function "inc" has an unannotated parameter "x", which has no SMT sort`, with the hint `` Annotate it, e.g. `x: int`. `` A verified function that calls such a helper (`func helper(x) { x + 1 }`) is skipped with `calls "helper", whose parameter "x" has no type annotation`; it was the same Z3 error.
- **A counterexample's `result` is a value** (S6). Each postcondition and call-obligation query now ends with `(get-value (result))`, so `result` is what the body evaluates to on the model's inputs (`result: Int = 0`, `result: (Option Int) = None`, `result: (Seq Int) = [0]`). Before, it was the body term over the inputs (`(let ((a!1 (ite (= (>= $p_n 0) …`), or missing when Z3 left the define-const out of the model.
- Docs: the contracts guide's skipped-construct table and the Z3 verification skill no longer list unannotated parameters as a Z3 error. Design docs: `m-verify-call-site-requires` and `m-verify-numeric-model` moved to `design_docs/implemented/v0_61_0/`; the three triage docs those milestones absorbed are marked resolved; the program doc records what shipped in v0.61.0 and the remaining work.
