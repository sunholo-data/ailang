### Added — serve-api serves MCP Apps widgets: `@mcp_ui_resource`, `@mcp_ui`, `@mcp_app_only` (2026-10-07)

An AILANG service can now ship an MCP App (ext-apps 2026-01-26), the HTML widget claude.ai and
ChatGPT render next to a tool result. This is M-MCP-FILE-HANDOFF F1c; the F1 spike proved a file
picker works this way in claude.ai.

- `@mcp_ui_resource("ui://svc/name", "self", ...)` goes on an exported `() -> string` function
  that returns HTML. The widget is listed by `resources/list` and served by `resources/read`
  with `mimeType: "text/html;profile=mcp-app"` and `_meta.ui.csp.connectDomains`. `"self"` is
  the server's own origin, taken from the request.
- `@mcp_ui("ui://…")` on a tool adds `_meta.ui.resourceUri` and the pre-GA
  `_meta["ui/resourceUri"]`.
- `@mcp_app_only` adds `_meta.ui.visibility: ["app"]`. The host hides the tool from the model,
  and the widget can still call it.

Each of these is a load error:
- an `@mcp_ui` URI with no matching resource;
- a non-`ui://` URI;
- a connect domain that is not a bare origin;
- a resource function with arguments or a non-string result;
- a URI declared twice.

Example: `examples/runnable/serve_api_mcp_app.ail`.
