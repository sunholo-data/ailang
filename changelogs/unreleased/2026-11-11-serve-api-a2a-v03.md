### Added
- **serve-api speaks A2A v0.3, and any AILANG program can be an A2A agent** (M-EXECUTOR-GE-A2A M1).
  `--a2a-message <export>` names one export taking a string: an A2A client's text goes in, the answer
  comes out. serve-api then answers `message/send` (a completed `Task` with one `answer` artifact),
  `message/stream` (SSE: `task` submitted, `status-update` working, an SSE heartbeat at most every
  15s while the handler runs, `artifact-update`, final `status-update` completed or failed) and
  `tasks/get` (recent tasks, one hour). A handler error is a `failed` task carrying its message.
  The card is v0.3 (`protocolVersion: "0.3.0"`, `preferredTransport: "JSONRPC"`, `url` ending
  `/a2a/`, https behind a TLS proxy) and is also served at `/.well-known/agent-card.json`; with a
  handler it names the service from `--server-info` and has one streamed skill whose description
  is the handler's doc comment, the text Gemini Enterprise reads to decide when to delegate.
  Validated with the official `a2a-sdk` 0.3.26 client (card, send, get, stream). Example:
  `examples/runnable/serve_api_a2a_message.ail`. `tasks/send` is unchanged.

### Changed
- **`--mcp-connect-only` now works with `--a2a`: `/a2a/` sits behind the same Bearer gate as
  `/mcp/connect/`** (M-EXECUTOR-GE-A2A M2). Every A2A request needs a token the service's
  `@mcp_token_verifier` accepts (401 with `resource_metadata` otherwise), and an identity verifier's
  per-subject limit counts each message. The agent card stays open: a registry reads it before
  anyone signs in. The startup refusal ("A2A skills are not behind the Bearer gate") is gone, and in
  its place `--a2a-message` under `--mcp-connect-only` requires the handler to be `@noexpose
  @nomcp`, so nothing but the gated `/a2a/` reaches it. Without `--mcp-connect-only` nothing changes.

### Added
- **The hosted executor has an agent: `executor_tools/agent.ail`** (M-EXECUTOR-GE-A2A M3). Its
  `ailangTask` is the `--a2a-message` handler: a bounded `std/ai` `runTools` loop (10 model turns,
  requests up to 20,000 characters) where the model, with the AILANG reference in its system role,
  writes a program, calls `ailang_check` and `ailang_run` (the same sandboxed functions the MCP tools
  serve, so every run still goes through `ailang run --policy`) and answers with the result, the
  program and its real output. `@noexpose @nomcp`: only the signed-in `/a2a/` reaches it. One log
  line per message (`executor_a2a`: outcome, messages, error code, duration, request size; never the
  text). Live on Gemini 3.8 Flash via Vertex: "print the first 15 Fibonacci numbers" answered in
  14.6s after one check and one run.

### Added
- **`--server-info icon=` sets the A2A card's `iconUrl`.** A path (`icon=/icon.png`) is resolved
  against the host the caller reached, so one flag works on every deployment and the icon stays on
  the card's own host; otherwise an `https://` URL. Anything else is a startup error. Gemini
  Enterprise's import preview showed a broken icon for a card without one. The hosted executor serves
  the AILANG icon at `/icon.png` (`executor_oauth/static/icon.png`).

### Added
- **One log line per `/a2a/` request** (`event: "a2a_request"`, JSON on stderr, so Cloud Logging
  parses it): the JSON-RPC `method`, the `outcome` (the task's final state, `completed` or `failed`,
  or why there was none: `invalid_params`, `not_found`, `unknown_method`, `bad_request`,
  `client_gone`, ...), `duration_ms`, and for `message/stream` the `heartbeats` sent. Never the
  request text, the answer or the caller's identity. The first live Gemini Enterprise call (dev,
  2026-11-12) showed one 27-second POST and no way to tell send from stream; this line answers it.

### Added
- **Under `--mcp-connect-only`, the A2A card says how to sign in.** With `--a2a-message` and
  `--oauth-issuer`, the card carries `securitySchemes.oauth` (an OAuth 2.0 authorization-code flow
  whose `authorizationUrl` and `tokenUrl` are the issuer's RFC 8414 endpoints, plus
  `oauth2MetadataUrl`) and `security: [{oauth: []}]`, so a client learns from the card alone that
  `/a2a/` needs a token and where to get one; Gemini Enterprise's registration form pre-fills its
  URL fields from it. serve-api reads the issuer's metadata when the card is first asked for and
  caches it for an hour. If the issuer cannot be read, or its metadata names a different issuer, or
  an https issuer's endpoint is not https, the card is served without the scheme and the reason is
  logged (retried after a minute). The client ID is never on the card. Without
  `--mcp-connect-only` the card is unchanged.

### Added
- **The hosted executor's agent has a daily message cap.** `executor_tools/agent.ail` admits at
  most `EXECUTOR_A2A_DAILY_CAP` messages (default 150) per UTC day per instance, counted in
  `EXECUTOR_A2A_STATE_DIR` (default `/tmp/executor_a2a`). Over the cap the user gets a refusal that
  says when it resets, and no model call is made (`executor_a2a` outcome `daily_cap`). A cap that is
  not a non-negative integer is 0, and a count that cannot be written refuses the message
  (`count_unwritable`), so a mistake closes the agent rather than lifting the limit. The service
  total is at most the cap times its max instances; a restarted instance starts its count again.
  Contracts on `clampCap`, `underCap` and `utcDay` are proved by Z3. Per-user limits and paid tiers
  (AILANG Cloud) need the caller's identity in the handler: a later change.
