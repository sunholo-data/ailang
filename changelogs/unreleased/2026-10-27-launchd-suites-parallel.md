### Changed — launchd driver suites run 4 at a time

`make test-launchd-drivers` ran its 49 bash-3.2 suites one after another: 803s of the macOS CI job (2026-10-26), against a 15-minute job timeout, and mostly spent waiting on the suites' own timeout bounds rather than on CPU. The suites are now listed once in `LAUNCHD_SUITES` (`make/test.mk`) and run by `tools/launchd/lib/run-suites.sh`, `LAUNCHD_JOBS` (default 4) at a time. Every suite still goes through `suite-env.sh`, so it gets the same clean environment. Each suite's output is printed whole when it finishes, a slowest-first timing table follows, and the run fails if any suite fails or never reports. `tools/eval/test_motoko_connection_probe.sh` stays in `LAUNCHD_SERIAL_SUITES` and runs alone afterwards: its fork-rate arm reads CPU contention as its signal. The syntax checks now run before the suites, so a failing suite can no longer hide them. Measured on CI run 40492652818 (GitHub macOS runner): the test step went from 803s to 263s, with all 49 suites passing; locally, 651s to 261s.

`test_suite_env.sh` arm F now checks the new wiring (no raw suite lines in the target, every suite listed, the runner routes through `suite-env.sh`). New arm G runs the runner on fixtures and fails if a failed or missing suite reports as a pass, if inherited env reaches a suite, or if the suites stop overlapping. Five mutations of the runner and wiring were each caught.
