### Changed — the executor's `ailang_prompt` comes in two parts

v0.62.2's single ~55 KB result was still refused by Claude Code: it counts a result's tokens with the API, and this prompt runs at about 2.2 characters a token, so 56,411 characters came to over its 25,000-token limit. `ailang_prompt` now takes `part`: `"core"` (or empty) returns program structure, syntax, effects, error handling, pattern matching, contracts, reserved words, imports and common mistakes (~40 KB on the wire, ~18k tokens); `"reference"` returns operators, print vs println, types, the list, string, JSON, map, array, regex and crypto sections and worked examples (~36 KB). Any other value is refused with `invalid_part`. A section added to the prompt goes to `reference` unless it is listed in `sandboxCore`. The library sections v0.62.2 dropped are back, in `reference`; "Output Discipline" (eval-harness byte comparison) stays out. `TestExecutorPromptTool_InSyncWithPrompt` checks each part against a 45,000-character budget, that every kept section is in exactly one part, and that the must-keep sections are in core.
