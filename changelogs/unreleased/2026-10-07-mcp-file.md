### Added — serve-api `@mcp_file`: a tool takes a file the user uploaded in ChatGPT (2026-10-07)

`@mcp_file("file")` marks a tool param as a host-supplied file (M-MCP-FILE-HANDOFF F1b,
[design](../../design_docs/planned/v0_53_0/m-mcp-file-handoff.md)). On both MCP surfaces, the
tool's `tools/list` entry gains:
- `_meta["openai/fileParams"]`;
- OpenAI's documented file object schema for the param: `download_url`, `file_id`, `mime_type`
  and `file_name`, all strings; the first two required; `additionalProperties: false`.

The param is typed `{ download_url: string, file_id: string, mime_type: string, file_name: string }`,
inline or as a same-module alias.
- The host's object binds to that record.
- `mime_type` and `file_name` default to `""`, and any extra fields are dropped.
- A call missing `download_url` or `file_id` is refused before the function runs.
- An omitted `@optional` file param binds the all-empty record.

A wrong param name or type, or a param that is also `@mcp_secret`, is a load error: `serve-api`
refuses to start. Example: `examples/runnable/serve_api_mcp_file.ail`.

### Added — ChatGPT mixed-auth metadata on `/mcp/connect/` (2026-10-07)

Every tool on the listed surface declares `securitySchemes`, top level and mirrored in `_meta`:
- `[{"type":"oauth2"}]` for `@mcp_auth("oauth2")` tools;
- `[{"type":"noauth"}]` for the rest.

A refused gated `tools/call` keeps **HTTP 401 + `WWW-Authenticate`**, so Claude's sign-in is
unchanged. Its body is now the JSON-RPC tool error OpenAI documents: the same request id,
`isError: true`, and `_meta["mcp/www_authenticate"]` holding the header's challenge. `/mcp/` is
unchanged.

`ailang mcp check --target openai` adds two checks:
- `file-params`: the fileParams schemas pass OpenAI's Scan Tools rules;
- `security-schemes`: every tool that answers 401 declares an `oauth2` scheme.
