### Fixed — verify: records built in helpers and accumulator literals have sorts

- **A record built in a helper body now encodes** (M-VERIFY-SOUNDNESS-COVERAGE M5). The tables that map a record literal's field set to its sort were created after the callee bodies had been encoded, so any helper that built a record was dropped, `std/json`'s `kv` among them. Each caller was then skipped with `record construction: no declared record type has fields [key value]`. They are now set up before callee resolution. They also include the inline records of ADT constructor fields, such as `Json`'s `{key, value}`, which a literal could never find before.
- **A record literal seeds its named alias.** A function that reaches a record type only through a literal, for example a `foldl` accumulator `{cells: [], idx: 0}` of type `EditApply_CellReplAcc`, had the alias filtered out of its declarations. The per-function sort filter now maps each literal's field set to the alias or inline record that declares it.
- **A let-bound `[]` in a record field takes the field's sort.** A-normalisation hoists the `[]` out of the literal, where it defaulted to `(Seq Int)` and Z3 rejected the record constructor. It now takes the declared field sort, for example `(Seq TableCell)`.
- **An undecided `map`/`filter`/`foldl` unrolling is a skip that says so.** A solver `unknown` reached through a bounded HOF specialisation is now reported like one reached through unrolled recursive helpers: `skipped`, `the solver could not decide this contract through the bounded unrolling of its map/filter/foldl chains (solver timeout)`. Before, it was `unknown` with no reason.
- Downstream corpora: 3 skips now verify (`cellRowsToJson`, `cellsToJson`, `pdfRoutePages`). Seven move past the record to their next blocker, `std/json.encode`/`decode`. Four `editApply_*` functions reach the solver, which cannot decide their unrolled `foldl` over `[TableCell]`.
