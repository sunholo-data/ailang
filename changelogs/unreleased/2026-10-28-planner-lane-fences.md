### Fixed — Planner lane Files parsing respects code fences (2026-10-28)

`tools/launchd/derive-planner-lane.sh` now skips fenced code in both its Files-section count and its path extraction, through one shared awk function. Before this, a fenced shell `#` comment matched the section terminator, so scanning stopped before a later language-core path and the doc was granted the codex/pi planner lane (fail-open). Fenced example paths and fenced `## Files` headings also caused false denials. Fences follow CommonMark (0–3 leading spaces, 3+ backticks or tildes, closed only by the same character at least as long), with two deliberate fail-closed exceptions: a trailing CR is ignored, so CRLF closers still close, and a fence left open at end of file inside the Files section fails closed (`opus fail-closed:unparsable-path-entry`) instead of hiding every later bullet. Routing policy, allowlists and reason tokens are unchanged. Resolves [#581 items 1–2](https://github.com/sunholo-data/ailang/issues/581); see the [sprint plan](../../design_docs/planned/sprint-plan-planner-lane-fences.md).
