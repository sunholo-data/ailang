### Fixed — `ailang test` broke on a brace inside a string in a multi-line test body (#1821) (2026-10-16)

The test runner found each `test`/`property` block's end by counting `{`/`}` runes, so
`contains("{a", "{")` on its own line made it stop at the block's first line and leave the
rest in the stripped module, which then failed to parse ("parse errors in ./x.ail:" with no
detail, for every test in the file). The block end is now found from the lexer's
`LBRACE`/`RBRACE` tokens, so braces inside strings, interpolations and comments are ignored
(`internal/testing/source_strip.go`).

### Fixed — `ailang run` on a module with no exports exited 0 silently (#1797) (2026-10-16)

Entry resolution only ran for modules with at least one export. A module whose `main` was
declared without `export` printed nothing and exited 0 on both engines. That is now an error
naming the fix (`entrypoint 'main' is declared in module m but not exported; add 'export'`).
A module that exports nothing and has no such function still exits 0, but prints a
`note: module m exports no functions` line on stderr instead of nothing.

### Fixed — Strict SharedIndex searches with `maxScan > 0` returned random results (#1795) (2026-10-16)

`findSimhash`/`findByEmbedding` stopped a Go map walk after `maxScan` entries. Map order is
randomised, so with `deterministic = true` the candidate set, and so the top hit, changed from
run to run on both engines. Strict mode now scans the lexicographically first `maxScan` keys (a
deterministic prefix scan; `maxScan = 0` is still the full scan). BestEffort is unchanged.
`_sharedmem_keys` is now sorted too (same defect class). Design:
`design_docs/planned/m-sharedindex-maxscan-determinism.md`.
