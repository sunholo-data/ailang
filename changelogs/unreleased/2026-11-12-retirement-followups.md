### Changed — follow-ups to the per-request API-key lane retirement (2026-11-12)

- **Cloud codex jobs no longer have a metered-key branch.** Since the `*-apikey` jobs were retired
  (#2217, ailang-multivac#16), the Cloud Run dispatcher refuses `auth_mode: apikey` without a
  `credit_account`, and the credit lane is Claude-only, so no codex job could receive
  `AILANG_AUTH_MODE=apikey`. The branch in `installCodexCredential`, `codex.EnsureAPIKeyAuth` and
  the "metered key is not leased" exemption in the coordinator's credential lane are removed.
  Codex on the ChatGPT subscription (`AILANG_CODEX_AUTH_SECRET`, leased `auth.json`) is unchanged,
  and `AILANG_AUTH_MODE=apikey` on a codex job now fails loudly for want of the secret, as an
  unset mode always did.
- **`AILANG_KMS_KEY` is gone from the executor env policy and its test.** The variable left the
  config registry in #2217.
- **The release-manager skill says the release rolls 10 executor jobs, not 15.** The `.agents`
  mirror is regenerated by `tools/launchd/sync-agents-skills.sh`, which now covers release-manager.

### Fixed — two release-CI flakes (2026-11-12)

- **`TestWorkerCLIProcessExitLifecycle/async/*/sigint|sigterm` exited 0 instead of 130/143 on
  macOS.** The harness sent the signal and then called `communicate()`, which closes the host's
  stdin. The EOF let `readLine` return, so the host could finish normally while the signal was still
  in flight. The signal scenarios now keep stdin open until the host exits, so the signal is the
  only way out. Reproduced locally under parallel load: 12 failures in 900 runs of the old harness,
  none in 1,800 runs of the new one.
- **`TestWS_PassHeaderCanary` hit an i/o timeout on Windows.** It allowed 5s for the handshake and
  for the handler's first frame, and a loaded `windows-latest` runner took 5.2s. Both waits return
  as soon as the event arrives, so they now allow 60s. `captureStderr` also restores `os.Stderr`
  and logs what it captured when the test fails partway, so the next failure shows the server's
  log instead of losing it.
