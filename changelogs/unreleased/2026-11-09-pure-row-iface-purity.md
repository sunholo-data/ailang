### Breaking — soundness: `pure` means `! {}`, and `iface` purity is derived from the checked row (fixes #1443)

- **`pure func` beside a declared effect row is now a type error.** `export pure func sneaky(x: string) -> unit ! {IO} { println(x) }` used to pass `ailang check`; it now fails with `The pure keyword contradicts the declared effect row ! {IO}. Suggested fix: remove pure to keep the effect row, or remove the effects and use ! {} with a pure body.` This covers labelled rows (`! {IO}`, `! {Declassify}`, scoped `! {Declassify[label=x]}`) and open rows (`! {e}`, `! {IO, e}`). `pure func` with no row or with `! {}` is unchanged. **Migration:** drop `pure` from any such declaration and keep the row, e.g. `func sanitize(raw: string<email>) -> string<sanitized> ! {Declassify}`. External packages that wrote `pure … ! {Declassify}` (e.g. the `sunholo/mcp_oauth` idiom) must make the same edit.
- **`ailang iface` `"pure"` is no longer a hard-coded `true`.** It is derived from each export's checked outer effect row: closed and empty → `true`; any label or a declared row variable (`std/list.mapE`'s `! {e}`) → `false`; an undeclared tail shared only with a callback parameter (`std/option.flatMap`) is latent and stays `true`, because the caller pays for the callback. Non-function exports use a deep type walk. Measured on std: 174 of 502 function exports now report `false` (previously all `true`), including all six `std/ai/streaming` exports. The keyword never feeds the derivation; a std census test asserts every keyword-`pure` export still reports `true`. The dead duplicate stub `elaborate.BuildInterface` (placeholder types, always-true purity, no callers) is deleted.
- serve-api, MCP `[pure]` tags/read-only hints, A2A tags and OpenAPI `x-ailang-pure` now read the interface value; the serve-api AST-heuristic overwrite is removed. The compile cache key is v9, shared with M-TRACE-LABEL-AWARE (#2193) in the same unreleased window: v8 interfaces carrying the old always-true flag miss, and v9 entries from a pre-#1443 dev build miss too because the build commit is part of the key.
- Package identity does not move: the v2 interface hash still hashes `pure` as the constant it was under the stub (purity follows from the effect row and type, which are already hashed), so publishers and the registry validator need not upgrade in lockstep.
- `ailang verify` admission is keyed on the row, not on the keyword: `pure`, an explicit `! {}`, or an explicit closed row containing only `Declassify` (bare or scoped) enters the SMT fragment, so declassification gates keep their contracts verified without the `pure` exploit. Unannotated non-`pure` functions, other effects and open rows remain outside. `Declassify` functions never gain `IsPure` metadata.
