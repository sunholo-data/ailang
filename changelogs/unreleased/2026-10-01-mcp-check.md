### Added — `ailang mcp check <url>` (M-SERVEAPI-DIRECTORY-READY M4)

- **What it does:** checks a live MCP endpoint against the Anthropic and OpenAI directory
  requirements before you submit. Options: `--target anthropic|openai|both` and `--json`. Exit
  codes: 0 no FAIL, 1 at least one FAIL, 2 could not check.
- **The five checks:**
  1. titles and hints (A7; for OpenAI, explicit booleans for all three hints, O8);
  2. no credential-shaped parameters (A2/O1);
  3. zero-argument tools callable with `{}`;
  4. lazy auth: a gated tool answers 401, and the resource metadata names this URL and an
     authorization server (A3);
  5. the authorization server advertises S256 and CIMD or DCR, and answers within 10 s (A5/A6/O6).
- Every finding cites a requirement ID from `design_docs/planned/v0_51_0/m-serveapi-directory-ready-sources.md`.
- **Probing safety:** it sends `tools/call {}` only to read-only tools, or to tools with required
  parameters (which are rejected before they run). A write tool that could run with `{}` is never
  called.
- **Against prod Parse `/mcp/`** (2026-10-01), it reports `apiKey` credential parameters on five
  tools, no OAuth gate, and six tools missing an explicit `destructiveHint` (OpenAI).

### Changed — every MCP hint is an explicit boolean

- `ResolveToolHints` now always emits `destructiveHint`, as `false` on read-only and pure tools.
  OpenAI's directory requires explicit `readOnlyHint`, `destructiveHint` and `openWorldHint`
  booleans on each tool (O8). Under the MCP spec an absent `destructiveHint` defaults to `true`.
