### Fixed — `std/env.getEnvOr` failed on the bytecode VM when the variable was unset (#1864)

v0.54.13 regression. `getEnv` returns `Err(NotFound(name))` from the evaluator, and the VM bridge only knew the constructor ordinals of a hand-kept list of std ADTs that did not include `EnvError`. Before v0.54.12 a bridge failure was silently replayed in the evaluator. #1576 B4 correctly stopped replaying a call after its effects ran, which exposed the gap. The bridge now reads every std ADT's constructor order from the embedded stdlib declarations (`internal/vm/std_adt.go`), the same order the compiler uses. So `EnvError`, `NetError`, `Json`, `XmlNode` and the other std ADTs returned by effects all cross. A test checks the hand-kept table against the declarations. `--strict-bytecode` still rejects `getEnv`, which is evaluator-only (unchanged since v0.54.11).
