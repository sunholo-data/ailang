### Fixed — `std/process` `exec` timeout kills the whole process tree, not just the direct child

A timed-out `exec` SIGKILLed only the process it started; that process's own children were reparented to launchd and kept running. On 2026-10-16 a motoko agent's `BashExec` (which runs through this effect) ran `cd /tmp/qtest && python3 gen.py && …` four times; each call returned `Timeout` after 35 s, and three `python3` processes — which never wrote, so never got the SIGPIPE the old comment relied on — grew to ~18 GB between them until the machine ran out of memory and the eval run was reaped. `exec` now runs the command as its own process-group leader and a timeout kills the group (`proctree.Configure`), as `stream_process.go` and `process_managed.go` already did. The 5 s `WaitDelay` is unchanged. Covered by `TestProcessExec_TimeoutKillsGrandchildren` (fails on the old code) and verified end to end through `ailang run --process-timeout`.
