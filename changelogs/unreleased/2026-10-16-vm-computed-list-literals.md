### Fixed — long list literals of computed elements still overflowed the strict VM (#1865)

The #1736 fix in v0.54.13 chunked long list literals, but it only helped when every element was a constant. Elaboration binds each non-atomic element (a call `g(i)`, a negated literal `-0.5`, a record) to a `$tmp` local first. 128 such elements pinned 128 registers, and the function went evaluator-only again under `--strict-bytecode`. The compiler now compiles single-use temps straight into their list, tuple, record or ADT slot (`internal/bytecode/compiler/ctor_temps.go`). It does this only when the temp is read exactly once, in a constructor position, and the evaluation order is unchanged, so effects in elements still run left to right. A 300-element list of calls, negated floats, effectful calls, and 16 records each holding a 16-string list now run strict and match the interpreter.
