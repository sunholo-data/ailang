# AILANG Vision

**A symbolic reasoning kernel for neural program synthesis.**

AILANG sits between probabilistic program synthesis (LLMs) and deterministic execution environments. It constrains, verifies, and traces programs synthesized by neural systems.

*(For the 2-minute comparison with Python/Go/TypeScript, see [Why AILANG](/docs/why-ailang). For the `1.0` stability contract, see [Why 1.0](/docs/why-1-0).)*

![AILANG Symbolic Kernel Loop](/img/diagrams/ailang-kernel-loop.svg)

## The Five Pillars

| Pillar | What It Means | Shipped Mechanism |
|--------|---------------|-------------------|
| **1. Symbolic/Concrete Separation** | Programs encode symbolic intent; concrete values arise within checked constraints | Core ANF IR, deterministic evaluator & VM |
| **2. Effects as Relations** | Effects are `(Intent × EffContext) ⇒ Outcome \| Constraints`, not opaque calls | `! {Effects}`, `--caps`, `@limit=N`, `--policy` |
| **3. Contracts as Specs** | `requires` / `ensures` are machine-checkable specifications | `ailang verify` (Z3 SMT) + `--verify-contracts` |
| **4. Traces as Artifacts** | Execution emits structured, replayable, auditable traces | `ailang chains` (agent) + `--emit-trace jsonl` (program) |
| **5. Explicit Authority** | Zero ambient authority — every capability is declared and bounded | Deny-by-default `--caps`, `Declassify` effect |

## Effects as Capability Relations

In traditional compilers, side effects are invisible to the type checker. In AILANG, the signature constrains what synthesized code **can** do:

```ailang
import std/fs (writeFile)
import std/string (toUpper)

type User = { name: string }

-- The type signature constrains what this function CAN do
func saveUser(user: User) -> () ! {FS} {
  writeFile("user.txt", toUpper(user.name))
}

-- Pure functions cannot perform FS or Net effects (type error if attempted)
pure func formatUser(user: User) -> string = toUpper(user.name)
```

An LLM literally cannot hallucinate a network call inside `formatUser`, and budget annotations bound how many times an effect may fire:

```ailang
import std/fs (readFile)
import std/io (println)
import std/string (toUpper)

-- Declare: this function needs IO and FS, with bounded IO usage
export func process(path: string) -> string ! {IO @limit=3, FS} {
  let data = readFile(path);      -- FS capability required
  println("Processing");          -- IO capability, budget: 1 of 3
  toUpper(data)                   -- Pure: no capability needed
}
```

Callers are charged the callee's declared budget (semantic charging), and exceeding a budget produces a structured failure.

## Two-Level Semantic Traces

When AI-generated code misbehaves, AILANG separates **what the agent decided** from **what the program executed**:

| Trace Level | Tool | Captures |
|---|---|---|
| **Level 1: Agent Traces** | `ailang chains view <id> --spans` | Reasoning turns, tool calls, tokens, cost, approvals |
| **Level 2: Program Traces** | `ailang run --emit-trace jsonl --caps IO prog.ail` | Function enter/exit, effect invocations, contract checks, budget deltas |

**Example program trace (`--emit-trace jsonl`):**

```json
{"version":"1.0","event":"function_enter","timestamp_ns":42459,"depth":1,"function":{"name":"processFile","args":["\"input.txt\""]}}
{"version":"1.0","event":"function_enter","timestamp_ns":44125,"depth":2,"function":{"name":"std/io.println","args":["\"Processing...\""]}}
{"version":"1.0","event":"function_exit","timestamp_ns":45750,"depth":2,"function":{"name":"std/io.println","result":"()","duration_ns":1625}}
{"version":"1.0","event":"function_exit","timestamp_ns":46500,"depth":1,"function":{"name":"processFile","result":"()","duration_ns":4041}}
```

Structured diagnostics (`ailang check --format=agent`), Z3 counterexamples, and JSONL traces turn blind retries into targeted self-repair.

## What AILANG Deliberately Excludes

AILANG prioritizes machine decidability and semantic clarity over syntactic variety:

- **No multiple syntaxes** — one canonical way to express each concept
- **No implicit side effects or hidden state** — every effect is declared in types
- **No ambient authority** — capabilities require explicit `--caps` / `--policy` grants
- **No unstructured concurrency** — no ad-hoc threads or data races (structured concurrency is planned via static effect-typed task graphs)

*(Editor integration IS supported via `ailang lsp --stdio` and `ailang check --fix`, sharing the same diagnostic and quick-fix engine that agents use on the CLI.)*
