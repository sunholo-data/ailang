The maintenance adapter exercises changes to an existing native application over
three fresh agent sessions. Each stage inherits its own previous source, locks,
public app files and explicit handover notes. Failed code and deletions carry
forward. Private grading results and old conversations stay with the controller.

This is a separate research lane from the standing generation eval suite. The
first public development taskpacks adapt resource ownership and text fidelity
requirements from real projects. They provide feasibility and instrument checks;
two task families cannot establish an average working day or a population language
advantage. Their public references make them unsuitable as sealed holdouts.

## Resolve a frozen schedule

Build the adapter binary from this branch and obtain the companion package source
containing the execution bindings. From that package repository:

```sh
ailang eval-suite --agent \
  --maintenance-manifest "$PWD/research/real-world-maintenance/taskpacks/v1/execution/development.example.json" \
  --dry-run
```

The output lists eight trajectories and 24 stage requirements, the native
toolchain/source identities, declared bounds and isolation status. Dry run reads
local inputs only: it does not discover generation benchmarks, construct an
executor, initialize telemetry, request credentials, take a rig lock or invoke an
inference canary. Explicit ordinary-suite flags conflict even at default values.

The execution envelope binds the native `maintenance.trajectory/2` plan, settings,
starter files, current requests, public checks and independent oracle drivers by
hash. Duplicate JSON keys, changed files, unsafe carried paths, symlinks, missing
native counterparts and unbounded schedules fail validation. The full envelope
is controller data, never an agent prompt.

## Run the development instrument

The Go adapter exposes `RunMaintenanceStages` with injected executor, task builder,
grader, admission and usage hooks. Scripted no-model integration controls drive
the actual native candidate graders and native AILANG analysis. The normal
one-shot runner and retained-stage runner share `BuildEvalExecutorTask`; retained
execution owns its workspace lifecycle and does not use `DEBUG_AGENT` for retention.

The real pi native-tool controls require `rg` and `fd` on PATH, along with the
explicit SDK/runtime dependencies. `make maintenance-adapter-check` checks both
tools before running; CI installs them with a bounded dependency step so offline
tests do not rely on SDK downloads.

Candidate snapshots use the same canonical path/content/executable manifest as
the taskpack bridge. A new runtime copy is compiled and graded against retained
obligations. Uncompilable model source is an artifact failure. Missing trusted
tools, changed oracle inputs, stale evidence or failed cleanup invalidate the
measurement. Expected semantic-mutant failures must reach actual assertions.

No model campaign is started by normal tests or this command. CLI live admission
remains closed until a reviewed launch freezes observed model/provider/harness,
prompt/tool/source/settings identities, prices, coverage policy and enforceable
limits. Declared request limits are not pre-request enforcement; existing token
and cost meters can stop after in-flight work has already spent money.

## Keep economics source-qualified

The existing pi parser captures settled-message usage with original field
presence, event/import identities and raw decimal cost text. It does not count
cumulative updates or turn summaries again. Missing cache/reasoning fields remain
unknown; aggregate `Result` zeroes cannot establish an explicitly reported zero.

Pi's local price-table amounts remain `list_price`, never provider invoices. The
bridge does not round floating USD into exact micros. The native package decides
whether a decimal has supported precision. Retry/compaction gaps and incomplete
request coverage retain an unchecked summary, so observed subtotals cannot become
a total maintenance-cost claim. Raw observations remain available for investigation.

`RunMaintenanceNativeAnalysis` invokes the explicit source-path native ledger and
banks compiler binary/version, source, input and output hashes externally. It
does not reimplement cohorts, monetary arithmetic or paired deltas in Go. The
companion `examples/maintenance-ledger-source` consumer uses a local dependency
on `sunholo/maintenance_bench` 0.2 source. Registry 0.1 lacks these APIs and cannot
substitute for the source dependency.

## Qualification and roadmap evidence

Protected execution must qualify both agent native tools and candidate/shell
processes. A separate oracle directory, an allowlist declaration or a supplied
policy digest is insufficient. The first backend work reuses pi extensions and
the locked sandbox runtime; actual no-model probes, declared protected roots and
runtime/policy/source identities determine admission. Unsupported or failed
boundaries keep admission closed rather than weakening the comparison.

Reports retain every scheduled stage, failed spend, unknown usage and unmatched
arm. Reproduction cards should link the exact request, owned prior/candidate
hashes, compiler diagnostics and independent oracle result. These can justify a
roadmap investigation. General language-quality claims need broader real-project
sampling; causal claims about type feedback need an explicit intervention cohort.
Initial generation and repair-vs-feature classification remain separate measures.
