# Extension Packages

Extension packages are independently-versioned AILANG packages that plug behaviour into a host application at compile time. Because AILANG resolves all `import` statements at compile time, integrating a set of extensions requires generating an explicit static-import file — the **extension registry**.

## Convention

Every extension package must:

1. Export `register_with_config(cfg: <ConfigType>) -> <HooksType> ! {}` from a `register` module.
2. Declare `motoko-ext-abi` (or your project's equivalent ABI package) as a dependency in its own `ailang.toml`.

```ailang
-- motoko-ext-compaction/register.ail
module motoko-ext-compaction/register

import motoko-ext-abi (ExtensionHooks)
import src/core/config (RuntimeConfig)

export func register_with_config(cfg: RuntimeConfig) -> ExtensionHooks ! {} {
  -- ... return the hooks record
}
```

## ailang.toml schema

Add an `[extensions]` section to list the extensions your application uses:

```toml
[extensions]
packages = [
  "motoko-ext-compaction@0.2.0",
  "motoko-ext-exa-search@0.4.1",
]
config_import = "src/core/config.RuntimeConfig"   # module/path.TypeName
hooks_import  = "src/core/ext/types.ExtensionHooks"
output        = "src/core/ext/registry_generated.ail"  # default: registry_generated.ail
```

| Field | Required | Description |
|-------|----------|-------------|
| `packages` | yes | List of `name@version` refs. Each must be present in `ailang.lock`. |
| `config_import` | yes (when packages > 0) | `module/path.TypeName` of the config type passed to each extension. |
| `hooks_import` | yes (when packages > 0) | `module/path.TypeName` of the hooks return type. |
| `output` | no | Path for the generated file (default: `registry_generated.ail`). |
| `module_name` | no | Override the generated module declaration (default: `output` path minus `.ail`). |

## Generating the registry

After adding extensions to `ailang.toml` and running `ailang lock`, generate the dispatch file:

```bash
ailang generate-extension-registry
```

This reads `ailang.toml`, verifies every listed package is present in `ailang.lock`, and writes the output file.

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--config FILE` | `ailang.toml` | Path to manifest |
| `--output FILE` | from `ailang.toml` | Override write location |
| `--dry-run` | false | Print to stdout, don't write |

### Preview without writing

```bash
ailang generate-extension-registry --dry-run
```

## Generated file

The generator emits a compilable AILANG module. For the two-package example above:

```ailang
-- GENERATED by ailang generate-extension-registry
-- Source: ailang.toml [extensions]
-- Do not edit. Regenerate: ailang generate-extension-registry

module src/core/ext/registry_generated

import motoko-ext-compaction/register (register_with_config) as register_compaction
import motoko-ext-exa-search/register (register_with_config) as register_exa_search
import src/core/config (RuntimeConfig)
import src/core/ext/types (ExtensionHooks)
import std/option (Option, Some, None)

export func resolve(name: string, cfg: RuntimeConfig) -> Option[ExtensionHooks] {
  if name == "compaction" then Some(register_compaction(cfg))
  else if name == "exa_search" then Some(register_exa_search(cfg))
  else None
}
```

## Short name derivation

The generator derives a short identifier for each package to use as the import alias and the `resolve()` string key:

1. Strip `@version` suffix: `motoko-ext-exa-search@0.4.1` → `motoko-ext-exa-search`
2. Strip `motoko-ext-` prefix if present: → `exa-search`
3. Replace `-` with `_`: → `exa_search`

## Commit the generated file

The generated file is deterministic — it depends only on `ailang.toml` and `ailang.lock`. Commit it alongside the lock file so builds remain reproducible without running the generator in CI.

```bash
git add ailang.toml ailang.lock src/core/ext/registry_generated.ail
```

## Workflow

```bash
# 1. Add extension to ailang.toml [extensions]
# 2. Pin it in the lockfile
ailang lock

# 3. Regenerate the dispatch file
ailang generate-extension-registry

# 4. Verify it compiles
ailang check src/core/ext/registry_generated.ail

# 5. Commit
git add ailang.lock src/core/ext/registry_generated.ail
```
