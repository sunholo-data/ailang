# Information-Flow Control (IFC) Labels

AILANG includes **compile-time information-flow control (IFC) labels** (`T<label>`, `T{not LABEL}`, and `! {Declassify}`) to block untrusted data (prompt injections, raw PII, secrets) from reaching sensitive sinks, with **zero runtime overhead**. Based on Meijer's [*Guardians of the Agents*](https://cacm.acm.org/practice/guardians-of-the-agents/) (CACM, Jan 2026).

![IFC Taint Lattice](/img/diagrams/ifc-taint-lattice.svg)

## The Three Syntax Forms

| Form | Meaning | Example |
|---|---|---|
| `T<label>` | Value carries source taint `<label>` | `func fetchMail() -> string<email> ! {FS}` |
| `T{not LABEL}` | Parameter sink rejects `<LABEL>` inputs | `func sendEmail(to: string, body: string{not email}) -> () ! {Net}` |
| `! {Declassify}` / `! {Declassify[label=ℓ]}` | Auditable sanitizer allowed to change/lower labels | `func sanitize(s: string<email>) -> string<sanitized> ! {Declassify}` |

Labels are **open, lowercase snake_case identifiers** (`<email>`, `<user_input>`, `<pii>`, `<api_key>`, `<tenant_a>`) defined at point of use. Joins combine naturally (`<email ⊔ pii>`), and pure expressions propagate input labels automatically (`APP-PURE`).

## Core Rules

1. **Sink refinement (`{not LABEL}`):** Passing a value labelled `<email>` to `body: string{not email}` is a compile-time error (`CheckModuleIFC`).
2. **Declassification (`! {Declassify}`):** Only functions declaring `! {Declassify}` (or scoped `! {Declassify[label=email]}`) may lower a label; identity helpers, record wrapping, and `let` bindings preserve taint.
3. **Scoped & positive parameters:** `! {Declassify[label=email]}` drops only `<email>` (leaving unrelated labels intact); a positive parameter `value: string<sqlsafe>` accepts only values covered by `<sqlsafe>` (rejecting `<arg>`/`<secret>` with `param_label_cover`).

```ailang parse
-- ✅ Allowed: explicit scoped declassifier
func sanitizeEmail(raw: string<email>) -> string<sanitized> ! {Declassify[label=email]} {
  "[sanitized]"
}

-- ❌ Rejected: changing a label without ! {Declassify}
pure func sneakySanitize(raw: string<email>) -> string<sanitized> ! {} {
  "[sanitized]"
}
```

## Cross-Module Enforcement (`#1134`) & Sinks as Values

Imported functions carry an IFC summary in module `iface` metadata (parameter labels, `{not ℓ}` sinks, return labels, intrinsic body taint, and `Declassify` authority). Importers enforce imported sinks across aliases, qualified calls, higher-order functions, and wrappers (`#1134`, `#1719`):

## Labels Inside Types

Within a module, labels written inside declared records (`{ raw: string<authcode> }`), aliases (`type Code = string<authcode>`), ADT fields, tuples, and lists are tracked field-precisely on getters and conservatively on `match` destructuring:

```ailang parse
type RawCode = { raw: string<authcode> }
pure func mk(s: string) -> RawCode = { raw: s }
pure func logLine(s: string{not authcode}) -> string = "log: ${s}"

export pure func leak(x: string) -> string {
  let c = mk(x);
  logLine(c.raw)   -- rejected: <authcode> reaches {not authcode}
}
```

## Caveats & Limitations

- **Explicit-flow only (no implicit-flow tracking):** `CheckModuleIFC` tracks **explicit dataflow** through bindings, record fields, constructors, and calls. Implicit control-flow channels (branching on a secret `if secretBool then "a" else "b"`) are **not** tracked.
- **One label per value / one `not` per parameter:** Multi-label syntax like `string{not a, not b}` does not parse; give untrusted sources a shared label (`<untrusted>`).
- **Inferred sinks stay intra-module:** An importer sees only what an export declares (`x: string{not ℓ}`); annotate exported library sinks explicitly.
- **Labels inside imported type definitions:** Structural labels nested inside an imported type flow to Z3 contracts via `iface`, not yet to `CheckModuleIFC` (`design_docs/planned/m-ifc-cross-module-labels.md`).
- **Sink refinements are parameter-only:** Return types cannot carry `{not LABEL}`.
- **No runtime IFC:** All labels erase at compile time (`ailang verify` additionally checks pure contracts across imported pure functions).
